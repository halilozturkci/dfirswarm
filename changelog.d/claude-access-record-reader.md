### Added: one reader for who reached a sensitive output, with the three kinds of evidence apart

`scripts/sensitive-access.ts` joins what a run already writes into a list of accesses to sensitive outputs. It adds no register and changes nothing for an agent: nothing is hidden or held back, it only reads.

- **Four chains, one reader.** The store's journal (`job_started.scope.auto_declared`, `job_committed.sensitive.because`, and `scope.could_read_sensitive` kept apart as a possible reach, not a read), the hub's `sensitive_access` lines on the trace, the ledger's entries that cite a sensitive output, and `operator-audit.jsonl`'s `console_view` lines. `SensitiveAccessArgs` is the one definition of the hub's line (`via` path, text or api_page), exported with `classifyTraceRow` and `accessLineArgs` for the code that writes it.
- **Three kinds of evidence, never merged.** A link the harness verified (a job's declared or added input), a read the harness observed (a path or command that names the output, a page returned to a seat, a console view) and what an agent says it did (a ledger entry). "Opened the container" is only ever the third. Each event carries how sure the harness is: certain, a named path, text that names it, or a possible reach.
- **The rules, versioned in one place.** `classifyTraceRow` reads a seat's row alone (its path or command, never a result): job paths and logs, blobs (named by their part alone, never by the digest), catalogue generations and aliases, a job id as a word (`j000001` is not `j0000010`), a root or glob a command reads or walks (a possible reach that lists the sensitive jobs), and a kept `tool-output/` copy. `verifyAccess` holds the hub's lines to the trace they came from and says when the rules changed instead of calling the difference a fault.
- **The chain of use.** `provenance` follows each secret output through the jobs made from it, with the three kinds apart and, marked as an inference and not a record, the later jobs of a seat that read it.
- **A lower bound, said every time.** Every output ends with the fixed sentence "Reads through a computed path, through a copy that was not a recorded page, or by a program that opened it by a name the command does not hold are not seen. This list is a lower bound."
- **Command line.** `node --experimental-strip-types scripts/sensitive-access.ts <run-dir> [--json] [--derive] [--verify] [--job jN] [--seat NAME]`; `--derive` adds what the rules read in the trace of a run that predates the hub's lines.
- **Never a crash.** A missing file is empty; a file that is a link or unreadable, and a line that is not the shape, is a problem line on the result and the rest is read. The store's sensitive index now skips a journal line or manifest that is not the shape instead of throwing.

`docs/protocol.md` describes it ("The access record"); `tests/sensitive-access.test.ts` and `tests/sensitive-access-fuzz.test.ts` (a thousand damaged runs) hold it.
