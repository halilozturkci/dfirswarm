### Fixed: computer-forensics-base answers every refusal of twelve tools as JSON with the status pair

ad1_extract, archive_extract, chunk_needles, feature_scan, file_type, icat_extract, image_layout, ioc_scan, sig_carve, sqlite_snapshot, timeline_super and timestamp_decode refused with a JSON error that carried no `status` and no `status_basis` (and `icat_extract` printed its refusals on stderr, or no JSON at all, when an image could not be found). The failure function of each of the twelve, through which its refusals go, now prints `status: "failed"`, a one-sentence `status_basis` ("the tool stopped with an error: ..." with the same message the `error` field carries) and exit 1; a test holds it for `{}`, a missing path and a wrong type, for all twelve. The refusals that the image and offset resolvers of `chunk_needles` and `icat_extract` raise as bare JSON text on stderr are now caught and printed on stdout with the pair. `image_layout` no longer ends in a traceback and no JSON when the image's name is not UTF-8 (the digest of the path is taken over its bytes).

Nothing else about the answers changes: the refusal's `error`, `tool` and extra fields are as before. `catalog_search`, `sqlite_query` and `check_inputs` are not part of this change. The tools' version labels, manifests and the four tool-library twins (chunk_needles, icat_extract, ioc_scan, sig_carve) are raised and updated together, and the manifests' `sha256` of their scripts is current. The pack's own test, `test_status_basis.py`, gains a case for the refusals of all twelve and one for the non-UTF-8 name; the base entries of `tests/tool-contract-allowed.json` and `tests/tool-paging-rerun-allowed.json` are removed (sig_carve is now covered by the paging driver).
