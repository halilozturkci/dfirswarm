### Fixed: computer-forensics-base tools and recipes hold to their bounds on hostile input

- **`disk-volumes` reads a partition table as mmls writes it, and nothing else.** A GPT partition name that held a line break and a forged row used to become a second row of the table, and its third column a directory name under the output directory: a name could make the recipe delete another generation's listing files or create a directory outside its output. A row is now taken only in sequence and in the shape mmls prints, its start sector is only digits, a line that is not a row is a note in the coverage (status partial), and control characters in a description are replaced. `image_layout` skips an out-of-sequence row the same way and says `partition_table: unknown` when mmls printed no row it could read.
- **`archive-members` no longer lists a tar as a zip.** The format was decided by four bytes found anywhere in the last 64 KiB; a tar whose last member is a zip, or any file ending in 22 bytes that spell an end record, was listed as a zip and reported complete. A tar header at offset 0 now decides before a zip end record does, a zip with a prefix needs an end record that agrees with the file, and a file that is neither answers `unsupported` on stdout. A tar that also ends in a zip record says so in the coverage.
- **`ioc_scan` and `chunk_needles` have a clock** (`max_seconds`, 100 by default, at most 110, inside the manifest's 120). A scan that reaches it answers for the occurrences that start before `next_start`, with `complete: false` and `status: partial`, and names how to go on, instead of being killed with nothing said. The values file (`write_values`) stops at 20,000,000 rows or 1 GiB and names the offset it stopped at, the locators go on. `file_carver` reads its source under a 25-second clock and refuses a walk that uses it with `reached_bytes`.
- **`ad1-items` bounds its listing and its attributes.** A metadata chain several items share is written to `attributes.tsv` once and later items get a `same-chain` row; the entries written cannot exceed the bytes the image holds, past which the file stops and `limits_hit` names the item; the listing has its own clock (97% of the recipe's seconds). The walk keeps the byte ranges it reached: data no item leads to (a zeroed next pointer drops items with no error, as the format has no item count) makes the coverage partial and `integrity_status` unverified, in the recipe and in `ad1_extract`.
- **Values writers refuse a job that was not run as secret output** (`ioc_scan`, `chunk_needles`, `feature_scan` with `write_values`), and the manifests declare it: `{ "when_args": ["write_values"] }` for the two scanners, `"required"` for `feature_scan`, whose `out_dir` always holds the values. `archive_extract` stays conditional, as its skill says, and its description now says why.
- **A file name that is not UTF-8 no longer stops a writer.** `ioc_scan`, `chunk_needles` and `feature_scan` write their JSON Lines files with ASCII escapes, so a path with lone surrogates (a Linux name of raw bytes) is an escape and not a `UnicodeEncodeError`.
- **`archive_extract` bounds what it loads and says what it checks.** A zip central directory is read whole, so one declaring more than four times `max_members` or more than 64 MiB is refused before it is loaded, naming the setting to raise; a 7z's output is held to `max_ratio` times the archive's size (the claim of a ratio per member held only for a zip); the first pass over a 7z listing looks at the clock. `archive-members` takes the same 64 MiB directory limit.
- **Smaller corrections.** `timestamp_decode` with `plausible_to` 9999-12-31 is a valid range and not a traceback; `catalog_search` and `check_inputs` answer invalid or non-UTF-8 JSON and JSON nested past the parser as JSON, not a traceback; `sqlite_snapshot` no longer follows a link beside the database, as its entry says; every tool's answer and every recipe's coverage carry `status` and `status_basis`; the skills and the README no longer claim a ratio protection, a per-tool time budget, a withheld recipe name or a bound that the code did not hold. Each fix has a test that fails on the code it replaced.
