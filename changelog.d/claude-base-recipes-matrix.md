### Fixed: computer-forensics-base recipes answer a target of an odd type, a target file with odd content and a refused write as JSON

- **A target of an odd type is a refusal.** `disk-timeline` took `paths[0]` of a `paths` that was an object, a number or `true` and ended with a `KeyError` or `TypeError` and no JSON; it refuses a `paths` that is not a list, as `ad1-items` does. `ad1-items`, `archive-members` and `disk-timeline` read a target that names a file inside a handler (at most 1 MiB), so bytes that are not UTF-8 are a refusal, not a `UnicodeDecodeError`.
- **An output directory that cannot be written is a refusal.** `ad1-items`, `archive-members` and `disk-timeline` write a probe file in `--out` before anything runs; a directory that is not owned, is read-only or is `/` is refused as JSON with exit 2 (the earlier changelog sentence about an unusable `--out` held only for a name that cannot be made). The two shell recipes ignore `SIGXFSZ`, so a write past a file-size limit fails and is reported instead of ending the script with the signal, and their step and coverage helpers say a write error on stderr in a word. A last-resort hook turns any exception nobody foresaw in the three Python recipes into JSON (`applies: unknown` for `detect`, `ok: false` for `run`) with exit 2.
- `tests/test_recipe_matrix.py` runs `detect` and `run` of all five recipes over sixteen odd-typed targets, targets that name files with non-UTF-8, NUL, 3 MiB, empty, binary, directory and FIFO content, output directories that cannot be written (run as nobody by `setpriv` when the test is root) and a file-size limit.
- `sqlite_query` looks at the database with `fstat` on a descriptor opened without waiting before SQLite opens it, so a FIFO put in its place after the check is refused instead of waited on (the instant between that look and SQLite's own open is not closed).
