### Fixed: computer-forensics-base tools and recipes: hostile paths, the protected printer, FIFO opens and one source for `complete`, by pattern across every tool

- **Every path parameter of every tool and recipe, given a hostile path, is answered as JSON.** `archive_extract` called `exists()`, `is_dir()` and `iterdir()` on the output directory outside a handler, so a 300-character `out_dir` (and a directory that cannot be searched) ended it with a traceback; the block is now one handler. The Python recipes' `run` (`ad1-items`, `archive-members`, `disk-timeline`) refuse an unusable `--out` as JSON, and the two shell recipes do too; `detect` of `ad1-items` and `archive-members` catches the `ValueError` a NUL or a lone surrogate in `paths[0]` raises, and the shell recipes treat a path that cannot be written as UTF-8 as no path. `tests/test_hostile_paths.py` runs a matrix (a 300-character name alone, as a directory and in the middle, a symlink loop, a NUL, a lone surrogate, a file where a directory is expected and the reverse, a directory that cannot be listed, a FIFO) over every path parameter of every tool and the target, `--out` and `--probe-out` of every recipe, with wrongly typed and 100,000-deep targets.
- **An answer is written by one protected printer.** `archive_extract`, `timeline_super` and `feature_scan` printed their answers with the stop signals free, so a signal while the write was blocked on a full pipe cut the document (a 755 KB answer left 64 KB of invalid JSON); they now hold the signals and clear the last word, as the other tools did. A reader that stops taking the answer can no longer make a tool unkillable: the held write is bounded (30 seconds; `TOOL_HELD_WRITE_SECONDS` sets it for the tests), and a stop signal that is waiting then ends the tool with 128 plus the signal and a line on stderr. A reader that has gone away ends it quietly. `tests/test_stalled_reader.py` stalls a 4096-byte pipe for eight tools and each of the three signals, and a source check requires every `print(json.dumps(...))` to be inside the printer, a last word (written with the stop signals already ignored) or the last-resort hook for an exception nobody foresaw (`_unexpected`, `unexpected`, `_cannot_write`: it prints one line and ends the process at once, and does not hold the signals). The recipes' short answers (smaller than a pipe) go through the printer as well.
- **A FIFO or a device is never opened by waiting.** `ad1_extract` and `ad1-items` opened the image segments with `open()` and waited on a FIFO with no clock; `ioc_scan`, `file_type`, `archive_extract`, `sqlite_query`, `archive-members` and `disk-timeline` open the caller's file the same way as the five tools of the last round (`O_NONBLOCK`, then `fstat` on the descriptor), and `icat_extract` and `chunk_needles` look at the image before they give it to icat. A swap in the instant between that look and the program's own open is not closed.
- **`complete`, `ok` and `status` are one fact, said once.** `ioc_scan` answered `complete: true` with `status: partial` when its locator file could not be written. The printer now reconciles every answer: an error flag in it (`all_results_error`, `all_matches_error`, `receipt_error`, `receipts_error`, `rows_file_error`, `invalid_lines_file_error`, `write_error`, at the top or two levels down) makes a `complete` status `partial`, and a `partial` or `failed` status is never `complete: true`, nor a `failed` one `ok: true`.
- `chunk_needles` waits on icat in steps of 0.2 second (it was 1), so it ends at most that far past its clock. `ad1_extract`'s `gaps.jsonl` is closed on a stop (the last round's changelog sentence is now tested). The `sqlite_query` description says which names are withheld where: a file name shaped like a token in every mode, table and column names only in the write_values mode, and printed as they are in sql mode.
