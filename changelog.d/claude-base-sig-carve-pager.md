### Fixed: computer-forensics-base `sig_carve` pages through the tool library's second pager generation

- **A row that holds a name that is not UTF-8 cannot raise.** `sig_carve` carried the first-generation `LosslessPage`, which writes its whole-result file with `ensure_ascii=False` into a UTF-8 file: a row holding a lone surrogate (a Linux file name of raw bytes) would raise `UnicodeEncodeError`. No row holds a path today, so the fault was latent. The class is now the library's second generation, byte for byte (the same text as `regkv`'s): it escapes a lone surrogate and loses nothing, and the pager on its own says as JSON when the whole result cannot be written (a read-only directory, a full disk) and exits 1, with no traceback. The tool keeps its own answer for that case: its `SafePage` hands the failure back, so the call still returns the count and the page whole with `all_results_error`, exit 0, as before. The tool-library twin follows, and the library still has two generations.
