### Fixed: computer-forensics-base `catalog_search` and `sqlite_query` carry `status` and `status_basis` on every answer

- **Every answer of the two tools says `status` (complete, partial or failed) and why in one sentence (`status_basis`).** Until now they answered with a `complete` boolean and neither field, although the changelog said every tool's answer had both. `complete` and `ok` keep their meaning for the readers that use them. A refusal or an error is `failed`. A search or a statement that the clock stopped, `catalog_search` lines too long to search, a values file or a locators file that stopped at its size cap or could not be written, and a page whose file of every row could not be written to its end are `partial`, and the sentence says which and where the whole is. A page that is not the whole result, with the file that holds the whole written, is `complete`.
- **`sqlite_query` no longer says `complete: true` over a page whose file of every row stopped at its cap or could not be written.** The page is the first rows, the file is where the rest was to be read, and a result whose rest is missing is now `partial` with `complete: false`.
- **`catalog_search` refusals are JSON on standard output.** The refusals that raised `SystemExit` with their text (no catalogue, several catalogues, a revision that is unavailable, a generation that is not listed) went to standard error; they are now the same answer on standard output as the other refusals, with the exit code 1. A refusal lists at most 200 names (`candidates`, `revisions`, `partitions`, `there`) with the count in `<name>_total`; the catalogue holds the whole.
- **Hostile and unforeseen input is JSON.** `catalog_search` refuses a `which`, `catalog` or `partition` that is not text and a `limit`, `offset` or `max_seconds` too large to read; arguments nested past the parser, an error nobody expected, and a time budget that ran out while the catalogue was located answer `failed` or `partial` with the error's class and no message, which could quote the evidence. `sqlite_query` answers an unexpected error the same way.
