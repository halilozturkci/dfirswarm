### Fixed: computer-forensics-base `catalog_search`, `check_inputs`, `chunk_needles`, `file_carver`, `icat_extract`, `ioc_scan`, `sig_carve` and `sqlite_query` answer once on a stop signal

- **SIGTERM, SIGINT and SIGHUP give one JSON document, exit 128 plus the signal, and leave no hidden temporary file.** Seven of the eight tools had no handler (a stop ended them with no answer and could leave the hidden file a pager was writing); `sig_carve` installed its own from `main()`, after the arguments were read. All eight now carry the shared STOP block (the windows lineage, byte for byte), run at module level right after the standard imports. Until the tool has its own last word, a stop is `failed` with `interrupted: true` and the signal; once the work has begun it is `partial` with `interrupted: true`, the signal, and what was done: `catalog_search` the matches counted and the line it reached, `check_inputs` the receipts file (the files checked so far have a row; nothing is a pass), `chunk_needles`, `ioc_scan` and `sig_carve` how far the scan read and where to go on, `icat_extract` the `.partial` file it keeps and its stderr file, `sqlite_query` and `file_carver` that no result is claimed.
- **The program a tool runs is ended by its pid.** `chunk_needles` and `icat_extract` end the `icat` they were reading before they answer, and no `icat` survives (the tests look at its pid). The hidden files of the pagers (`catalog_search`, `chunk_needles`, `file_carver`, `ioc_scan`, `sig_carve`, `sqlite_query`, including the locators file of a values-mode export) are removed by the block.
- **The final answer goes through the block's `print_answer`**, which holds the stop signals back while the document is written, so a signal during the write cannot cut it. `catalog_search`'s own SIGALRM budget is not touched by the block. A signal in the start of the interpreter, before the block has run, is not claimed.
