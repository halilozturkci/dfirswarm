### Fixed: computer-forensics-base tools and recipes answer a refused write, a hostile argument or a swapped file as JSON, and leave no temporary file

- **A write the file system refuses is JSON, not a crash and not a leftover.** `catalog_search`'s all-matches file (a full disk, `ulimit -f`) is dropped and the answer is `partial` with `all_matches_error`; the hidden `.catalog-search-*` file is also removed when an unexpected exception ends the tool. `archive_extract` and `sqlite_snapshot`: a receipt that cannot be written is `receipt_error` and `partial`, and the half-written `*.tmp.<pid>` file is removed. `ioc_scan` and `file_type`: the file of every locator or result that cannot be written is `all_results_error`, the page and the counts stay whole, and the status is `partial` when the page was not the whole result. `sig_carve`: the same for each signature's file, and the status is no longer `complete` over a hit list that no file holds. `feature_scan`'s values file and `timeline_super`'s invalid-lines listing say a write error instead of ending the run. `file_carver` names a refused write as one (it said the source could not be read). `tests/test_write_failures.py` runs the tools under a file-size limit and looks for a hidden or `.tmp` file afterwards.
- **A JSON nested 100,000 deep, and an `out_dir` that is a symlink loop, 300 characters or a lone surrogate, are refused as JSON.** `file_carver`, `file_type`, `image_layout`, `ioc_scan`, `sig_carve`, `sqlite_query`, `sqlite_snapshot`, `timestamp_decode` and `catalog_search` caught only `ValueError` where the parser raises `RecursionError`; so did the `--target` parsers of `ad1-items`, `archive-members`, `disk-timeline`, `disk-volumes` and `memory-windows`. `resolve_output` of `archive_extract`, `timeline_super`, `file_carver`, `icat_extract`, `sqlite_snapshot` and `ad1_extract` refuses what `Path.resolve()` cannot resolve. `tests/test_hostile_input.py` drives every tool and recipe with both.
- **`chunk_needles` does not wait on an icat that says nothing.** The pipe is read with `select()` against the tool's own clock, as `icat_extract` does; at the deadline icat is ended and the answer is `partial` with `next_start`.
- **A FIFO put in the place of a file after the tool checked it is refused, not waited on.** `sig_carve`, `chunk_needles`, `sqlite_snapshot`, `file_carver` and `image_layout` open the path without waiting and look at the descriptor with `fstat`; `image_layout` does so for the image before it hands it to `mmls` or `fsstat`. A swap in the instant between that check and the program's own open is not closed.
- **`disk-volumes` and `memory-windows` remove their temporaries on a stop** (`out/.fsstat.tmp` and the `mktemp` files), and write their answers with the stop signals ignored, so a late signal cannot add a second document.
- `archive_extract` prints its one document on a stop after `main()` has set its last word. `check_inputs`: `max_seconds` now says what the code does (hashing runs to `max_seconds`, then the walk gets up to a fifth of it more, at most 60 seconds), and a directory that cannot be listed has a row in the receipts. `ad1_extract` closes `gaps.jsonl` on a stop. `icat_extract` holds the stop signals back between starting icat and recording it, so a stop cannot leave icat running.
