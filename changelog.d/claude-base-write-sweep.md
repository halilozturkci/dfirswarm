### Fixed: computer-forensics-base answers `complete` only when every file it names was written whole, under a file-size limit

- **`disk-volumes` and `memory-windows`** (shell recipes) check the writes that carry the answer. A step output, `index.tsv`, `partitions.txt` or `coverage.json` that could not be written whole (a file-size limit, `ulimit -f`, makes the write fail while `fls` and `mactime` still exit 0) makes the answer `partial` and names the file, and a file at or past the limit is named in the notes. `coverage.json` is written beside and renamed over, so it is whole or absent, and the final answer is built from the values the recipe holds instead of re-reading the file (the re-read raised `JSONDecodeError` and left an empty stdout).
- **`ad1-items`, `archive-members` and `disk-timeline`** write `coverage.json` (and `image.json`) whole or not at all (a temporary file renamed over the name).
- **`ad1_extract`** says a failure of the manifest's flush or close as a manifest error and answers `partial`, where it used to end with a traceback; `coverage.json` is written whole or not at all, and a failed write makes a `complete` answer `partial`.
- **`sqlite_query`** opens the database once (a FIFO put in its place is refused, not waited on) and points SQLite at that open descriptor through `/proc/self/fd`, so a swap between the check and SQLite's own open cannot reach it.
- `tests/test_write_sweep.py` runs both shell recipes (with stand-in `mmls`, `fsstat`, `fls`, `mactime` and `vol`), `archive-members` and ten tools under `ulimit -f` at fifteen sizes from 1 up to the largest file the run makes plus one, and holds each answer to: JSON on stdout, no traceback, no death by signal, every new `*.json` parses, and a `complete` answer leaves no non-JSON file at the limit. A test in `tests/ad1-pack.test.ts` does the same for `ad1_extract` with a 300-item image. `ad1-items` and `disk-timeline` are not in these test files (they need an AD1 reader and plaso fixtures); they were swept by hand in verification with no finding, and their writes use the same whole-or-nothing helper.
- **A full disk, not only a size limit.** `file_carver` closed its output file before it removed its temporary file, so a close that failed with "no space left" left a hidden `.file_carver-*` file behind; the temporary file is now removed whatever the close does. `feature_scan` answered `complete` when a full disk cut bulk_extractor's files and the program still exited 0; it now reads bulk_extractor's stderr for a full disk or quota and writes a 64 KiB probe beside its files, and answers `partial` (basis says why) when either shows the disk refused a write. A probe cannot tell which file was cut, and says so. `disk-volumes` and `memory-windows` write a 4 KiB probe beside their outputs before the answer and answer `partial` (naming the cause) when the disk refuses it, because a step cut by a full disk can still exit 0; they also replace a coverage file they cannot rewrite by a short one that says `partial` (or remove it), so an earlier one that says `complete` never stands over a cut `index.tsv`. `archive_extract` no longer changes the mode of an `out_dir` or `extracted/` directory that already existed.
- `tests/test_enospc_sweep.py` runs the scenarios of `tests/test_write_sweep.py` (and `feature_scan`) inside `unshare -rm` on a tmpfs mounted over the working directory, sized from the room the inputs take plus 8 KiB up to 1.6 times what the run writes and the page boundaries around that, and holds each answer to the same checks plus: no hidden or `.tmp` file that a complete run does not leave, and a `complete` answer has every file of a complete run at its size. `tests/ad1-pack.test.ts` does the same for `ad1_extract`. They skip with a reason where `unshare -rm` is not allowed. On the earlier head the `file_carver` case fails at tmpfs 1,200,128 (a 600 KB output) and the `feature_scan` case fails at every size that cuts its files.
- `test_disk_volumes`' shared-clock test uses a 6-second clock over 4-second steps (it was 3 over 2, which a loaded machine could tip).
- `tests/shared-blocks.json` declares the PROCESS and STOP carriers as the census counts them (24 and 58), and `tests/tool-contract-allowed.json` no longer lists `catalog_search`, `check_inputs` and `sqlite_query`, which meet the status contract.
