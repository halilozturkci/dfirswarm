### Changed: windows-forensics and macos-forensics carry the one BOUNDARY text, which the virtualization tools can move onto

The shared BOUNDARY block of windows-forensics (amcache_apps, esedb_query, evtx_carve, evtx_query, regkv, shellbags), macos-forensics (fsevents_parse, knowledgec_query, unified_log) and the tool-library twins (amcache_apps, esedb_query, evtx_query, regkv) is now the text the three virtualization tools will move onto. It gains only what they rely on and it lacked, and each addition is inert for a tool that does not use it:

- Six identifier kinds for virtualized storage and machines, which a tool declares in its table of field kinds: `vmfs` (a VMFS volume id), `device` (`naa.`, `eui.`, `wwn-0x`, `vml.` and `t10.` ids), `iqn`, `vmuuid` (the VMware uuid of a machine), `cid` (a disk's content id) and `winhost` (the name Windows gives a machine nobody named). A string is shown only when it fits the grammar of its kind, a secret glued to it makes it a withheld string, and the second check holds a field of these kinds to the characters of its kind. A `t10.` or `iqn.` id also holds a name a person chose, and is withheld when what follows the prefix reads as random text. No windows or macOS tool declares these kinds, so what they print does not change.
- `bind_fields(table, key_kinds)`: the table of field kinds is passed in by the tool (the shared text holds none), and a kind the text does not know is refused instead of judging the field as free text. A digit run in a field name stands for any number (`ethernet#.address`); no windows or macOS table has such an entry.
- A second bound on a run: past 400,000,000 characters judged in one run, a string not judged before is withheld by its size, as it is past the clock of the seal; the final answer is always judged.

What a windows or macOS tool prints differently: when judging stopped (the seal's clock ran out, or the cap above), the answer's `boundary` now carries `stopped_by` and `strings_withheld_by_the_stop`, and the `status_basis` of the partial answer adds a sentence that names the stop and the number of strings withheld by it (the sentence about strings that "still held a secret-shaped text" is as before). An answer of a run that was not stopped carries neither key and is unchanged. The block's header now carries the map from the virtualization block's calls to this text's.

`tests/pack-boundary-shared.test.ts` finds every copy of the block under `packs/` and `tool-library/` by its markers, declares the two variants that exist until the virtualization tools move (13 carriers and 3) and fails on a third variant, a copy that differs or a changed count; it replaces the pairwise equality checks of the macOS, esedb, evtx and registry boundary suites. It also drives the block from a windows tool for each new kind (a well-formed id is shown, a secret glued to it is withheld, a run of 1 MiB of its characters is judged in bounded time), for the table of field kinds and for the cap. The 512 KiB inline cut of the virtualization tools is not part of the shared text: the block withholds the rest of any string over 256 KiB, and the tools page their rows.

The two packs and their tools are re-sealed with their versions raised, and the four tool-library twins are updated.
