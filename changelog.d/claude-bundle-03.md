### Fixed: windows-forensics, mft_records, usn_journal, indx_carve and recyclebin_i

- The four file-system readers carry the windows STOP, PAGE and PLACE blocks. SIGTERM, SIGINT and SIGHUP end each with one JSON document (status `interrupted`, exit 128 plus the signal) and no hidden temporary file, at any moment, a signal that arrives while the answer is being written included (the answer is written whole first). A result file is never replaced: a rerun whose result is smaller or different takes the next free `-n` name, and the first file keeps its bytes.
- Each tool has its own clock below the manifest's: 285 s of 300 for mft_records and indx_carve, 114 of 120 for usn_journal, 54 of 60 for recyclebin_i. It is read in every loop that grows with the input (the record and block loops, usn_journal's skip over bytes that are not a record, the directory walk), and when it runs out the answer is `partial` with a `status_basis` that names the clock and how far the read got. Before, the inputs that outran the timeout (millions of records, hundreds of megabytes of non-zero bytes, megabytes of repeated `INDX`) were ended by the harness with no answer.
- Every answer carries `status` and `status_basis`. A failure is one JSON document with `status` `failed` and a non-zero exit; an unexpected exception is the same, not a traceback. indx_carve answers `partial` (not `complete`) for a file in which it found no INDX block and for any run that names a problem. mft_records answers `partial` when a forced `record_size` is contradicted by the first record's header or by the gap between FILE signatures.
- Arguments of the wrong type are refused as JSON: a non-object, a `name` that is not a string (`name: 5`), a `record_size` past 65,536 (`2**62`), a boolean where a number is wanted and the reverse. `limit` is 1 to 10,000 in all four (usn_journal took up to 100,000 inline); the whole result stays in the file the answer names. A `name` expression is tested for at most 0.5 s per record, and one that takes longer stops the sweep with a partial answer instead of outrunning the clock.
- mft_records declares `with_resident` as secret output (`secret_output` with `when_args`), and refuses it as JSON before opening anything unless the job runs as secret output.
