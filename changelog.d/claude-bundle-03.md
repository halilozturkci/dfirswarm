### Fixed: windows-forensics, mft_records, usn_journal, indx_carve and recyclebin_i

- The four file-system readers carry the windows STOP, PAGE and PLACE blocks. SIGTERM, SIGINT and SIGHUP end each with one JSON document (status `interrupted`, exit 128 plus the signal) and no hidden temporary file, at any moment, a signal that arrives while the answer is being written included (the answer is written whole first). A result file is never replaced: a rerun whose result is smaller or different takes the next free `-n` name, and the first file keeps its bytes.
- Each tool has its own clock below the manifest's: 285 s of 300 for mft_records and indx_carve, 114 of 120 for usn_journal, 54 of 60 for recyclebin_i. It is read in every loop that grows with the input (the record and block loops, usn_journal's skip over bytes that are not a record, the directory walk), and when it runs out the answer is `partial` with a `status_basis` that names the clock and how far the read got. Before, the inputs that outran the timeout (millions of records, hundreds of megabytes of non-zero bytes, megabytes of repeated `INDX`) were ended by the harness with no answer.
- Every answer carries `status` and `status_basis`. A failure is one JSON document with `status` `failed` and a non-zero exit; an unexpected exception is the same, not a traceback. indx_carve answers `partial` (not `complete`) for a file in which it found no INDX block and for any run that names a problem. mft_records answers `partial` when a forced `record_size` is contradicted by the first record's header or by the gap between FILE signatures.
- Arguments of the wrong type are refused as JSON: a non-object, a `name` that is not a string (`name: 5`), a `record_size` past 65,536 (`2**62`), a boolean where a number is wanted and the reverse. `limit` is 1 to 10,000 in all four (usn_journal took up to 100,000 inline); the whole result stays in the file the answer names. A `name` expression is tested for at most 0.5 s per record, and one that takes longer stops the sweep with a partial answer instead of outrunning the clock.
- mft_records declares `with_resident` as secret output (`secret_output` with `when_args`), and refuses it as JSON before opening anything unless the job runs as secret output.

### Fixed: windows-forensics, lnk_parse, jumplist and lnk_jumplist

- lnk_parse and jumplist carry the windows STOP, PAGE and PLACE blocks and have their own clocks (24 s of 30 for lnk_parse, 114 s of 120 for jumplist): SIGTERM, SIGINT and SIGHUP end each with one JSON document and no hidden file, a result is never replaced by a smaller one, a clock that runs out ends `partial` with a `status_basis`, every answer has `status` and `status_basis`, and arguments of the wrong type are refused as JSON. The read of up to 256 MiB, the scan, the ExtraData walk, the string scan and the search for the end of a LinkInfo string are all inside lnk_parse's clock.
- lnk_parse counts every ExtraData block (`extra_count`), decodes the first 50 inline, keeps the first 16 tracker blocks apart (`tracker`, `tracker_count`) and writes every block as a row of a JSON Lines file the answer names (`all_extra_blocks`). A structure of eight megabytes of 8-byte blocks used to be held as a million dictionaries; it is now read in bounded memory.
- lnk_parse shows the first word of a link's arguments only when it is a program, a script or a switch whose name is on a closed list of known names. Any other switch-shaped word (`-pSECRET`, `/pSECRET`, `--password=SECRET`) is withheld whole, with `arguments_first_token_withheld`; before, a pattern told a switch name from a program, and a name and its value glued into one word could not be told apart. The manifests of lnk_parse and lnk_jumplist say this.
- jumplist bounds the DestList entries and the link structures it shows inline over the whole answer (`limit` each), where it used to show `limit` of each in every file (`limit` squared over a directory), writes the link files with mode 0600, and no longer fails on a long file name that is not UTF-8. Writing the link files is secret output: it takes `write_links: true` beside `out_dir`, which the manifest declares for the job service, and the tool refuses as JSON, before anything is created, when the job is not run as secret output. lnk_parse declares `write_strings` the same way. The manifest no longer says an automaticDestinations stream is read in pieces: it is read whole, up to 32 MiB.
- lnk_jumplist keeps its own stop handlers when it loads lnk_parse and jumplist, which now install their own: a signal while lnkinfo runs ends lnkinfo, removes the temporary files and gets lnk_jumplist's own answer. Its link rows keep every tracker block and carry `arguments_first_token_withheld`.
