### Added: CI runs the pack-tool suites on the images' Python 3.11

The pack tools run in the VM images on Debian 12's Python 3.11, and no CI job met that interpreter: the Linux jobs run Ubuntu 24.04's 3.12 and the macOS jobs 3.14. A new job, `python-311`, runs the `tests/pack-*.test.ts` suites in two shards inside the base image's own `node:24-bookworm-slim` (the digest `images/base.Dockerfile` pins; a test compares the two), with Debian's `python3` installed from the images' apt snapshot, as the image's unprivileged user, and fails when the interpreter is not 3.11. `scripts/test-select.ts` reports `py311` for a change to a pack, the tool library, an image file or a pack-tool suite, and every run that runs everything (the nightly run, a run by hand, the `full-ci` label, a change to the workflow) runs the job; `CI green` needs it. The container runs with `--init` (the runner's own first process reaps nothing, and a program a suite kills would stay a zombie that a stop-signal case still sees as a pid), and the job leaves out one case by its name, lnk_jumplist's walk of `/` with a one-second clock, which needs a file system too big to walk in a second and ends `complete` on the image's small root; the Linux and macOS jobs run it, and a test holds the job to that one name. The job adds runner time to every pull request that changes a pack.

### Fixed: the named flaky tests no longer depend on the host's clock or load

The model gateway's refusal log takes its clock from an option (default `Date.now`), and its test drives a fake clock across a minute boundary instead of counting six calls inside whatever minute the host was in. The 16 test files and one fixture that read `ru_maxrss` read the tool's own peak through one helper (`tests/fixtures/peak_rss.py`, `tests/peak-rss.ts`): on Linux `ru_maxrss` keeps the size of the process image that exec replaced, so a child forked from a large parent read as that large; the helper reads VmHWM of the image the process runs now, and `tests/peak-rss.test.ts` fails if a suite reads `ru_maxrss` itself again. The heartbeat test of `tests/table-lock.test.ts` no longer fails when a heartbeat tick is between its read and its write while the test replaces the lock directory (ENOTEMPTY on the macOS runner, run 40645078378). The stop-signal tests of the network pack (pcap_extract, suricata_run) and the re-parenting case of the linux pack wait for a state with a deadline (a minute; twenty seconds for the linux case) instead of a fixed number of polls and a fixed sleep afterwards, and the mobile-forensics slow-reader test counts the pauses it made instead of the wall time the host took.
