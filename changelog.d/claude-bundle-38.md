### Added: triage-collection keeps the clocks of a delivery apart with `collection_timestamps`

A new tool reads two clocks as separate objects, each with its precision and its zone: an archive's member times (a zip header's DOS date and time, two-second steps with no zone and never read as UTC; a zip's extended-timestamp and NTFS fields; a tar's whole seconds; a pax mtime to the digit the writer wrote) and the delivered files' modification times (one `lstat` per entry, `modified_epoch_ns` as a decimal string). It gives each clock's earliest and latest time with the raw value, `apparent_flattening` (more than 90% of more than 20 files on one date, as a count and with no cause), a per-file comparison only where an archive member and a delivered file have the same name after NFC and case folding, and the conflicts. `local_zone` reads a zip's zoneless times under a named zone and says which times a clock change makes ambiguous or non-existent. The archive is read by the collection-intake recipe's bounded readers (the same text, held equal by a test) and never extracted: a damaged or appended gzip, bzip2 or xz stream, a tar without its end-of-archive marker (two zero blocks; one is accepted, as GNU tar does), a zip with bytes in front of it, or an archive inside the archive makes the answer `partial`. `verify/time-layers` names the tool. It also keeps the collector's own record times (a KAPE copy log's time columns, the timestamps of UAC's log, KAPE's console log and Velociraptor's `log.json`, a Velociraptor upload row's `Timestamp` and `started`) as the collector's raw text with the zone its writer states and the basis for it (a time with none is a wall-clock reading and is never taken to be UTC), gives each collector log's first and last timestamped line as the acquisition interval (`unknown` where no log states one, never inferred from file times), and compares a copy row's `ModifiedOnUtc` with the delivered mtime of the file the records join names, only where it names exactly one; a record cut by the clock, malformed or in another encoding makes the answer `partial`. `verify/collector-effects` names the tool too.

### Changed: the image recipe installs the data a pack pins for a program that is not in the image

`images/recipe.py` dropped the `install.data` of a program declared `not_in_image` along with the program. A pack that pins definitions for a tool to read (as opposed to a program it runs) can now declare them on the collector's entry: the program stays under "not applicable", and its data entries are in the spec like any other. The rule goes by kind, never by a program's or a pack's name.

### Added: triage-collection compares what a collector's profile could request with what the delivery shows, with `collection_profile_compare`

A new tool, a parser and a comparator and never a live collector, resolves a UAC profile's artefact list (include globs and `!` exclude globs, in order), a Velociraptor collection's recorded request (`collection_context.json`, read as data, each artefact looked up by name with its parameters) and the KAPE targets a run names (`.tkape` files, compound targets followed to a depth bound, a cycle refused by name, a `%user%` path unresolved and never expanded) against definitions read from three corpus archives. Each archive is hashed and compared with the list of sha256 in the script before one member is read; one not on the list is refused (or, with `allow_unpinned`, read and everything from it reported as version `unknown`), and every definition file used is reported with its version and sha256. Only UAC 3.4.0's hash is on the list in this version; the Velociraptor and KAPE lists wait for their archives to be pinned, so without `allow_unpinned` those two answer `definitions_not_available` and `partial`. The answer lists `could_request`, `requested`, `excluded`, `collected`, `not_collected` (with the collector's own words), `unresolved_dynamic_selection`, `differs` (a profile, definition or target file in the delivery that differs from the pinned one is described and never used), `unknown` and `proposed_additional_evidence` (a list for the operator, never a command). A bounded YAML reader refuses anchors, aliases, tags, merge keys, complex keys, more than one document, tabs in indentation, duplicate keys and any file, line count, depth, node count or scalar over its bound, by name. `verify/target-outcomes` names the tool.
