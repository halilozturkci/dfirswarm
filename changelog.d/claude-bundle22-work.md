### Fixed: windows-forensics skills and README say what the tools withhold, and how to describe a found secret

The pack's skills and README said that `lnk_parse`, `lnk_jumplist`, `browser_history`, `utf16_urls`, `yara_scan` and `jumplist` print none of a secret, or that URL tokens and arguments are "withheld". The tools withhold by shape or by name, and a secret of another shape is printed (a token in a URL path or under another parameter name, a secret inside a value that does not look like one, a first word of program shape). Every Sensitive-output line that names one of these tools now says what its withholding goes by and what is printed, and the README no longer says five tools "print none of it".

Every leaf that names a tool whose manifest declares `secret_output` now says how to describe a found secret: by where it sits, its kind, length and what it grants, never its value, a fragment or a digest. The Sensitive-output line missing from `filesystem/indx`, `filesystem/journals`, `filesystem/recycle-bin`, `filesystem/shadowcopies`, `execution/prefetch` and `execution/prefetch-carved` is back. Sentences lost when the skills were split are restored: run `sigma_hunt` once at `informational` (`logs/hunting`), Event Viewer shows local time (`logs/security`), run `vol` offline and record its version and symbol identity (`memory/windows`), and never record password material (`accounts/logons`). "Operator" no longer names the adversary. `tests/pack-windows-skills.test.ts` holds these as rules.
