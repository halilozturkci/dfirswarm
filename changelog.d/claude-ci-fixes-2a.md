### Fixed: doc_structure answers as JSON under a Python older than 3.11, and the node tests state what a host must hold

`doc_structure` (reverse-engineering 1.16.5, tool version 12) compiles possessive quantifiers at import, so under a Python older than 3.11 it ended in a traceback before `main()` could refuse the call. The refusal is now written as JSON, by name, before those blocks are reached. In the tests, the cases that hold only where the tool can adopt the orphans of a program (Linux) are skipped elsewhere, named by one shared reason in `tests/host-gates.ts`; the darwin and refused cases of the process-apply suites keep covering the answer of a host that cannot. Tests that narrow PATH keep the interpreter that runs the tools, test directories are made under their real path, the deep 5,000,000-row case of `pack-network-conn-series` moves to the deep list, and three stale `VIRT-09` entries are gone from `tool-contract-allowed.json`.

The tool-library copy of `sig_carve` follows the pack again (version 16), and the missing-binary test of `esedb_query` and `yara_scan` narrows `PATH` to the stand-in directory and a link to python3, so a host that has `yara` installed no longer fails it.
