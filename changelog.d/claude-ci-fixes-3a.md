### Fixed: capture_transform runs its programs from a temporary directory it names by an absolute path

- **capture_transform on Python 3.11.** `tempfile.mkdtemp` answers a relative path when `out_dir` is relative on Python 3.11 (the images' interpreter; 3.12 answers an absolute one), and the programs (editcap, mergecap, tcpdump, text2pcap) run with that directory as their working directory, so a relative output path named a directory that did not exist from there and no derivative was written. The temporary directory is now made absolute. Pack raised: `network-forensics` 1.14.10 (capture_transform 6).
- **Tests no longer depend on the host they ran on.** The macOS log-reader copies are checked for being executable, not for the exact mode a checkout's umask gives them; the two full-ranges-file cases are skipped where a tmpfs cannot be mounted in a user namespace (`NO_TMPFS_NAMESPACE`); the stand-in of the unified_log setsid storm creates its pid file before it waits on it.
