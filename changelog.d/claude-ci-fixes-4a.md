### Fixed: a flooded converter pipe on a host that cannot adopt orphans no longer gives a "ready" ISF table; `conn_series` reports its peak memory in kilobytes on macOS; the tests state what the host holds

- **`isf_intake`** (memory-forensics 1.15.9, tool version 7). The converter's output is read by the tool's own reader (`run_engine`), which gave a flood that a leftover wrote into the pipe after the converter had ended one second of grace and kept every byte it read as part of the table. Where the leftover is adopted (Linux) it is found, ended and counted, and the table is dropped; where nothing is adopted (macOS, `PR_SET_CHILD_SUBREAPER` refused) it was not found, and the answer was `ready` over a table of 154 MB with the flood in it. The reader now counts the bytes that come after the program has ended and, past `POST_EXIT_BYTES`, lets the pipe go and counts the cut (`PIPE_CUT`, as `communicate_bounded` does); `program_group_problems` turns a cut into a problem on every host, as `package_verify`'s does, so no table is kept and the verdict is `unknown`. A leftover that writes more slowly than the cap cannot be told from the converter on a host that cannot adopt it: the answer carries `program_group.unproven`, as before. New: the two `flooded` cases of `tests/pack-memory-process-apply.test.ts`, run on the `darwin` and `refused` hosts everywhere.
- **`conn_series`** (network-forensics 1.14.12, tool version 7). `resources.max_rss_kb` was `ru_maxrss` as it comes, which macOS counts in bytes: a run of 600 MB said 607,125,504 kB. It is divided by 1,024 there.
- **Tests.** A case that needs a host that adopts the orphans of a program, finds a leftover that holds the program's pipes, or reads `/proc` is skipped elsewhere with the one named reason (`NO_ADOPTION`, `NO_PROC`), where it was run on macOS before; the cases whose answer differs by host expect `CLEAN` there (`partial`) and the host's own exit code (`out.ok`, the recipes' `coverage.json`). The macos-triage recipe answers "does not apply here" on arm64 (mac_apt is installed in the amd64 image only), so the cases that need it to run are skipped on an arm64 host (`NO_MAC_APT`). Cases that keep two names that differ only by case, or a name that is not UTF-8, are skipped where the file system folds case or refuses the name. `withCwd` makes its directory under `/tmp` on macOS (its per-user temporary directory has a part that looks like a token, which the tools withhold from their answers). `otool` is asked for every slice of a universal binary; the decompression-bomb fixture makes its tar header without `addfile` (Python 3.14 wants the body); the `container_inventory` case accepts a parser that reads 100,000 levels of `[` (Python 3.14) and says the file is unreadable for the other reason; the capa-floss recipe is started with the real interpreter, not Xcode's 3.9; a planted tool in the stop-contract suite lists its temporary file before it creates it; the fsevents result-file case compares with the fixture's record count, not with a limit that cuts it on one host and not on another; `test_memory_windows` expects `complete` of a shell recipe on every host (the base pack, 1.16.7). The shell suites expect the exit code and status of a host that cannot adopt (`pack-recipes`, `pack-tools`).
