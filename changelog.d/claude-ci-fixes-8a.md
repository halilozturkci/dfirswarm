### Fixed: a stop signal that lands as a call ends no longer kills it by the signal's default action (network-forensics), and the hidden file of a result page is registered before a stop can find it (windows-forensics, encrypted-containers, network-forensics)

- **The ending of the network pack's tools (all eleven, network-forensics 1.14.13).** The CI run of `main` on the hosted Mac ended `tests/pack-network-pcap-summary.test.ts` ("the tool keeps its own clock") with `null !== 130`: a SIGINT that landed after the call had printed its answer, in the interpreter's teardown (which resets the handlers to their defaults), killed the process by the signal's default action. Same family as the reverse-engineering directory tools (round 6), but here the whole pack carried it: `__main__` of every tool ended through the normal teardown. Every tool now ends with `_leave(code)` (flush standard output, then `os._exit` with the exit code the call had; `fail()` and a returned status still give their own code). The three tools that print one document at the end (`pcap_summary`, `beacon_score`, `network_log_summary`) had a second hole: a signal that landed after the answer was printed, and before the call ended, still ran the handler, which wrote a second document ("no summary had been answered yet", a false claim after a whole one). They now serialize the answer first, then set a flag (`ANSWERING`) that the handler reads, and the handler lets the answer finish. The eight tools that already print through a signal-holding `answer_out` (`zeek_run`, `suricata_run`, `pcap_extract`, `capture_transform`, `flow_reader`, `tls_decrypt`, `quic_inspect`, `conn_series`) get only the `_leave`. `tests/pack-network-stop-after-answer.test.ts` sends each of the three signals the moment a complete document has been read, six times each, for all eleven tools (a success where no outside program is needed, a refusal otherwise): 0 of 18 may die by the signal and the answer stays one document; before the change the three summary tools died in the first round. It also pins the ending in all eleven scripts.
- **The hidden temporary file of a result page (the `NoReplacePage` of the SHARED PAGE block, 40 tools: windows-forensics 21 (1.7.34), encrypted-containers 6 (1.14.8), network-forensics 5 (1.14.13), ransomware-response 8 (1.13.7)).** `LosslessPage.add()` makes the file with `tempfile.mkstemp` and names it in `_tmp` on the next line; a stop signal between the two found no file to remove and left `.<name>-*` behind. The macOS CI run met it in `usn_journal: SIGTERM at temp` (the case sends the signal the moment the file appears; it passed on the rerun). `NoReplacePage.add()` now holds the stop signals while the file is made and registered; the signal waits and is answered by the handler that removes the file. `tests/pack-page-stop-registration.test.ts` sends the signal right after `mkstemp` returns, in each of the tools that can be driven that way: the old block left the file in 1 of 1 runs, the new one leaves none. `usn_journal` itself had neither hole of the network pack (it prints through `print_answer`, which holds the stop signals for the rest of the call); the ransomware-response tools carry the same block (a test pins it byte-equal to the windows pack's) and now carry the changed `add()` too (ransomware-response 1.13.7), although their own `LosslessPage` already holds the signals around the same two lines: the holds nest.

By rule 2 of AGENTS.md the block is fixed in all of them at once: the `__main__` part of each of the 116 remaining tools is wrapped (`SystemExit` becomes the exit code) and ends with `_leave(code)`: flush standard output and error, run the atexit hooks (the hooks that remove a temporary file, in cloud-forensics, computer-forensics-base and triage-collection, are not lost), `os._exit(code)`. Four computer-forensics-base scripts have no `__main__` guard (`catalog_search`, `check_inputs`, `chunk_needles`, `icat_extract`): every `sys.exit` of theirs is `_leave` now. Two more holes found on the way: `doc_structure.emit()` set the flag the handler reads before it serialized the answer (the same as the three directory tools in round 6), and `fuzzy_hash` printed its answer with the engines' last word still armed; and 33 tools whose `fail()` printed with a plain `print` now hold the stop signals first (a refusal comes before `main()` installs the handlers in some of them, and where they are in a signal after it wrote a second, false, document: `linux_triage`, `lnk_jumplist`, `virtualization_inventory` in the new test). `tests/pack-stop-after-answer.test.ts` runs every tool of every pack with `{}` (a refusal) and sends each of the three signals the moment a complete document has been read: 0 of 6 per tool may die by the signal or print a second document; a static case pins the ending in every script.
- **Mobile stop case, exit 227.** 227 is the test's own number for "killed by a signal" (`128 + 99`): on the hosted Mac the harness's 60-second guard ended a tool that had not answered the SIGTERM, after the stand-in `hang()` had slept 60 seconds in one call. `hang()` sleeps in 50 ms steps now, so the main thread runs a pending handler at once, whichever thread the kernel gave the signal to. Not reproduced here; the mobile tools carry the `_leave` as well.
