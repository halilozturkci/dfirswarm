### Added: one `CI green` check, the one main requires

A pull request could not merge by itself once it was green: `main` required no check, and naming each of CI's twenty-odd parts in a ruleset would break whenever a shard count changes. `ci.yml` now ends with a `CI green` job that needs every other job, always runs, and passes only when each of them passed or was skipped (the microVM job when no image or pack requirement changed, the replay on a push); a failure or a cancelled run fails it. A ruleset on `main` requires that one check, so auto-merge on a pull request merges it as soon as CI is green, and a red pull request cannot be merged by accident. `tests/ci-shards.test.ts` holds the job to need every other job in `ci.yml` and to keep its name. No harness, pack or skill file changes.
