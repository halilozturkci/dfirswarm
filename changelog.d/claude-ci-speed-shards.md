### Changed: the Linux CI job runs in six parts, and two waits are gone

The Linux job was the longest of every run and the one each pull request waited for: 67 min 12 s on a green run of 27 October (npm test 31 min 36 s, test:bash 24 min 6 s, the Playwright browser 8 min 36 s). Nothing it runs is dropped.

- **Six parts side by side**: three node parts (`npm test -- --test-shard=I/3`, the typecheck in the first), two shell parts (`npm run test:bash -- --shard I/2`, dealt out by `tests/shell-suites.weights`), and the UI build with the tracked-files check. `tests/ci-shards.test.ts` holds the Linux parts, as it already held the macOS ones, to run every node suite and every shell suite exactly once, the browser to be required where it is installed, and the UI build to run once.
- **The Node 22.19 and Node 24 jobs in two parts each** (node shards, the floor's typecheck in its first): with the Linux job split they were the longest of the run, about 33 min each as one job. `tests/ci-shards.test.ts` holds their parts too.
- **The browser without the apt wait**: the headless shell is a 3-second download; `--with-deps`' apt fetch of its libraries took 8 min 28 s at 51 kB/s. The parts install the browser alone, launch it to prove it starts, and fall back to `--with-deps` only when it does not.
- **The microVM job's images are cached**: building base and disk took 4 min 24 s of the job's 6 min 54 s. The saved images are kept under a key of `images/**`, the packs' `requires/**` and the ISO week (nothing else goes into them), so an upstream change is still met within a week here and at once in `images.yml`.
