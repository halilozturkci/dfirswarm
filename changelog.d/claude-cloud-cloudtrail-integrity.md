### Added: cloud-forensics routes the CloudTrail integrity check to the operator

The pack has no digest or chain verifier and the analysis image holds no AWS program or credential, yet `aws/cloudtrail` said only that a validation was not performed unless the case supplied a record. A second-level leaf, `aws/cloudtrail-integrity`, now opens from it "only if" a validation is wanted. It tells the agent that the operator validates the digest files with `aws cloudtrail validate-logs` (trail ARN, start and end times) outside the image and that the agent cites the recorded result, names the options of the command from the AWS CLI reference read on 2026-11-01 (marking what that page does not document: the wording of a failure, the effect of `--verbose`, the exit status), fixes the result vocabulary (`verified`, `failed`, `unavailable` per digest file and per log file, plus gaps in the chain), and says that an export without the S3 object metadata (the digest signature) cannot show that validation and that a file hash is not that validation. The agent is never told to run the program: `aws` stays an operator's program that is not in the image, and the leaf lists it under `mentions`. The router names the new id and the pack now carries eleven skills.
