### Added: cloud-forensics reads GCP audit logs, Kubernetes audit events and Entra directory audit records as canonical rows (`cloud_normalise`)

A fourth tool in the cloud pack turns an identified export (JSON, JSON Lines, CSV whose header carries the Graph property names, gzip of those; a file, several, or directories) into streaming canonical JSONL, a `rejected.jsonl` and a `coverage.json` per source. It is a core with three adapters:

- **`gcp_audit`**: Cloud Logging entries whose payload is a Cloud Audit Log: the principal and its delegation chain, service, method, resource, status, caller address and user agent, the log's type, the project, and the event time beside the receive time.
- **`kubernetes_audit`**: `audit.k8s.io/v1` events, alone, as lines or in an `EventList`. A record is one stage and one row: the stages of one audit id are never merged into one action. A request or response body that is a Secret object is replaced whole before the record is cleaned.
- **`entra_directory_audit`**: Graph `directoryAudit` records, the initiator (user or application) kept apart from the target resources and their modified properties. The values of modified properties are sensitive: a property named like a secret has both values withheld and every other value goes through the credential rules.

Each row has the provider, the tenant (or says the record names none), principal, action, resource, outcome with its basis (unknown when the record says nothing), the raw time and the UTC time (a time with no zone is never read as UTC), a locator (file, record, line, offset in characters of the decoded text) and the whole record, cleaned. A record no adapter reads, a malformed line and a record over `max_record_bytes` are rejected with a reason and a locator and counted; a duplicate is annotated and kept. The coverage names, per file, the format, the counts read, rejected and unsupported, the observed time range, pagination markers (`nextPageToken`, `@odata.nextLink`) and the first failures. One clock (`time_limit_seconds`, default 420, at most 480 against the 600 the call has) covers the walk, the reads, the withholding and the writes, and a signal leaves a partial coverage file and one line of JSON. The tool carries the shared blocks of the other three cloud tools byte for byte, declares `secret_output` for `write_values` and writes its values only to a mode 0600 file in a secret job.

The fixtures are written from each format's published field list; no real export exists and no vendor page was read while building them (`tests/fixtures/cloud-normalise/SOURCES.json`). `entra/signins` and `identity/tokens` name the tool where they said the directory audit had no reader. Pack: cloud-forensics.
