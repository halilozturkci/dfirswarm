### Added: cloud-forensics reads Azure Activity log records, S3 server access logs and VPC Flow Logs as canonical rows (`cloud_normalise`)

Three more adapters of the same tool, with the same rows, rejected file, coverage file, one clock and masking:

- **`azure_activity_log`**: Activity log events as JSON (the REST list's `value` array, an envelope or lines) or as a CSV whose header carries the field names. A start and its completion are separate rows of one correlation id and are never merged; a status of Started or Accepted is an unknown outcome, not a success; the scope and resource ids are printed as written, and the claims, properties and request are kept whole and go through the credential rules.
- **`aws_s3_access_log`**: the space-separated S3 server access log, 27 fields per line. `-` is null; fields appended after the last documented one are counted and kept; a quoted field that holds a quote is counted; a line that does not have the time field, or does not quote the request URI, referer and user agent where the format does, is rejected with its line number.
- **`aws_vpc_flow`**: VPC Flow Logs as delivered text. The fields are named by the file's header line (a repeated header replaces it), for every field the AWS page lists through version 11; `start` and `end` are Unix seconds; a record with no header line is read only in the 14-field version 2 default order, or in the order the new `vpc_flow_fields` argument names. A `NODATA` or `SKIPDATA` record is a row of kind `no_flow_record` with no packet or byte count, never a flow of zero traffic.

The AWS field lists were read from the AWS documentation pages named in `tests/fixtures/cloud-normalise/SOURCES.json` on 2026-11-04. The Azure documentation was not read: the Azure field names are the work card's, and the layout of the portal's own CSV export is not known to this version (a CSV whose header does not carry the field names is rejected row by row and counted). A directory walk now also reads names ending `.txt`. `logs/sources`, `aws/cloudtrail` and the pack README no longer say that these three families have no reader. Pack: cloud-forensics.
