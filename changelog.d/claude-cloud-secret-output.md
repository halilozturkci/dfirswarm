### Fixed: cloud-forensics declares its values mode as secret output and honours it only under SECRET_OUTPUT

cloudtrail_parse, signin_analyse and ual_parse take `write_values`, which writes the originals of what they withheld to a mode 0600 file under `$OUT`. Their manifests carried no `secret_output` key and the shared `SecretValues` checked only `JOB_ID` and `OUT`, so a job with `write_values: true` but without the agent's own `secret_output: true` was sealed as ordinary output: the values file was not marked sensitive, a redacted package did not withhold it, and its reads were not recorded as reads of sensitive output.

All three manifests now declare `"secret_output": {"when_args": ["write_values"]}`, so a job with `write_values` runs as secret output whether or not the agent set the flag (`secret_output_by: "tool_manifest"`). `SecretValues` refuses as JSON, before it creates anything, in a run whose `SECRET_OUTPUT` is not `1` (a direct run, or a command job that was not run as secret output), with `write_values: "refused"`, `written: false` and a message that nothing was written. The refusal text is the same in all three copies of the shared block. The `write_values` descriptions say so.
