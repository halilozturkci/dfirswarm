### Fixed: computer-forensics-base reads a partition table only as mmls writes it, says what it did not read, and holds the scanners to their clock

- **`disk-volumes` and `image_layout` no longer take a forged row that continues the table's sequence.** A row is now the shape mmls writes: a slot, a table column and three columns of ten or more ASCII digits (mmls prints them `%.10`; a GPT name of 36 characters cannot hold a line that long), in sequence, with an end and a length that agree with the start. Digits of other scripts are not digits here, and `image_layout` splits only on the line feed, as the recipe does. A line of the table after its header that is not read as a row is a note, and the status is `partial`, so a forged last line can no longer leave a phantom volume under a `complete` answer.
- **A long run of zeros no longer hides lost AD1 items.** The check for data no item leads to reads the first 256 MiB of it; when that is not all of it and the part read held nothing, the recipe and `ad1_extract` now say `partial` and `unverified`, naming how much was read, where they used to say `complete` and `verified`.
- **`ioc_scan` and `chunk_needles` read their clock every 256 matches, not only between reads.** A stream of one repeated byte searched for 30 nested needles ended after 19 s for a 5-second clock (92 s for 150); both now end at the clock with `next_start` just after the last offset taken, and the engine holds one position per needle instead of every match of a read (1.7 GB resident for 60 needles before, 30 MB now). Going on from `next_start` finds what one scan finds, with no occurrence twice.
- **`finding_id` names the occurrence** (its offset and needle variant) instead of counting from F000001 in every call, so a scan that goes on never reuses an id. `complete` is false beside every `partial` status, a values file that stopped at its cap included. The whole-result file (`all_results`) has a byte cap of 1 GiB beside its row cap, and when either is reached says `all_results_complete: false` and where it stopped.
- **Smaller corrections.** `ad1_extract` answers a JSON array on stdin, and the recipes an invalid or non-object `--target`, as JSON and not a traceback. `archive-members` lists a 7z with `7zz`, `7za` or `7zr` when there is no `7z`, as `archive_extract` does, and notes it when a file that starts with a zip signature is also a tar. The scanners skill no longer says `chunk_needles` takes `start` and `length`. Each fix has a test that fails on the code it replaced.
