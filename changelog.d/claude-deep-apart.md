### Changed: the deep node suites run apart, under a fifteen-minute limit

Node 22 holds each whole suite file to `--test-timeout` (five minutes). In #233's run on the hosted macOS runner, `pack-triage-slots` and `pack-virtualization-boundary`, which take about two minutes on other runs, were cut off at 300 s with no test failed, and on the owner's Mac mini at concurrency 3 four more deep files were. `npm test` now runs the suites `tests/node-tests.deep` names in a second `node --test` after the others, under fifteen minutes (`DEEP_TIMEOUT_MS`); the others keep five. `--test-shard=I/N` is cut by `scripts/test-node.ts` instead of by node, by the same round-robin rule over the others and over the deep suites apart, so every suite still runs in exactly one shard and each shard holds an even share of the deep ones. `--timings` writes one document for both runs, `--retry-alone` retries each run's failures under that run's limit, and a failure in either run fails the whole. `npm test -- --list` prints what a run would run. The CI jobs and their names are unchanged; `tests/ci-shards.test.ts` now checks the script's own shards, the deep suites last in each, instead of node's.
