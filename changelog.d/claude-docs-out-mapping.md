### Changed: the worker prompt and the docs say how $OUT is mapped and what the by-shape rule misses

`prompts/worker-system.md` gains one bullet under "Tool jobs": a tool run as a job writes only `$OUT`; a place given as an output under `work/<you>/` (or `work/extracted/<you>/`, `work/quarantine/<you>/`, `tool-output/<you>/`) is given as `{OUT}/<name>` (under `{OUT}/extracted/`, `{OUT}/quarantine/`, `{OUT}/tool-output/` for the other three); a file that has bytes in it or a directory with entries is what the tool reads and stays as given, and an empty directory is taken as an output place; the answer's `written_to`, `not_written` and `unconfirmed` say where each place went, which hold nothing, and which this VM could not yet see (read from `placedOutputs` in `extensions/protocol-core.ts`). It also says that `check_inputs`, the base pack's tool, is not `inputs_check`, the harness's own event; `docs/protocol.md` says the same where `inputs_check` is described. `docs/packs.md` section 8 states once, in ADR 0018's terms, what the shape rule misses (printed in the answer) and where to use such a file (a `secret_output` job's sealed output). The five kickoff goldens are regenerated: only their `SYSTEM.md` changes, by the new bullet.
