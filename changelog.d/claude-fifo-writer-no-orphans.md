### Fixed: the registry tests no longer leave a blocked FIFO writer behind

The helper of the "a pipe is not a hive" tests fed its named pipe from a child `sh -c 'head -c 20000 /dev/zero > pipe'`. The shell forks to do the redirection, so the SIGKILL the helper sent after the test ended the outer shell only; the forked one stayed at open() for ever, once per test run (three per run), and a runner that died before the cleanup left them all the same. On a developer's Mac 248 of them, some 11 days old, had piled up in `$TMPDIR/lib-eval-*/work/pipe`. The writer now lives in the test process (an open() on a libuv thread, then 20000 zero bytes), so no process outlives the runner whatever kills it, and the test opens the pipe itself, non-blocking, to release the writer when the tool under test never opened it. The test still proves what it did: a tool that opens the pipe anyway reads to the end and fails instead of waiting. It is a test change only; no pack is changed.
