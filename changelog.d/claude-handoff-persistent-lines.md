### Fixed: the lines every seat's prompt carries no longer disappear at its first hand-off

The prompt the extension forces in `before_agent_start` lasts for the run a user prompt starts. A self-compact hand-off starts the next run with a custom message, which has no `before_agent_start`, so every request after the first hand-off went out on Pi's own prompt sections and without what only the forced prompt said: the seat's id, the stop rule, the read-only inputs rule (the files, the sets, "never write, delete, move or chmod"), the forging rule and the self-compaction mechanics (shown through the real CLI in `tests/skills-e2e.test.ts`). The skill index had the same problem and was moved to Pi's own sections in the skill-delivery change; this moves the rest.

- **The kickoff writes what holds for the whole run to two files** (`scripts/seat-prompt.ts`): `<sandbox>/.pi/APPEND_SYSTEM.md` for the run (the packs' skill index, the self-compaction mechanics, the inputs rule read from `inputs.json`, the forging rule; empty when none applies) and `<sandbox>/.pi/seat-<id>.md` for each seat (its id and the stop rule). Every seat is started with both (`--append-system-prompt`, at the three places the kickoff starts a seat's Pi: the host panes, the probe, a VM's launch script); Pi appends them to its own prompt sections, which every run keeps. An explicit source also replaces Pi's discovery of an operator's own `~/.pi/agent/APPEND_SYSTEM.md`, which a run with no pack used to get.
- **One wording** (`extensions/seat-prompt.ts`, no Pi imports): the kickoff writes the lines and the extension recognises them in the prompt it is given, adding to the forced prompt only a line the prompt lacks (a manual start, a sandbox from before the files) and what changes: the seat's name, the sentinel, a cap that was hit, the tools forged so far, and what this pane measured of its guard on `inputs/`. The inputs rule says what holds in every pane (a write is refused, or detected and undone, and announced); the kernel claim is the measurement, said to the first run.
- **The hand-off header carries the two rules that change** and that the prompt of the run a hand-off starts therefore cannot: what the seat is told when the run's cap was hit, and the tools forged so far (`Tool forging is on. Forged so far: ...`, or "Nothing has been forged yet. Call `tools` before you forge one, in case a peer has."). The cap words are the live steer's (`capSteerText`), by the run's stop policy and cap: under cap-pause, the default, the run pauses for the operator to extend it and the seat is told not to call done; under cap-stop it is told to stop; a token cap is worded as one. The forced prompt says the same words now (it said "Call done(reason=cannot_complete) now" under every policy, and printed dollar figures for a token cap), so the steer, the prompt and the header cannot disagree. The header's last paragraph ("do not end your turn, work on until the definition of done is met") is not said when the lines above order the seat to stop (the sentinel stands, or a cap-stop cap was hit).
- **The inputs wording is exact for how the evidence is held.** A write is refused or, where it gets through, detected and announced; "undone from the pristine copy" is said only for a copied run. Evidence held in place (bind, or an attached image) has no copy to restore it from, and the rule and the pane's measured line say so instead of promising an undo; a pane without the kernel guard says the tools refuse a write through write or edit, and what happens to one through a shell.
- **The kickoff's writes into `.pi/` never follow a link.** `scripts/seat-prompt.ts` removes a name and creates the file with `wx`, so a link a host pane's shell planted there (the pane can write the sandbox, and a resume runs the kickoff again in it) is replaced and its target left alone; so are `SYSTEM.md` and `settings.json`, which had the same hole. A file the script cannot write is named in the kickoff's BLOCKER (it said "Node.js v24").
- **A prompt file that is gone at run time is a fault.** Pi takes the path of a missing `--append-system-prompt` file as the prompt's text; a seat that finds `.pi/seat-<id>.md` or `.pi/APPEND_SYSTEM.md` in its own prompt logs an `extension_error` and puts a veto on the board, once.
- **An empty run file is not passed** (`seat_prompt_args`, one function at the three launch points), so the prompt does not open with blank lines; the seat's file is always passed, which is what still replaces Pi's discovery of an operator's own file.
- Tests: the e2e that was a diagnostic is an assertion: after a real hand-off the seat's line, the inputs rule and the self-compaction mechanics (and, with forging, the forging rule) are in every request exactly once, the first run's included; the operator's global `APPEND_SYSTEM.md` never reaches a request; the cap rule under cap-pause and cap-stop through a real hand-off; the kickoff goldens carry the run's file and the first seat's, and two cases more (a pack with a router, forging and two input sets; a run where nothing applies, whose run file is empty). The kickoff passes `--no-skills` and the seat's files, in order, at all three launch sites (`tests/skills.test.ts`).
