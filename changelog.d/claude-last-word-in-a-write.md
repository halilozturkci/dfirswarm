### Fixed: a stop signal during a write leaves no paging file unnamed (linux-forensics)

`utmp_parse`, `cron_dump` and `shell_history` end on SIGTERM, SIGINT or SIGHUP with a last word that keeps each paging file under its final name. Python can run that handler inside a buffered file's own flush, where the file refuses a second flush: a signal that came while a row was being written left that paging file as an unfinished temporary file, not named in the last word (the SIGTERM tests met it now and then on a loaded CI runner), and a signal that came while an answer was being printed could cut it and lose its exit status. Now a signal during such a write is answered once the write is done, every row written so far whole in the kept file; a signal while the answer or an error answer is being written is not answered, so that answer stands alone. Every paging file is named from the moment it exists: `cron_dump`'s `locations` file had never been, and a signal while it was written left it unnamed. `finish()`'s file is named too when a signal comes after it. A harness in `tests/pack-linux-bounds.test.ts` makes the signal land inside the flush every time, for the paging file and for the answer of each of the three tools; all six cases fail on the old code.
