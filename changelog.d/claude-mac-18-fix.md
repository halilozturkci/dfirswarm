### Fixed: macos_triage, the macos-artefacts recipe and unified_log no longer answer complete over a file that a child of the program is still writing; the mac_apt log reader no longer reads a quoted, shapeless or over-long line as a plugin line, a clean line or an unread one, and its read has a clock

- **An abandoned child cannot make a run complete.** mac_apt (or the unified log reader) could write a clean log, exit 0 and leave a child that closed its descriptors and wrote later (a traceback line in the log, 100 KB more in `mac_apt.db`): the answer said `complete` with the early sizes. On Linux each tool now makes itself a child subreaper (`prctl(PR_SET_CHILD_SUBREAPER)`) before it starts the program, so every orphan, whatever its session or process group (setsid, setpgid, a double fork, a periodic writer that never exits), comes to the tool. When the program has ended the tool kills those children (start time and parent read again before the signal), reaps them, and ends new members of its own group, until a round finds none (3 s at most), BEFORE any size, hash, file list or log is read (`program_group.left_behind`, `reader_group.left_behind`, `plugins.program_group` in the recipe's coverage.json); one found makes the answer `partial`. Where the tool cannot become the subreaper (not Linux, prctl refused) or the process table cannot be read (or the tool does not lead its group and nothing else can search), the answer is at most `partial` and says what could not be checked; the sentence that no process was left appears only when the check ran. After that the files are measured again one second later and the holders are looked for. `unified_log` also measures the output again after its sha256. The shared PROCESS block is unchanged; the code is tool-local.
- **The log reader (one text in macos_triage and the recipe).** (a) The finish hint is exempt from the error vocabulary only as the whole message of its own line, with no error word in the prefix; a line that quotes it inside a path or carries other error text is an error. (b) A line is scanned whole up to 1 MiB (it was scanned to byte 4000: a failure word at byte 4500 read `parsed`); a longer line is read to the cap, counted in `long_lines` and makes the answer `partial`. (c) With the log format `time|logger|LEVEL|message` (read from the source through a page summary and never seen in a real run) a start, plugin start, plugin end, exception, finish or no-macOS line is recognised only when its message begins with that text; a line with the text but without the shape is counted (`unanchored_lines`) and not recognised, so two bare lines "Running plugin BASH" and "BASH plugin ran for ..." cannot make a never-run plugin `parsed`, and a line ending "Finished in time = ..." cannot stand for a missing finish line. If the real format differs the run reads as `failed` or `partial`, never as a wrong `complete`; a value of the evidence that carries a line break followed by the whole shape could still forge a line.
- **The log read is on the tool's clock.** It was read whole after the run, outside `max_seconds` (a 400 MB log with `max_seconds` 5 took 103 s; a log of 2.3 GB overran the 7200 s manifest limit). It now gets what is left of `max_seconds` and at least 10 seconds, never past 7050 s (the recipe 14250 s) from the start, and at most 512 MiB; a cut read is `partial` ("the log was not fully read", `log.read_cut`). A stop signal that arrives during the read ends it (the read checks for one at every line); after a stop signal that came before the read, the read is given 5 seconds. A log name that is a FIFO or any non-regular file is never opened blocking: the log is unreadable and the run `partial`.
- **stderr and stdout are read when a log file exists.** The last 64 KiB of each is scanned with the same error vocabulary (the finish hint taken out); a hit makes the answer `partial` (a traceback on stderr with exit 0 and a clean log read `complete`).
- Text: the `macos_tcc` manifest now says that a secret of another shape is printed; `workflow/mac-apt` says that for DD a path that is not a regular file is refused and there is no signature check, and that `mac_apt.py -h` listing plugin names is expected and was never observed (the same hedge in `artifacts/spotlight`).
- Still open (listed, not chased): the shared BOUNDARY gap on random runs of 20 to 31 characters, and the start-up window before the stop handlers. Pack raised: `macos-forensics` 1.9.2 (the recipe 1.0.2). Read, not changed: `keychain_open` runs a shim that imports chainbreaker in its own process and hands it the tool's items file as an inherited descriptor (a child exists only if the library forked, which was not seen), and `apfs_inventory` keeps what it captured from pipes only, so a child that writes after the pipes are let go changes no file the tool reports.
