### Fixed: a self-hosted macOS runner no longer fails every job at its first step

`scripts/macos-runner-setup.sh` installed under `/Library/Application Support/dfirswarm-runner`, and the runner calls the job-started hook by its path without quoting it, so every job on the owner's Mac stopped at `/bin/bash: /Library/Application: No such file or directory` before its checkout (no step of the job ran). The script now installs under `/Library/dfirswarm-runner`, refuses an install directory that holds a space, and `install` on a Mac set up by the first version stops that version's supervisor, moves its stored token to the new directory and removes the old one. `docs/macos-runners.md` says so, and names the fork-approval setting as GitHub's settings page words it today ("Require approval for all external contributors").
