### Fixed: the first-round findings on the new memory tools and leaves (`memory-forensics`)

- **`vol_readiness` read a column Volatility 3 2.28.2 does not have.** `isfinfo` has seven columns, the last `Identifying information` (read from the source of `isfinfo.py` at the pinned version); the tool read "Linux banner" and "Mac banner" and so answered `blocked` on a real listing. It now reads `Identifying information` (decoded text, or the `b'...'` form of a cached table), still reads the two older names, counts as a banner only an identifier that begins "Linux version " or "Darwin Kernel Version", and answers `unknown`, never `blocked`, when the header has none of the three. The tests' stand-in now uses the real layout, with a second stand-in for the older layout and one with no identifier column. The manifest and `symbols/linux` say "Identifying information". Every other claim about Volatility's output was re-read against the 2.28.2 source (the `Plugins` section of `--help`, `hivelist`'s and `printkey`'s columns and options, `banners.Banners`'s decoded text, `windows.info`'s `Symbols` row, `-s`, `-o`, `-q`, `--offline`, exit status 1) and what could not be confirmed is marked UNVERIFIED in the manifests: how the quick renderer prints an unreadable cell, the wording of the engine's log lines, whether `isfinfo`'s cache lists a table in a directory not yet indexed.
- **`mem_registry`:** an unnamed hive (hivelist could not read its path) is taken as credential-class and refused outside a secret-output job; placeholder rows (what `printkey` yields for a key not found or a page not readable) are counted and make the status `partial`.
- **`symbols_dir` takes no semicolon** in `vol_readiness`, `mem_registry` and `vol_views` (Volatility's `-s` reads a semicolon-separated list).
- **`isf_intake`:** "equal" now means equal once the line end and NULs after a banner are taken off and nothing else (a trailing space is a difference). The contradiction with the leaves is removed: the table is the one exception to "never in a job's output", the answer says to copy it to the local symbols directory and remove it from `$OUT` before any report package or thread (`table.remove_before_report`), and `symbols/linux`, `symbols/macos`, `triage/volatility-symbols` and `triage/volatility` say the same. A stand-in `vol` that forks a child and ignores SIGTERM is ended with its child.
- **`triage/volatility-plugins`:** "no exhaustive public cache" is marked UNVERIFIED; the same claim is dropped from `symbols/linux`.
- **Repo-wide tests:** `tests/pack-program-declarations.test.ts` allow-lists `vol` (and the Python module `yara`) for the tools that start it and report its absence as their own answer; `tests/shared-blocks.json` counts the new carriers (PAGE of the memory text 8, general PROCESS 23, SHOWN 7, WITHHOLDING 38); `tests/tool-paging-rerun.test.ts` gains builders for `vol_readiness`, `mem_registry` and `vol_views` (a stand-in `vol` on PATH, per case) and two entries for `carve_handoff` and `isf_intake`, which write no paging file.
