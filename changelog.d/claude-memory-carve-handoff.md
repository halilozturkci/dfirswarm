### Added: `carve_handoff`, a carved hit made ready for the parser that reads it (`memory-forensics`)

- **`carve_handoff`** takes one hit of `mem_carve` (`path`, `kind`, `signature_offset`) and readies it without parsing it. It checks that the signature is at the offset, then gives the structure's start (a plain Prefetch record four bytes before `SCCA`, and only when those four bytes are a known version; a caller's `object_offset` is compared and never taken), the cut by `mem_carve`'s own rule (`declared_bytes`, `requested_bytes`, `available_bytes`, `cut_complete`; the signatures, caps and header checks are copied from `mem_carve`, and a test holds the two equal on one image, field for field), `validation` (header plausible or implausible, truncated when the file itself ends first, unknown), and checks a slice can fail: a registry hive's base-block checksum, its sequence numbers (unequal: the hive was written to while it was copied) and its chain of bins; an event log file's chunks, each of which must start with `ElfChnk`; an event log chunk's header CRC-32. A break in a chain is reported as fragmentation, the place where the structure's pages stop being adjacent in the image. A family with no such check says "not checkable", which is not "intact".
- **The slice.** Its sha256 is reported only for a family that cannot be a credential store; a registry hive, a SQLite database and a binary property list can be one, so their slice is never hashed (the digest of a secret is itself a secret-shaped output). Slice bytes are written only with `write_values` in a job run as secret output, to `$OUT/carve_handoff` (directory 0700, file 0600, created exclusively under a hidden name and placed without replacing an earlier file); the manifest declares `secret_output` for `write_values`, and the tool refuses as JSON, before it opens the image, outside a job or in one that is not secret output. The windows-forensics tools that read the family are named (`regkv`, `evtx_carve`, `mam_scan`, `prefetch_mam`), never called, and no dependency on that pack is added; a result of one passed as `parser` and `parser_result` is referenced by path and size and not read.
- **Bounds.** The clock (`max_seconds`, default 120, at most 270) is looked at before every 1 MiB block of the hash and the copy and every 256th bin or 64th chunk of a walk; `examine_bytes` bounds a walk; a walk, hash or copy that either ends says so (status `partial`) and gives no digest. A FIFO, a device or a directory is refused with fstat after an open that does not wait. SIGTERM, SIGINT and SIGHUP give one document (status `failed`, `interrupted` true) naming a slice file that was being written under a name ending in `.partial`.
- **Shared blocks copied byte for byte:** WITHHOLDING, SHOWN and PAGE; the tool runs no program, so it has no PROCESS block.
- Tests: `tests/pack-memory-carve-handoff.test.ts` builds Prefetch, hive, event log, SQLite and PE structures from their layouts (checksums and digests computed by the test), covers the start rule, truncated hits, a broken chain, the credential families, the refusals, the downstream reference, hostile parameters and a signal in the middle of a copy, and holds the tool equal to `mem_carve`; the carrier lists of `tests/pack-memory-shared.test.ts` and `tests/pack-memory-f2-shared.test.ts` follow. Each fails on the base, where the tool is missing.
