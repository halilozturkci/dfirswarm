### Fixed: a stop at the end of a memory tool no longer leaves a hidden temporary name in the answer, a second document or a file nobody names

`mem_carve`'s SIGTERM test failed on three of four tries on the macOS runner. The tool writes its hit list to a hidden temporary file, moves it onto its final name when the sweep ends, and only then forgets the temporary name. A stop that landed between the move and the forgetting was handled as an interrupted sweep: the tool tried to keep the temporary file under a `.partial` name, the file was no longer there, and the answer named the hidden temporary path (which did not exist any more) as the partial hit list, with an empty `.partial` file beside the real hit list that nobody named. Other stops in the same few lines left an empty file under the final name, or a complete answer followed by an interrupted one on the same stdout (two documents), or a hit list under its final name that the answer called partial and did not name. A stop that arrived while the module was still loading, before the tool's handler was installed, killed it with no answer at all.

`mem_carve` now holds a stop from the moment the hidden file is created until the sweep's own checkpoint, and again from the end of the sweep until the answer is out: the file is then always removed, kept under a visible `.partial` name, or under its final name, and a stop that arrives after the sweep has ended changes nothing (the answer is the complete one, `signal_after_sweep` says a stop came, and the exit status is 0). The answer is printed once, whole, and a later stop is ignored. A kept file is never named by its hidden name; when the directory will not take a visible name for it, `partial_results` is null and says so. A small handler installed before the module's imports answers a stop that arrives while the tool is still loading (`interrupted`, nothing was read or written).

`mem_fs` and `mem_profile` share the paging code and had the same windows, which a stop delivered at each point of the ending reproduced (the tests below fail on the tools as they were): the answer printed twice, an empty or half-placed file, a finished list of rows that no answer named (`mem_fs` placed it on a stop and called the run interrupted without naming it; `mem_profile` left the finished list of LiME ranges when a stop came during its sampling and said that no file was left), a hidden file whose name nothing knew. The paging object now knows its temporary name before the file exists, places the finished file under a held stop, and keeps a stopped one under a visible name; `mem_fs` names the rows already kept (`partial_results`) and `mem_profile` names a finished range list (`kept_results`).

The SIGTERM test of `mem_carve` no longer sleeps: it sends the signal when the tool's hidden file holds its first rows, on an image whose sweep cannot end first (a megabyte of hits and 64 GiB of nothing). A new suite delivers SIGTERM at each point of the ending of the three tools with `tests/memory-signal-inject.py`. Pack memory-forensics.
