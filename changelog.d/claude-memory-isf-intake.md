### Added: `isf_intake`, an operator-supplied kernel's ISF validated by exact match (`memory-forensics`); `dwarf2json` 0.9.0 pinned for amd64

- **`isf_intake`** takes the image, the operator's kernel file (`kind` `elf`: a vmlinux or debug-symbols file; `system_map`: a System.map) and the release it is for (`build_identity`), finds the image's Linux banners with `vol --offline -q -f IMAGE banners.Banners`, runs `dwarf2json` (version and argv recorded in the answer) and says `ready` only if the table's own `linux_banner` constant is, character for character, a banner found in the image and begins with the build identity. A near release, another compiler, another kernel's table or a System.map (no banner) is `blocked`, and the table is removed, not left where Volatility could load it. An image with no banner, or none for the identity, ends the call before anything is converted. A ready table is placed without replacing an earlier file as `isf_intake-<digest>.json` in `symbols_out` (mode 0600 in a 0700 directory) with its size and sha256; it is local-only like every symbol table, with one exception to "never in a job's output": the tool contract has a job write only under `$OUT`, so a ready table is there, and the person copies it to the local symbols directory and removes it from `$OUT` before any report package or thread (the answer names the file).
- **Promises no more than the match.** `ready` is not a claim that the examination will work, that the running kernel is that banner's (the answer counts the image's banners), or that any Linux or macOS version is supported; macOS is not handled. `skills/triage/volatility-plugins.md` no longer says the pack has no converter: it names the tool and its exact-match rule.
- **Bounds.** The converter's output is read as it streams (counted, hashed, searched for the banner without holding the table) and the converter is ended at its time or at 4 GiB; a debug file over 8 GiB is refused before anything runs; the converter runs in the tool's own process group; SIGTERM, SIGINT and SIGHUP give one document (`failed`, `interrupted` true) and remove the table being written. Shared blocks copied byte for byte: WITHHOLDING, SHOWN, PAGE and the general PROCESS block.
- **`dwarf2json` declared.** `requires/host.json` pins the project's v0.9.0 Linux amd64 release asset by sha256 (a download, installed under the name `dwarf2json`), with the licence label from the release's own LICENSE.txt (Volatility Software License 1.0; GitHub's metadata reports no SPDX licence) and `redistributable: false`. The project publishes no Linux arm64 asset and its source build needs a Go module fetch, so no build recipe is used: an arm64 image records the program as not installed, and the tool fails with verdict `blocked` wherever `dwarf2json` is not on PATH, and says so.
- **Not run:** against the real `dwarf2json` or Volatility; the tests use stand-ins that follow their documented output (the one real run is skipped, and says why).
- Tests: `tests/pack-memory-isf-intake.test.ts` (an exact match with the table found behind more than a block of other symbols, a near miss, another release, a System.map, an image with no banner or none for the identity, a converter that fails, a missing converter or `vol`, a hang and one that ignores SIGTERM, the output cap, a debug file over the limit, SIGTERM, hostile parameters, canaries in banners and paths) and the carrier lists of `tests/pack-memory-shared.test.ts` and `tests/pack-memory-f2-shared.test.ts`. Each fails on the base, where the tool is missing.
