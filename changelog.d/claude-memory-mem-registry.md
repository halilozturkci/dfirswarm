### Added: `mem_registry`, the registry hive inventory and selected non-secret records through Volatility (`memory-forensics`)

- **`mem_registry`** (opt-in; the base `memory-windows` recipe is unchanged) runs `windows.registry.hivelist` and `windows.registry.printkey` of the installed Volatility, offline, the plugin names taken from `vol --offline --help` (a plugin it does not list is a refusal). Mode `hivelist` gives one record per hive (offset, the path the hive names itself by, whether it is a credential-class hive); mode `printkey` (a hive's `offset`, a `key`, `recurse`) gives one record per subkey and value. Every record carries the hive offset, the plugin and the Volatility version; the answer carries a coverage of hives found against hives named and read, and the status is `partial` when the engine's log says pages were missing, when a hive had no readable name, or when a limit, the clock or an output cap ended the read. Records are paged: `limit` in the answer, all of them in a file the answer names; `max_records` ends the read (and the program) and says so.
- **What is not printed.** SAM and SECURITY hives and keys under SAM, SECURITY, `Policy\Secrets` and `SAM\Domains` are refused before they are read and before anything is written, unless `write_values` is true in a job run as secret output; the value of a record whose key path or value name carries a credential word is withheld whole with its length, by name and not by content; a binary value is not printed. `write_values` writes the withheld values, unjudged, to a 0600 file in a 0700 directory under `$OUT/mem_registry`, placed without replacing an earlier file; the manifest declares `secret_output` for it, and the tool refuses as JSON, before it looks at the image, outside a job or in one that is not secret output. Key names and values pass the shared SHOWN rules (withholding is by shape: a plain password is printed under an innocent name).
- **Shared blocks copied byte for byte:** WITHHOLDING, SHOWN and PAGE of the memory lineage and the general PROCESS block; the programs run in the tool's own process group and are ended at their time, at their output cap, or by SIGTERM, SIGINT and SIGHUP (status `failed`, `interrupted` true, the files being written kept under a name ending in `.partial`).
- **Not run:** against the real Volatility. The tests' hivelist and printkey outputs are written by hand to the columns Volatility 3's quick renderer documents, not recorded from the pinned 2.28.2, and the phrases that mean "pages were missing" in the engine's log are a guess; a first real run on a small Windows image with its table is the check (the test that would do it is skipped, and says why).
- Tests: `tests/pack-memory-registry.test.ts` (the inventory and its coverage, a plugin not listed, records with canaries in key names and values, credential-named values withheld, SAM and SECURITY refused in each way and written nowhere, the values file in a secret job and a second run, a missing page, `max_records`, a hang, SIGTERM at a program that ignores it, hostile parameters) and the carrier lists of `tests/pack-memory-shared.test.ts` and `tests/pack-memory-f2-shared.test.ts`. Each fails on the base, where the tool is missing.
