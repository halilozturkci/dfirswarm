### Added: three memory skills that name the new tools (`memory-forensics`)

- **Three leaves.** `triage/memprocfs` (what a MemProcFS mount needs: the pinned 5.18.11 and its libraries, a `/dev/fuse` and a `fusermount` helper that the image build does not install, the `no_fuse` answer and `vol_readiness`'s `fuse` view; no flag about symbols, caches or forensic mode is passed; readiness is not completion; a failed clean-up can leave the mount), `symbols/linux` (the image's banner and architecture, matching debug material, `isf_intake` and its exact-banner rule, validation; it says the pack does not yet declare `dwarf2json`) and `artifacts/reconstruction` (a signature hit against a contiguous slice against a reconstructed virtual file against a validated record; `carve_handoff`'s start, cut and adjacency checks; the windows-forensics parsers named conditionally). Each opens "Use when ... Not for ...", carries Shows, Does not show, Record and Sensitive output, and points to the leaves that hold a rule instead of repeating it. No existing sentence moved.
- **The router names each once;** the pack is 28 skills, and the README and the counts say so.
- Tests: `tests/pack-memory-skills.test.ts` holds the three to the same rules as the five of the first half and checks that every tool field a leaf names is written by its tool; each fails on the base (the leaves are missing).
