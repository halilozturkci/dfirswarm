### Changed: network-forensics: the QUIC skill says what Zeek and Suricata wrote for synthetic QUIC, and the manifest says what the alignment check covers

- **What Zeek and Suricata write for QUIC was observed, once, in one run, on synthetic traffic (not a real capture).** In one throwaway container (the repository's dfirswarm base image, Debian 12) Zeek 8.0.11 (the pinned amd64 release asset, its sha256 checked against `requires/host.json`) and Suricata 7.0.10 (apt, bookworm-backports; the default `/etc/suricata/suricata.yaml` of that package, no rules, QUIC app-layer enabled; the JA3 setting of that file was not recorded, and Suricata normally computes JA3 only when it is enabled or a rule asks for it) read 13 QUIC captures built for the purpose from RFC 9000, RFC 9001 and RFC 9369: a v1 and a v2 handshake with a TLS ClientHello carrying an SNI and ALPN `h3`, a Retry, a Version Negotiation, coalesced packets, a ClientHello split over two Initials, and Initials that cannot be decrypted. `sessions/quic-http3` item 7 says what was seen: Zeek `quic.log` carries the version (`1`, `quicv2`, `unknown-<hex>`), the first destination id, both source ids, the SNI, the first ALPN and a history; Suricata's `quic` events carry the version, `sni`, `ja3`, `ja3s` and the extensions, and no connection ids; an Initial that does not decrypt, a Retry and a Version Negotiation show little or nothing in either. Zeek also wrote `ssl.log` rows in this run: with version and cipher when both hellos decrypted, without them for a client Initial alone, a Retry alone or an undecryptable server Initial, and none for an undecryptable, truncated or reserved-version Initial. So `ssl.log` neither lists QUIC nor shows its absence; the earlier sentence that it holds no QUIC was wrong for Zeek. **Not checked:** real captures, other Zeek or Suricata versions or configurations, Google QUIC (gQUIC), IPv6, arm64 (only amd64 was run). **Not reproducible from the repository:** the traffic builder is not in it (the repository's QUIC tests hold only a tshark stand-in), so these observations cannot be repeated from the repository. **Recorded by the implementer, not independently verified:** the key derivation of the builder matched the RFC 9001 test vectors, and the container had no network after the install.
- **A disclosed limit of the alignment check.** `quic_inspect` checks the lists of connection ids, versions and source ids against the packets of a datagram, not the packet type, token or frame lists; a shift in those is not flagged. The manifest and the skill say so.
