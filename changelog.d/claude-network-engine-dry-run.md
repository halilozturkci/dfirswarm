### Added: network-forensics: `suricata_run` and `zeek_run` take `dry_run: true`, the engine receipt without a capture

- **A mode, not a tool.** `dry_run: true` (a boolean, default false) on `suricata_run` (v11) and `zeek_run` (v12) gives a receipt of what a run would use, and reads no capture. `path` is refused as JSON with it. The tool writes only under `out_dir`, opens no socket and names no capture or interface to the engine; the answer is one document (`status`, `status_basis`, `dry_run: true`) with five parts: `identities`, `effective_configuration`, the rule-load or script-load status, `log_outputs` and `not_covered`.
- **`suricata_run`.** Identities are the rules file's SHA-256, size and rule lines, and its rules read as text: counts per action with the commented-out rules counted apart, the sid ranges (the first 100 inline, every one in `sid-ranges.txt`, 0600), duplicate sids and the `rev` values. A rule longer than 1 MiB is located by line number and not read, and makes the receipt partial. The effective configuration is the `-T` test and `suricata --dump-config` where the build's help lists it; a build without it is named and is not a failure. The rule-load status is the loaded, failed and skipped numbers the engine printed (None is not zero) and the first ten failure lines, each passed through the withholding block whole and then cut.
- **`zeek_run`.** Zeek is started once with the policy script and a small script of the tool's own that prints each script Zeek loads (`zeek_script_loaded`), with no capture and no interface. The receipt has the policy script's SHA-256 and size (the bytes a run writes for the same policies), `zeek --version`, `zeek --help`, the scripts Zeek listed, and for each requested policy whether it was listed. A Zeek that exits 0 and lists nothing is partial, never an empty complete receipt. The log streams a run would write are not listed: they depend on traffic.
- **Not covered, said in every receipt.** No ruleset ships with the pack and none is fetched; there is no automatic download and no `suricata-update`; no capture was read, so nothing says what would match or be logged.
- Why a mode and not a tool: the owner decided on 2026-10-29 that the receipt is a `dry_run` mode of the two engine tools and no standalone tool.
- Real Suricata and Zeek were not available where this was built: the tests use stand-in programs that print what the documentation says, so the stand-ins prove the wrapper and nothing about a real build's `--help`, `--dump-config` or `zeek_script_loaded`; the receipt names what a build lacks.
- Pack raised: `network-forensics` (minor).
- Tests: `tests/pack-network-suricata-run.test.ts` and `tests/pack-network-zeek-run.test.ts` (dry-run cases: no capture and a refused `path`, writes only under `out_dir`, every receipt field, a build without `--dump-config`, failed loads, a 10 MB rule and a NUL, 5,000 sid ranges, 200,000 continuation lines, a refused write of the range file, a stop signal); each fails on the code before this change.
