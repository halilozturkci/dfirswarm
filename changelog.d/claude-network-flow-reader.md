### Added: network-forensics: `flow_reader`, NetFlow v5, v9 and IPFIX records from an nfcapd file, over nfdump

- **A reader over `nfdump`**, for an nfcapd file (the records nfdump's collector stored from NetFlow v5, NetFlow v9 or IPFIX packets). It runs `nfdump -V`, `-v`, `-I`, `-E` and `-o json` and nothing else: it never runs `nfcapd` or `nfpcapd`, and nothing listens on a port. `declared_format` (`netflow_v5`, `netflow_v9`, `ipfix`, `sflow`, `nfcapd`) is required; for the three export protocols the exporters the file lists must all be of that protocol, or the file is partial.
- **Refused by name, before any program runs:** a capture (pcap or pcapng: no mode of the pinned nfdump turns the export packets inside a capture into records, and `nfpcapd` would build new flows from the packets), sFlow (the Debian package ships `nfcapd` and `nfpcapd`; its `nfcapd` counts an sFlow datagram as a bad packet and `sfcapd` is not installed) and any file without the nfcapd magic.
- **What an answer says.** Per file: size and SHA-256, nfdump's verification, its statistics (flows, packets and bytes, first and last second, sequence failures, the ident string) and the exporters it lists (the address the collector saw, the protocol, the observation domain or source id, the engine for NetFlow v5, announced samplers). Per record: the source file and its position in nfdump's output, the parser, times in UTC (nfdump runs with `TZ=UTC`) with the raw text and an epoch in milliseconds beside the collector's receive time, protocol, addresses, ports, TCP flags, counters, direction, the translated (post-NAT) fields, interfaces and every other field nfdump printed. Rows are paged (`limit` inline, the whole in `all_results`, placed without replacing an earlier file); nfdump's own messages are kept beside it.
- **Sampled counters are never exact.** A record nfdump flagged sampled has `counters_exact: false`; a record that is not flagged has `counters_exact: null`, because nfdump flags only the sampling it understood. The totals keep the two apart.
- **Said in every answer as not provided:** template ids and templates, the exporter's active and inactive timeouts, whether a record is one direction or both, a byte offset of a record, and the export packets.
- **nfdump's exit code is not trusted.** The pinned nfdump exits 0 for a truncated file and for a file that is not a flow file, with the error on stderr (checked on 1.7.1). `-v`, `-I`, `-E` and `-o json` are all run; a message on stderr, an output line the parsers do not know, a nonzero exit, and a record count that differs from the file's own flow count make the file partial, or failed when no record was read. A file changed inside a record that still decodes is not detected (the SHA-256 is given).
- **Bounds.** `max_records` (default 100000, at most 500000) bounds one file; a file with more is read to the bound and the answer is partial. `max_seconds` (default 900, at most 1000) is one clock over hashing, every nfdump run and the parsing, below the manifest's 1200; a program still running at the end is killed with everything it started. SIGTERM, SIGINT and SIGHUP end the tool with partial JSON and exit 128 plus the signal. Measured on a NetFlow v5 file of 120,000 records read with `max_records` 500000 (nfdump 1.7.1, Python 3.11, one container): 25 s, 24 MB at most for the tool and nfdump each, a 160 MB result file.
- **Shared blocks.** The tool carries PROCESS (the general text), PLACE, PAGE and STOP (the windows text), copied byte for byte; the STOP block comes first.
- **Skills and docs.** `flows/interpret` names the tool and the program and no longer says that no flow reader is provided; `capture/what-you-have`, the pack's description and its README follow. `requires/host.json` lists `nfdump` (the Debian package, installed at the image's apt snapshot date; 1.7.1 on Debian 12) with its `-V` as a recorded fact.
- Pack raised: `network-forensics` (minor).
- Tests: `tests/pack-network-flow-reader.test.ts` (the five supported forms, refusals, arguments, truncated files that nfdump reports with exit 0, a flow count that disagrees, a declared protocol that does not match, hostile output, paging and reruns, a job's places, the exact calls made, no socket held, the tool's own clock, four runs at once, three stop signals, a fuzz of 160 cases, the manifest); each fails on the code before the change. The stand-in `nfdump` replays what a real nfdump 1.7.1 printed for files collected from export packets built from the protocol specifications (`tests/network-flow-fixture.py`); one test runs the real program when it is installed and is skipped, with its reason, when it is not.
