### Added: network-forensics: `quic_inspect`, a connection-aware table of the QUIC datagrams of a capture over tshark

- **A tool over `tshark`** that lists every UDP datagram tshark dissects as QUIC, in capture order: frame, interface, time (raw epoch and UTC), UDP endpoints, and for each QUIC packet in it the header form, the packet type (RFC 9000 table for v1, RFC 9369 table for version `0x6b3343cf`, `version_negotiation` for version 0), the version, the destination and source connection ids and whether an Initial carried a token; the SNI and ALPN, frame types and HTTP/3 stream ids where tshark decoded the packet. Each row has its limits: `encrypted_payload`, `version_unsupported`, `dissector_missing`, `fields_not_aligned`. The whole table is a JSON Lines file (mode 0600, never replaced by a smaller rerun); the answer pages it.
- **A connection model that keeps tuples and connection ids apart.** An attempt is the set of connection ids joined by long headers; a Retry or a Version Negotiation packet ends one and the Initial that follows starts another (`follows_attempt` for the Retry link); a change of UDP endpoint within an attempt is reported as migration or a NAT rebinding; a short-header packet whose connection id no long header named is an unlinked attempt and says so. The model is bounded; a bound passed makes the answer partial.
- **Not inferred from other logs.** UDP port 443 datagrams that tshark did not dissect as QUIC are counted (`udp_443_not_dissected_as_quic`); nothing is read from `ssl.log`, so an absent row is never a finding.
- **Secrets as `tls_decrypt` takes them:** a key log FILE (never its text; text that looks like a key log is refused unechoed) and/or a pcapng's Decryption Secrets Blocks. The manifest declares `secret_output: "required"`; inline connection ids and server names go through the withholding rules, the file holds them as they are. Canaries of every key log label were searched for everywhere.
- **tshark is checked, not assumed:** `tshark --version` is recorded, `tshark -G fields` is read for each field the tool relies on, and a build without the core QUIC fields is refused by name (`dissector_missing`). **Not verified here:** tshark was not available, so the suite runs a stand-in that prints tshark's documented output; the meaning of the field values and the alignment of aggregated lists for coalesced packets were not checked against a real build, and the manifest says so. One test runs the real tshark when installed and is skipped, with its reason, when not.
- **Bounds.** The listing is read as a stream and cut at 2 GiB; connection ids, attempts (100000) and tuples are bounded; the tool's own clock (`max_seconds`, default 900, at most 1000) is below the manifest's 1200; SIGTERM, SIGINT and SIGHUP end it with partial JSON and exit 128 plus the signal.
- **Shared blocks.** WITHHOLDING (from `zeek_run`), PROCESS, PLACE, PAGE and STOP, copied byte for byte.
- **`metadata/dns-tls`** names the tool and no longer says the pack has no QUIC method.
- Pack raised: `network-forensics` (minor).
- Tests: `tests/pack-network-quic-inspect.test.ts`: the table, coalesced packets, v2, Retry, Version Negotiation, migration, unlinked short headers, paging, refusals, key log canaries, hostile lines and fields, 150000 attempts, four simultaneous runs, the clock, three stop signals, a fuzz of 300 listings and the manifest.
