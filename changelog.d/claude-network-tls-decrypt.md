### Added: network-forensics: `tls_decrypt`, authorised offline TLS decryption over tshark

- **A tool over `tshark`** that says which sessions of a capture the supplied secrets decrypt. Inputs: a capture (pcap or pcapng), a key log given as a FILE reference (`keylog_file`, a job input) and/or the Decryption Secrets Blocks of a pcapng (`use_embedded_secrets`), and a scope (`host`, `port`, `stream`, `display_filter`). A key log passed as text is refused without being echoed. The manifest declares `secret_output: "required"`: the decrypted bytes go only to files (mode 0600) under `out_dir`, one per flow and direction, placed without replacing an earlier file; `write_payload: false` gives the statuses alone, and `write_payload` outside a secret-output job is refused before anything is read.
- **A status for every TCP flow:** `decrypted`, `partially`, `unsupported` (ECH, a key log line that did not decrypt the session, only the handshake secrets of a TLS 1.3 session, no application data), `no_secret_for_session` (a forward-secret session with no line, or no ClientHello in the capture to match: a resumed or mid-flow session) or `not_tls`, each with its reason, frame range, endpoints, counts, the application protocol tshark named and the TLS version where the hellos show it. The tool reads the key log itself and keeps only each line's client random and label kind, in memory, to tell "no line for this session" from "a line that did not decrypt".
- **The answer is locators.** Stream ids, frame ranges, counts, protocol names, byte lengths, and counts of key log lines and Decryption Secrets Blocks by kind. It never carries decrypted data, a key log line, a fragment, a client random or a digest of one; a key log path that looks like a token is withheld, and tshark's messages have the path replaced and are scrubbed. Canaries of every key log label were searched for in the answer, the arguments of the tool and of the stand-in tshark it ran, file names and every result file.
- **tshark is checked, not assumed.** The tool records `tshark --version`, reads `tshark -G currentprefs` for `tls.keylog_file` (or `ssl.keylog_file` in an older build) and refuses as JSON if neither exists, and reads `tshark -G fields` for each field it relies on; a build without them is refused by name. A pcapng with Decryption Secrets Blocks is decrypted without `-o`, and the answer names the source by counts.
- **Not verified here:** tshark was not available, so the suite runs a stand-in that prints tshark's documented output; the tool relies on `tls.app_data_proto` as the sign of a decrypted frame (data in a protocol tshark has no dissector for shows no sign of decryption) and on the output of `-z follow,tls,raw,N`, and the manifest says so. One test runs the real tshark when it is installed and is skipped, with its reason, when it is not.
- **Bounds.** The listing is read as a stream and cut at 2 GiB, flows past 100000 are counted not tracked, a payload direction is cut at 256 MiB and said to be cut, `max_payload_streams` (default 20, at most 200) bounds the extraction passes, and a cut or skipped flow makes the answer `partial`. The tool's own clock (`max_seconds`, default 900, at most 1000) is below the manifest's 1200; SIGTERM, SIGINT and SIGHUP end it with partial JSON and exit 128 plus the signal.
- **Shared blocks.** The tool carries WITHHOLDING (from `zeek_run`), PROCESS (the general text), PLACE, PAGE and STOP (the windows text), copied byte for byte.
- **`sessions/reconstruct`** names the tool and no longer says the pack carries no decryption method.
- Pack raised: `network-forensics` (minor).
- Tests: `tests/pack-network-tls-decrypt.test.ts`, with real TLS bytes from `tests/network-tls-fixture.py` (a TLS 1.2 and a TLS 1.3 session between two Python `ssl` contexts over `ssl.MemoryBIO`, with `keylog_filename`), wrapped in TCP segments in a pcap and a pcapng with a Decryption Secrets Block: the statuses, a missing session, a wrong key log and a handshake-only key log, the older preference name, refusals, key log canaries, payload bytes and modes, an existing payload file, hostile captures and key logs, 20000 flows, the tool's own clock, three stop signals at two moments, a fuzz of 120 key logs and the manifest; each fails on the code before the change.
