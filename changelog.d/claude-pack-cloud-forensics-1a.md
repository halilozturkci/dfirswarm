### Security: the cloud pack's tools withhold what is named or shaped like a credential, and write a value only to a sealed file in a job

`cloudtrail_parse` copied every event's `requestParameters` into its rows; `ual_parse` copied the Exchange parameters and the modified properties; both, and `signin_analyse`, printed every path and error message as it was and returned the whole result inline when no `out_file` was given. A request, a response, a parameter or a property can hold a password, a session token, a client secret or a key, and the answer is recorded in the trace and quoted into reports. All three tools now follow the secret-safe output pattern of `recovery_key_scan` (docs/packs.md, "Secrets and sensitive output"): a field whose name says it is a credential (password, secret, token, `secretAccessKey`, `sessionToken`, an Exchange parameter or a modified property named so), and any text shaped like one (a JSON Web Token, a private key block, a value assigned to a credential name, the common token families, a long random-looking base64 run), is replaced in every channel (a row, the raw record, a printed path, an error message, every file the answer names) by a marker that holds only its length. The original goes to `cloudtrail-values.jsonl`, `ual-values.jsonl` or `signin-values.jsonl` under `$OUT` (mode 0600, created first, a file or link already there refused by name) only when `write_values: true` is asked, only when the tool runs as a job (its manifest says to run it with `secret_output: true`; the skills follow); outside a job the request is refused and nothing is written. A name and a shape recognise some secrets and never all, so each answer says so (`sensitive_output`) and every manifest says the tool is sensitive. The three tools carry one identical block of this code, and `tests/pack-cloud-shared.test.ts` holds the copies equal and holds all three to withholding the same strings, in a path and in an error message as well as in a row.

### Fixed: the cloud pack's tools stop returning plausible wrong answers

- **`cloudtrail_parse`** linked an assumed-role session to the latest AssumeRole request whose role name and session name matched, failed requests included, so a failed attempt by someone else was reported as the session's origin; it rebuilt the role ARN as `arn:aws:iam::...` (no other partition) and dropped the role's path. A session is now linked only to a successful AssumeRole-family call, by the access key id the call returned, else the session ARN it returned (or, with no response, the ARN derived from the request in the request's own partition without the role path), narrowed by the session's creationDate, and never to a call logged after the use. The link is a `session_origin` with its basis and source event: a candidate, `unresolved` when several distinct calls match (the matching calls are listed up to a cap, with their count, and none is chosen), or `not_found`; `role_assumed_by` and `assume_role_event_id`, which read as attribution, are gone. A line of JSON Lines that did not parse was skipped without a word and a file that failed was counted without a name; an `errorCode` of any kind was a refusal; `accessKeyId`, `sourceIdentity`, `responseElements`, `additionalEventData` (so `MFAUsed`), `sharedEventID` and `recipientAccountId` were dropped; `StopLogging` was "the gap that follows is the finding" and the note called a high refusal count "the shape of permission enumeration"; the whole export was held in memory; subdirectories were read in directory order. It now reads each file as a bounded stream (a Records file, a bare array, one event, JSON Lines, a `lookup-events` page through its `CloudTrailEvent` text, any of them gzip), keeps the identity, request, response and additional data, names every file with its status, counts and locates (file, record, line) every record it did not read as an event and every file it did not read to its end (a gzip that ends early, expansion past `max_expanded_bytes`, a response that names a next page, files not reached before `time_limit_seconds`), and says `status` partial rather than complete. A digest file is named in `digest_files` and read as no events; the tool says plainly that it validates neither the digest files nor the log files' integrity (and a digest file next to complete logs does not make the read partial). Error codes are classified by name and only authorisation denials are refusals; a failed console login is an error too. The flagged API names say what the call is, not what happened.
- **`ual_parse`** flattened only the nested `AuditData`, so a native audit event (`Operation`, `UserId`, `Id`, `CreationTime` at the top) became a file name, a time and a record type; reduced `ExtendedProperties` to `NewValue`/`OldValue`, so an entry written `Name`/`Value` lost its value and `MailAccessType` was never kept; collapsed duplicate parameter names; tried `%m/%d/%Y` before `%d/%m/%Y`, so `03/04/2026` was March 4; gave every time with no zone a UTC; stopped the whole run with a traceback on an `AuditData` over the csv module's 128 KiB field limit; had no `record_type` filter although the skill told the agent to filter by `RecordType`; and computed its tables before its filters. It reads wrapper rows, native events, a value envelope and a Graph record, keeps the whole payload as `audit_data` (Name/Value, NewValue/OldValue and duplicates as written) beside the fields lifted out of it, filters by `record_type`, reads a time only as it was written (a time with no zone is undecoded unless `assume_utc`, a day/month/year string needs `date_order` or unambiguous rows in the same file that prove one, and the answer says which), counts failed files, rejected rows and unreadable payloads separately, describes the matched records in its tables and the whole export in `operations_all_rows`, and, where a header is one column holding a semicolon, a tab or a bar, stops and names the delimiter it may use instead of reading one column of garbage.
- **`signin_analyse`** dropped the event id, the correlation id, the authentication details and the applied conditional access policies (the fields its own skill uses to judge a single-factor success); read a `.jsonl` file as CSV and returned no events; counted `Interrupted` as a failure; gave every time with no zone a UTC; called any three failures before a success a burst however far apart; grouped every record with no user as one account; described `50158` as a conditional access failure; and held the whole export in memory. It reads the format from the content, keeps every field the leads need with the raw record and a locator (file, record, line, nested event), makes `success` true, false or null, refuses a time with no zone unless `assume_utc` says so (recording the assumption) and a day/month/year string with no declared or proved order, finds bursts per account and application within `burst_window_seconds` (default an hour), keeps events with no user out of the account analysis and counts them, glosses a result code as a convenience and keeps the provider's `failure_reason` as written, analyses one account at a time from a database on disk, and pages every list of leads past `limit` into a file it names. A response that names a next page is partial; its token is not printed.
- **All three** wrote a result with `open(..., "w")`, so a rerun with a smaller filter replaced a larger earlier file, and their manifest examples wrote to `work/<file>`, which a job's read-only run directory cannot take. An `out_file` is now written to a temporary file and published without replacing what is there (the earlier file is kept and the new one named beside it, the same bytes again being the file already there); in a job it must be under `$OUT`, with a JSON error that says how to name one; without it the whole result is paged into `$OUT/tool-output` (an agent's own `work/<id>/tool-output` outside a job) under a random name. A refused or failed run leaves no half-written result file. An answer is ASCII-escaped, so a lone surrogate or a name that is not UTF-8 cannot raise; a lone surrogate or a time outside the range a 64-bit count of nanoseconds holds is handled, not fatal; non-object or wrongly typed arguments are a JSON error. A UTF-16 export (PowerShell's `Export-Csv -Encoding Unicode`) is read by its byte order mark, where it was a file of replacement characters, and bytes that do not decode are replaced, counted, and make the read partial. Directories are read in a stable order (the files of a directory, then its subdirectories, each by name); a link and a special file are named and not opened.

### Changed: the cloud pack's tool manifests say what each tool reads, measures and does not

Each manifest states what its tool reads (by name hints: a bare `.json` or `.csv` would offer it for every such file), that its answers carry `status` and `status_basis`, what is not measured, that it can reach secrets and how, declares every argument the script reads, and carries its raised version and the sha256 of its script. New suites (`tests/pack-cloud-*.test.ts`) build their fixtures from the formats' own layouts (CloudTrail's record, Microsoft Graph's signIn, the audit schema's native event and the portal's CSV, the Reports API's activity) and fail on the old tools. ### Security: the withholding covers the formats a cloud log really holds, a filter cannot be used to read a withheld value, and no pattern can hang a tool

The first version printed `aws_secret_access_key` and `AccountKey=` connection strings in clear, and answered a `user` or `identity` filter by testing the raw value of a field that it then withheld from the row: a caller could read a withheld value one bit per call. The shared block now recognises a credential by more name stems (`secretAccessKey`, `AccountKey`, `SharedAccessKey`, `SecretText`, `keyValue`, `tokenCode`, `mfaCode`, `plaintext`, `db_pass`, `Ocp-Apim-Subscription-Key`, cookies and authorization headers, with no prefix guard) and by shape (an AWS secret access key, a Base64 key of 32, 40, 43 or 86 characters, a SAS `sig`, a presigned `X-Amz-Signature` and `X-Amz-Security-Token`, an ESTS cookie, a Basic or Bearer value of any length, a private key block with or without its header, the `Q~` client secret, the Google and GitHub token families). One test per format, run through all three tools, looks for any eight consecutive characters of the secret in the answer, every file the answer names and standard error; a second test keeps what is evidence and only looks like a secret (an access key id, a Secrets Manager ARN, a KMS key ARN, a GUID, a hash, a `clientToken`). A filter (`identity`, `user`, `events`, `operations`, `record_type`) is matched against the text as it is printed, never against a withheld original; a pattern is limited to 200 characters, one that can take exponential time is refused before it is compiled, and every test of a pattern against a value is timed (a quarter of a second) and fails the call, named, instead of hanging it. An argument a tool does not have is refused by name. SIGTERM, which a job's `timeout` sends first, removes every temporary result and index and exits 143; an `out_file` of a read that ended early is published as `<name>.partial<ext>`, never under the requested name.

### Fixed: cloudtrail_parse, ual_parse and signin_analyse after the review of the first version

- **`cloudtrail_parse`** treated one call as several: the same `eventID` in two exports, or a cross-account call logged in two accounts (two `eventID`s, one `sharedEventID`), made a session `unresolved`. Copies of one call now count as one; a call that returned a different access key id is disproved as the source of a session that carries another; the filters and the count run in the session index, so a limit applies only to the calls listed (sixty calls for one session ARN are sixty, and the creationDate picks the one at its time wherever it sits). A gzip that ends early keeps every record before the break (a small file used to lose all of them), and one with a damaged check keeps its records; a hundred mebibytes of blank lines in a small gzip took minutes and ignored the time limit; a pretty-printed export whose records follow another member was read as one document, re-parsed on every read (58 times the file in memory); at most a hundred thousand rejected records are listed, the rest counted, and a file whose first thousand records are all rejected is stopped, named; an archive in a directory (`.zip`, tar) is named and makes the read partial; `eventVersion`, `requestID`, `addendum`, `tlsDetails` and any other top-level key are kept (`other_fields`), and a version this tool has not seen makes the read partial. Error classes cover SNS, Cognito (the same code from another service is a denial), EC2 `Server.*` and a failed console login; the digest check no longer drops an event that carries a digest file's keys.
- **`ual_parse`** matched `record_type` against the payload's number or the outer column's name, never both; it now matches the number and the name, whichever the export wrote, shows the export's own pairing (`record_types_all_rows`), and reports a filter value that matched no row. A native `CreationTime` with no zone was silent; it is `no_zone`, said in `time_zone`, and a `since`/`until` that needs it makes the read partial. A declared `date_order` that a row contradicts left the row decoded the wrong way; it is now undecoded and named. An export whose own `ResultCount` is larger than the rows it holds is partial. `operations_all_rows` and the raw `time` passed the withholding unchecked; they no longer do. NaN is not JSON and is rejected, named.
- **`signin_analyse`** read the error code before the `Status`, so an `Interrupted` portal row (which carries 50074, 50076, 50079, 50125, 50140 or 50158) was a failure, and a multi-factor flow of three prompts and a success was reported as a failure burst. `Interrupted` is now null whatever the code beside it says, a code the tool lists as a prompt is null with `outcome_class: interrupt` (counted in `interrupts`, kept out of `failures` and bursts), and `prompts_before_success` (`prompt_min_count`, default 5) lists a run of prompts before a success as a lead for multi-factor prompt flooding. The portal's `User` column, the display name, was the account: two people called Alice were one account and a travel pair between them; an account is now its object id, else its lower-cased user name. The `user` filter reads the user name and the display name as printed. A portal `Location` is `City, State, Country` and its last component is the country, so a move between two cities of one country is no travel; a slash date in a `Date (UTC)` column needs a date order like any other; a `format` the content contradicts is refused; a lead cites an id that has been through the withholding; `failure_events` shows ten of a burst with the total and every one is in `burst_members`; two far successes at one recorded second are listed with no speed; a Workspace activity of another application (Drive, Admin) is rejected, named; "Login success" is a success as "Login failure" is a failure; an event with no decodable time is counted and makes the read partial; a service principal is analysed under its own name.

### Security: the masking also covers a password in a URL, a Google client secret, an Azure Functions key and a five-part JWE, and a long string is scanned in linear time

A password in a connection URL (`scheme://user:PASS@host`, which ECS, Lambda and App Service environment values are logged as in `requestParameters`), a Google OAuth client secret (`GOCSPX-…`), an Azure Functions key (`?code=…`, `x-functions-key:`) and a JWE (five parts; the JSON Web Token rule stops at three) were printed in clear and were not in the values file; each is now a rule of the shared block with a test. The JSON Web Token rule was quadratic on a long string (a megabyte of `eyJ` took 120 s under a 5 s limit): it is anchored at the start of a run and possessive, a text over 64 KiB is scanned with the deadline in view, and a scan the deadline ends withholds the text it did not scan. A base64 digest under a field named a checksum, a digest or a hash (`x-amz-checksum-sha256`) is no longer taken for a key by its length, and `nextToken=`, `clientToken=` and prose such as `pass: 3 attempts` are no longer withheld. SIGTERM flushes the values file and disarms the pattern timer before it exits; the deadline is checked between the members of a gzip.

### Fixed: cloudtrail_parse, ual_parse and signin_analyse, second review

Copies of one call that disagree on the caller or the returned access key id were merged and the order of the files decided the caller: the session is now `unresolved`, with the copies that differ marked. The session lookups were quadratic in calls times uses (5,000 calls and 20,000 uses: 67 s): they are by composite index, the counts are made once per ARN and the answer for the same question is kept (3.9 s). A result of a read that ended early is named `partial_records` or `partial_events`, never `complete_*`; a `not_found` says once that a call returned a different key; the note says a session from `GetSessionToken` or `GetFederationToken` has no AssumeRole call. `ual_parse` compares `record_type` without white space or leading zeros and `operations` without case, and reports an unmatched value as it was given. `signin_analyse` takes the nil object id for no id.
