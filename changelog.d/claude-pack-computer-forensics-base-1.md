### Fixed: the computer-forensics-base pack's tools, recipes and skills say what they measured, and stop turning failures into clean results

Review-driven fixes to the base pack (every other pack depends on it), one regression test for each, with fixtures built from the formats' specifications and shown to fail on the earlier code. The pack gets its own tests directory (`packs/computer-forensics-base/tests/`, run by `tests/pack-local.test.sh`).

- **The `memory-windows` recipe never fetches symbols.** It retried Volatility without `--offline` when `windows.info` failed on a missing symbol table, and the test asserted it, against the memory pack's rule to switch off nothing and fetch nothing. Every call is offline now; an image with no table for its kernel ends after one `windows.info` call, partial, with the kernel's PDB, GUID and age named in coverage, and no plugin that needs symbols is run. Coverage is written before the first step and `steps.jsonl` holds one record per step (command, exit, seconds, outputs).
- **`timestamp_decode` keeps fractions.** `45000.5` was read as `45000`, a half day wrong on an OLE date; FILETIME ticks and Apple nanoseconds lost their last digits. The value is read exactly, fractions are kept to the nanosecond (the rest is `remainder_s`), Unix nanoseconds are a reading, OLE negative dates follow the format, a DOS date is built through a real date in both word orders with refused readings listed, DOS and OLE carry no invented zone, and plausibility is judged against an explicit range (every reading by default) instead of the wall clock, whose year replace crashed on 29 February.
- **`image_layout` passes the sector size to the Sleuth Kit.** `sector_size` changed only its own arithmetic; the same `-b` now reaches `mmls`, `fsstat` and the example commands. A VHD (dynamic or fixed) is recognised, a missing, timed-out or refused `mmls` is `partition_table: "unknown"` and not "no partition table", and the programs' whole output is kept in files.
- **`sqlite_query` reads, bounded and typed, and says what the WAL left out.** It opens the file immutable through Python's `sqlite3` with an authorizer that allows reading only (no write, ATTACH, extension or setting pragma; `readonly: false` is refused), returns an inline page and a complete JSON Lines file with NULL, BLOB (length and sha256) and non-UTF-8 text typed, runs several statements, stops at a time budget, and reports the `-wal`, `-shm` and rollback journal beside the database with `snapshot_status` saying that rows committed only in the WAL are not in the result. Applying the WAL needs a staged copy of the database set, which is for the next change. **Behaviour change for dependents:** the answer keeps `ok`, `stdout`, `stderr` and `returncode` and adds `rows`, `columns`, `rows_file` and the sidecar report; high entropy is called unidentified, not encrypted.
- **`timeline_super` reports each stage.** It carried on after a nonzero Plaso exit when a file stood where it wrote and returned no exit code. It returns `collect_exit`, `export_exit`, a `status`, the versions the programs print and valid and invalid line counts, runs under one deadline, refuses an output directory that already holds files unless `resume` is true, and `mode: export` runs psort alone over an existing storage file so a new filter does not collect again.
- **`file_carver` names a candidate and walks the format.** Registry hives were never carved (the size was read from the file format field at `0x20`, not the hive bins size at `0x28`); a PDF stopped at its first `%%EOF`, a PNG, JPEG or GIF at a footer byte inside the payload, a PE ignored its certificate table and overlay. The ends now come from structure walks, the result says `boundary: validated` or `heuristic`, a short header is an error, the range is streamed, and the output is created new.
- **`sig_carve` counts each header once.** Seventeen passes over the file, with the previous read's tail glued on again, reported a MAM at 64 MiB less one from bytes the file does not hold. One pass, one carry, an unknown signature is an error.
- **`ioc_scan`, `chunk_needles` and `feature_scan` no longer return the bytes around a hit.** They return locators; the text goes to a 0600 file under `$OUT` only on `write_values`, in a job (the secret-safe pattern), and the skills say to run those jobs with `secret_output`. Counts no longer depend on `chunk`, `chunk_needles` names the image, volume offset and inode and takes `-b`, and `feature_scan` returns the whole output inventory, counts histogram files apart and reports a nonzero exit as partial or failed.
- **`file_type`, `catalog_search`, `check_inputs`, `icat_extract`, `ad1_extract` and the recipes.** `file_type` counts what it opened and keeps every result (a Java class is not Mach-O, prefetch is at offset 4); `catalog_search` writes its overflow under a job's `$OUT` and says when a revision cannot be read; `check_inputs` checks the whole manifest and does not pass a size-only check; `icat_extract` streams into a new file under a budget; `ad1_extract` keeps partial names distinct, separates `processing_status` from `integrity_status` and takes budgets; `disk-volumes` inventories every allocated entry; `disk-timeline` passes a timezone and says complete means the pipeline finished; `archive-members` stops promising an extractor the pack does not ship.
- **The skills** say what an artefact shows, what it does not and what must corroborate it; `filesystem/encrypted` no longer puts a key on a command line, and `filesystem/extract` no longer says nothing extracted can execute. `ewfverify`, `mactime`, `exiftool` and `7z` are declared. The tool-library copies of `file_carver`, `catalog_search`, `sig_carve`, `ioc_scan` and `sqlite_query` (which was still the old shell wrapper) are the pack's, and a test in `tests/tool-library.test.ts` holds all five equal, `run.py` and manifest.
- **A second review round, each finding checked and fixed with its own test.** `ioc_scan` and `chunk_needles` give the same ids and the same inline page whatever `chunk` is, and a needle given twice is one; `check_inputs` writes a receipts file of its own per run as it goes, lists a directory it cannot read, and does not die on a name that is not UTF-8; `catalog_search` says a generation whose index or directory is missing, and bounds `limit`; `feature_scan` can say `failed`, confines `out_dir` to `$OUT` in a job and answers instead of a traceback; `sig_carve` survives a result file it cannot write; `ad1_extract` no longer calls an item absent that a budget stop never reached, keeps a partial by rename where the file system has no hard links, and the `ad1-items` recipe does not call an image verified when a file records no digest. `disk-volumes` asks `fsstat` before it believes a partition's name, time-boxes its no-table tries and keeps what `mmls` said; both shell recipes end on a flag with no value instead of looping; `memory-windows` says a failed `windows.info` whole and rewrites its coverage after each plugin; `disk-timeline` leaves an earlier run's `coverage.json` alone when it refuses a stale directory. `image_layout` reads FAT's volume ID and label, an empty field as empty, a partition by its table column, keeps each command's output apart, takes an image named with a leading dash as a path, and counts a silent `mmls` failure as "no table" only when `img_stat` opens the image. `timeline_super` refuses a link at any file it writes, lists only this run's logs, reports the earliest and latest event time, ends its child when it is terminated and bounds its budget and sample. `sqlite_query` never drops a last statement with a trailing comment, reads a row at a time, keeps the rows read before a stop, counts the inline page in bytes and treats an empty journal as not hot. `file_type` reports a directory it cannot list, hashes under the time budget, names Ex01 and L01 files and every EWF segment, and does not call a script's extension a mismatch. `icat_extract` stops a stalled `icat` at its budget and never replaces a file that appears at the name while it runs. Every tool that has a time budget of its own (`check_inputs`, `icat_extract`, `ad1_extract`, `timeline_super`, `feature_scan`, `sig_carve`) now ends it inside its manifest's limit; `ioc_scan` and `chunk_needles` have none, and their 120-second manifest limit is left for the owner.
- **A third review round.** In a job, `icat_extract`, `file_carver` and `timeline_super` refuse an output outside `$OUT`, and the `filesystem/extract` and `timeline/super` skills show a path that works there (`{OUT}/<name>`); `timeline_super` says an unwritable directory as JSON, names a resumed run's files beside the earlier ones (`timeline.2.jsonl`) instead of over them, and the pack declares `pinfo`. `feature_scan` makes `out_dir` 0700 and its files 0600 once bulk_extractor ends and answers `out_dir_contains_secret_values` and `kinds_holding_values` (`alerts.txt` can hold a whole recovery key). `ioc_scan`, `chunk_needles` and `feature_scan` take the secret-values constructor from the reference (a second `write_values` run in a job is a JSON refusal, a link at the name is refused, an empty file says `written: 0`) and leave no half-written results file. `disk-timeline` is partial when Plaso's own words (an error line, a killed worker, zero events, an empty timeline) say so, whatever the exit codes. Results files of `sqlite_query`, `ioc_scan`, `chunk_needles`, `sig_carve`, `file_type` and `catalog_search` are never replaced by a later, different answer to the same question (it is kept as `name.2.ext`); the same answer again is the file that is there. `sqlite_query` refuses a value past 64 MiB by name and streams a large BLOB. `ad1_extract` takes a `max_walk` budget and holds the depth of the tree, not every item (100,000 items: 32 MB, was 100 MB). `sig_carve` has a `start` and a 100-second budget and says `complete: false` and where to go on. `file_carver` validates a ZIP of 65,536 entries or more by its ZIP64 record and ends a JPEG at a following start-of-image as a guess. `check_inputs` refuses a manifest path outside `inputs/`. `file_type` follows a path that is itself a link once, names what the time budget left unlooked at, and returns the first bytes only with `head_hex`. `archive-members` refuses a long-name or pax header that declares more than 1 MiB, writes its coverage first, stops a stalled `7z` at its deadline and judges a name with a NUL whole. `timestamp_decode` caps a value at 80 characters and reads ASCII digits only. `image_layout` asks `img_stat` which image type the Sleuth Kit opened and gives no offsets for a container it read as raw. `ioc_scan` names the needles that ran. The image discovery of `chunk_needles`, `icat_extract` and `catalog_search` follows a link only for a set `inputs.json` names, and `catalog_search` takes only a catalogue under `catalog/`.
- **Behaviour changes for dependents.** `timestamp_decode` returns readings with a precision and a remainder and refuses what it cannot read exactly; `check_inputs` writes a receipts file named for the run (the `modified`, `missing` and `added` keys are as they were) and fails on a manifest entry with no digest; `ioc_scan`, `chunk_needles` and `feature_scan` return locators and counts and no context, and `write_values` is refused outside a job; `file_type` no longer returns `head_hex` unless asked and `catalog_search` bounds `limit` to 1000; A stop at a budget between windows or items is exit 0 with the answer saying where it stopped (the engine ran): `sig_carve` (`scanned.complete: false`, `scanned.stopped`, `start` to go on), `ad1_extract` (`processing_status: partial`, `stopped_by_budget`) and `file_type` (`complete: false`, `why_not_complete`); a read error, a broken item or a child that failed or was killed mid-write (`icat_extract`'s `.partial`, `feature_scan`, `timeline_super`, `sqlite_query` cut by its clock) is exit 1, and `check_inputs` exits 1 on any verdict that is not a pass. The six tools that keep results files (`sqlite_query`, `ioc_scan`, `chunk_needles`, `sig_carve`, `file_type`, `catalog_search`) say `earlier_answers`, how many other files already answer the same question.
- **`timeline_super` no longer starts Plaso in a session of its own.** `start_new_session=True` took log2timeline and psort out of the group the harness kills when it ends a tool, so they went on writing into the output directory after the tool was gone. They now run in the tool's own group (as the network-forensics engine tools do), on Linux the kernel is asked to end them if the tool dies, the tool's deadline ends them and what they started by walking the process tree, and SIGTERM, SIGINT and SIGHUP do the same and print a last word (`stopped_by_signal`). A test starts the tool in a group of its own, kills the group the way the harness does, and asserts the engine and its child die; another holds every tool and recipe of the pack free of `start_new_session`, `setsid` and `process_group`. Nothing else in the pack used them.
