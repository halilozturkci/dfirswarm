### Security: the Linux pack's tools no longer print command lines, sudo lines, cron environments or journal messages

`shell_history` returned every command of every history file inline; `auth_log` returned each sudo line's whole command and every message; `cron_dump` returned each cron command and the environment in force at it; `journal_export` returned messages and `_CMDLINE`. Any of these can hold a password or a token (a `mysql -p...`, a `--token=`, a name typed into a login prompt that was a password), and the answer is recorded in the trace and quoted into reports. All four now follow the secret-safe output pattern of `recovery_key_scan` (docs/packs.md, "Secrets and sensitive output"): the answer is fields and locators (file, physical line, byte offset) and the length of the text, never the text; `write_commands` / `write_text` writes it to a file under `$OUT` (mode 0600, created first, a file or link already there refused) and `preview_commands` / `preview_text` puts it in the answer, each only when the tool runs as a job, which the skill says to run with `secret_output: true`; outside a job both are refused and nothing is written. No value is hashed, shortened or masked. The new suites assert the absence of a planted secret in the answer and in every file the answer names.

### Fixed: the Linux pack's tools stop returning plausible wrong answers

- **`auth_log`** lost the key type and fingerprint of an ordinary `Accepted publickey ... ssh2: ED25519 SHA256:...` line (an optional word after the port ate `ssh2:`), lost the user and source of a PAM authentication failure, could report the word `user` as the source of a disconnect, and called `Accepted key` (sshd matching a login to an authorized_keys entry) `key_added`, as if a key had been installed. The SSH rules are explicit variants (a certificate's id, serial and CA included), PAM is read as key=value pairs, a source is an address or it is not a source, and the kind is `key_observed_authentication`. The year was added at every month that went down, so January, December, January became two year ends: a year end is now counted only where the months wrap forward, a line out of order is flagged `reordered`, the stamp is kept as written with `time_zone: unknown`, an unknown month is an unparsed line and not January, and the year of a file says its basis (the file's mtime, or your `year`). Lines carry their file, physical line and byte offset; unparsed lines are counted, located and paged; a gzip cut off mid-stream, or expanding past `max_expanded_bytes`, is a named partial file with what was read kept; `complete` is replaced by `all_lines_parsed`.
- **`journal_export`** kept 14 fields of each entry, dropped the cursor and the monotonic timestamp, popped the original realtime value, held the whole export in memory, and told the examiner "within one boot the clock is consistent" and that a journal with no `/var/log/journal` behind it "was volatile". It now writes the complete native export (`journalctl -o json --all`) to `$OUT/journal-native.jsonl` exactly as journalctl produced it, answers with a projection that keeps the cursor and both clocks raw, requires time bounds that carry their zone, keeps stderr whole, returns what it read as partial at a deadline, and has a `mode: verify` that claims only a structural check. The note no longer gives a chronology rule the journal does not support.
- **`cron_dump`** called itself "every scheduled job", looked in no user systemd directory, dropped the empty assignments of a timer and took the first `Unit=`, joined a cron command's words with single spaces, and computed `complete` after `contains` had filtered its entries. It is now a candidate inventory with a census of every place it looked in and a list of what it does not read, keeps the cron line and the command as written and every timer assignment in order with its section and line, and computes coverage before it filters.
- **`shell_history`** split a timestamped multi-line Bash entry into several commands, read every file with Bash's rules, took a directory's name for the account, dropped any directory called `dev`, `sys` or `proc` at any depth and ignored a directory it could not open. It reads Bash, zsh, fish and plain client histories by their formats, says how each record's boundaries were found, names the owner only where the evidence's `etc/passwd` gives that home to one account, leaves out only the top of the tree's `proc`, `sys` and `dev`, and records walk errors.
- **`utmp_parse`** chose a lastlog layout by scoring a sample and said nothing about it, assumed a little-endian utmp, reduced an invalid microsecond count modulo a million so it looked like a time, read every slot of a sparse lastlog (a large UID timed out), and carried no locator. It names the layout and byte order and how it chose them, refuses what it cannot tell apart, keeps raw seconds and microseconds, locates every record, walks a lastlog skipping holes within `max_slots` and `max_seconds`, and refuses a SQLite accounting database with a pointer to `sqlite_query`.
- **`linux_triage`** called a run `complete` because every process exited 0. It runs each dissect.target function on its own, gives it a status from what was observed (parsed, empty, unsupported, failed, not attempted, unknown), says what each family does and does not cover, refuses an empty, unknown or repeated `groups`, stops at a total deadline, and rewrites `summary.json` after every function. **The `linux-target` recipe** answered "does not apply" where it could not read the OS; it now exits 2 with `applies: "unknown"` there, writes its coverage receipt before the wrapper starts and from the wrapper's own summary, and is `complete` only where every selected function produced records or nothing.

### Fixed: what an independent adversarial pass found in the rewritten tools

Non-object or wrongly typed arguments gave a traceback in every tool; a PAM line's own `key=value` text could overwrite a record's locator fields in `auth_log` (a user name typed at a prompt reaches that line), so only the seven keys pam_unix writes set a field; two `auth_log` patterns were quadratic in a run of whitespace and a stamp at the end of the calendar or a pid of thousands of digits was a traceback; a line longer than 64 KiB is now located and not parsed, a long free-text field is shown cut with its whole length, and a gzip's expansion cap holds through a very long line. A month decrease through an invalid date no longer makes the lines after it `reordered`; a dotted date suffix (`auth.log.20240101`) orders as a date; `su`'s account and target are told apart; a zoned stamp's `time` is the clock as written and `time_utc` the instant. In `shell_history` a long stamped entry was quadratic (60,000 lines took 34 s), a zsh empty line inside a continued command ended it, a huge `elapsed` field was a traceback, a line over 8 MiB became several unflagged records, and trailing blank lines joined the command. In `cron_dump` the values of a section that is withheld leaked through the derived `schedules`/`unit`/`persistent` fields, an account deleted from `/etc/passwd` kept its home unread, every entry copied the whole environment (4,000 variables and 4,000 jobs took 620 MB), and a comment ending in a backslash swallowed the next assignment. A pipe named like a log or a history file hung `auth_log`, `shell_history` and `cron_dump`; they now list it and never open it. In `journal_export` a repeated `_BOOT_ID` was a traceback, one huge entry cost several times its size in memory, the deadline killed journalctl and not what it had started, and a journal directory could hold links journalctl would follow out of the evidence. In `utmp_parse` a `types` string was split into characters, a `start_uid` past the file gave a negative count, and two requests with different `max_slots` overwrote each other's paging file; a paging file now has a random name in every tool (a digest of the request would have hashed a search term). A preview's text went into the paging file once an answer passed `limit`; it no longer does. `linux_triage` glued a function's unterminated last line to the next function's first record, read a whole stderr into memory, called a function `unsupported` on any stderr that said so about something else, and left dissect.target running after SIGTERM; the recipe's detect answered "does not apply" on an exception and its receipt could read an earlier run's summary.

### Fixed: what the review of the Linux pack's tools found

- **A name typed at a prompt is no longer printed.** `auth_log` printed the name of an `Invalid user` line, of `Failed password for invalid user`, of a disconnect from an invalid user and a PAM `user=` inline, and `utmp_parse` printed btmp's `ut_user`: each is what someone typed and can be a password in the wrong field. The answer and the paging file now carry its length (`user_bytes`, `user_withheld`) and the job's text file and `preview_text` carry the name; an account the log accepted (Accepted, sessions, sudo, su, wtmp) stays inline. `contains` / `grep` / `user` match withheld text only in a job (outside one they match the fields the answer shows, so they are no oracle on a withheld value) and the answer says `filter_touched_withheld_text`. `cron_dump` shows a timer value only for the keys with scheduling semantics (`value_bytes` and `value_withheld` for the rest).
- **One `status` on every answer.** The six tools and the `linux-target` recipe (its receipt, `detect` and `run`) carry `status: complete|partial|failed` and `status_basis`, the pair the form recipes' coverage.json carries; the tool-specific booleans (`all_lines_parsed`, `all_files_read`, `all_checked_locations_read`, `all_records_read`, `execution_complete`) stay beside it, and `journal_export`'s `export_status` is now `status`. An error answer says `status: failed`. `docs/packs.md` §8 says so in the tool contract.
- **Nothing ends in a traceback or a hang.** An unwritable `$OUT` or run directory, an `open()` that fails (a mode 000 file), a pipe named as the file or as `passwd` (opened, it waits for a writer), a directory or pipe as a journal `path`, an `lstat` of a readable but unsearchable directory, and `max_seconds` of NaN or Infinity are each an error in JSON. `journal_export` ends journalctl and what it started on SIGTERM, passes `--quiet` and counts `-- No entries --` as no entries, never writes over an earlier verify or stderr output of the same job, and checks every component of the path for a link.
- **`auth_log` dates a file from the lines that agree.** A stray March line in a January file no longer makes the file March (a line the next line contradicts is `reordered`), and a log that skips from January to September is not given a year end; a PAM line is read by a linear split (the quadratic pattern is gone); a failed public key keeps the rejected key; a second 60 and a fraction past six digits are noted and not dropped; a single trailing CR is stripped; `max_seconds` bounds a 300 MB read and names the files not reached.
- **`utmp_parse` no longer reads another record size as 384 bytes.** The byte order is decided from `ut_type` 1-9 only, and a file where fewer than 80% of its non-empty records have such a type is refused as not 384-byte records (392-byte records read as 384 before, with `all_records_read: true`); `layout: utmp-384` or a `byte_order` reads it anyway and says it doubts. `ut_exit` is kept, `holes_skipped` and the `passwd` that named the accounts are printed, `lastlog.1` is read as a lastlog, `start_record` resumes a read, arguments of the other kind are refused and `max_seconds` bounds a very large wtmp.
- **`cron_dump` streams.** A cron table is read a line at a time with byte offsets and the environment goes straight to the text file (a 300,000-line table no longer sits in memory), a merged-`/usr` directory reached twice is read once and the alias named, the places looked in are counted by state and paged, and `max_seconds` bounds the walk; a BOM, a line without `=` and a `..` home in passwd no longer pass unnoticed.
- **`shell_history` keeps the whole.** The sealed text file keeps a byte that is not UTF-8 (it was replaced), a run of blank lines inside a stamped entry is bounded (20 million newlines was 2.3 GB), a write error is no longer reported as a read error of the evidence file, `max_seconds` counts stamp-only lines, and `root_is_file_system_root` lets a root without an `etc/` be read as one.
- **`linux_triage` and the recipe.** A function's name is found in a stderr line as a whole word and by its whole dotted name; a function is started only if the time left in the total deadline covers its own timeout, otherwise it is `not_attempted` and not a `failed` one cut off by the clock; a job's `out_dir` must be under `$OUT` (the manifest's example is `work/<your id>/linux-triage`) and a directory that cannot be made is an error in JSON. The recipe's `detect` reads the `os` value as one value (a hostname called `linux` is not the OS; `unix` and a distribution name are `could not tell`, exit 2), says Linux is dissect.target's own identification, catches only `OSError`, `SubprocessError` and `UnicodeError`, and runs the wrapper in its own output directory, so it no longer fails when the census starts it in the host's working directory. Its receipt says `partial` before the wrapper ends and `failed` where no summary of this run exists, in place of `unknown`.

### Changed: the Linux pack's tool manifests say what they read and what they do not

Each manifest now has a `use` (what its tool is for), states what is and is not measured, and carries its raised version and the sha256 of its script. New suites (`tests/pack-linux-*.test.ts`) build their fixtures from the formats' own layouts (glibc `struct utmp` and `struct lastlog`, OpenSSH and PAM log lines, Bash, zsh and fish history forms, `journalctl -o json` entries, crontab and systemd.timer files) and fail on the old tools. `tests/pack-recipes.test.sh` accepts a recipe's detect exiting 2 with `applies: "unknown"`, the protocol's error for a probe that could not tell. The skills follow in the pack's next pull request.
