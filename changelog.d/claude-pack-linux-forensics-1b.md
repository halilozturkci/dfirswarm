### Changed: the Linux pack's skills say what each artefact shows and does not show, and no longer contradict the worker prompt

The ten skills are rewritten in the defender's voice, each separating what an artefact shows from what it does not and from what must corroborate it, with every negative bounded by what was searched. `accounts/users` read `/etc/shadow` as "the hash" with no handling rule and treated a recent password change, a duplicate UID 0, an authorized key and a group's membership as findings; it now sends credential-bearing files to a sealed job with `secret_output: true`, reports an account, a field's meaning and a location and never a verifier or a hash of one, and names the policy that makes each of those a finding (sshd's effective configuration, sudoers includes and Runas targets, the container daemon's socket and mode). `containers/docker` is rewritten as a runtime-identification method (the Docker layout is an example for overlay2, not a universal one), keeps OCI whiteouts apart from native OverlayFS ones, reads state timestamps as runtime metadata and not as execution, reads `Config.Env` in a sealed job and reports names, and reads the daemon's log with `journal_export` at the evidence path instead of `journalctl -u docker`, which reads the analysis machine's journal. `packages/integrity` is triage against the examined machine's own package database and says so; its `rpm` route carries `--noscripts --nodeps`, confirmed on the installed version against a trial database, so that a `%verifyscript` scriptlet from the evidence does not run (the worker prompt never runs recovered code), and an independent baseline is a separately obtained, authenticated package payload extracted without its scripts.

`logs/journal` no longer says a missing `/var/log/journal` means the journal was never persistent, that `journal_export` returns "every record", that "boot grouping makes a clock change stop mattering" (a boot id orders nothing and the wall clock can step within a boot; monotonic time is the order inside it) or that `--verify` shows completeness. `logs/auth`, `filesystem/ext`, `filesystem/storage`, `persistence/mechanisms`, `timeline/linux` and `triage/system-profile` drop, in the same way, "three sources that disagree show the logs were touched", a `sudo -i` followed by silence as "itself the finding", a `crtime` later than `mtime` as "copied", a later `ctime` as "the closest Linux gets to the tell", two failed recovery routes as "the contents are not recoverable", `qemu-img info --force-share` as the backing-chain method, `[Install] WantedBy` as "makes it start", `find /` (the worker's own filesystem) as the SUID search, the absence of every mechanism as "the operator expected to return another way", the oldest timestamp as the install date, and rsyslog times as always local with no offset.

`requires/host.json` declares the companions the bodies call (`pvs` and `vgs` with `lvs`, `dumpe2fs` with `debugfs`) and drops comparisons with other tools that nothing here tested. Every skill names the tools and programs its front matter lists and the other way round, so the pack's lines leave `tests/pack-links.pending`; `ausearch`, which no skill names yet, is in `unreferenced_ok` with the reason. The README and the two goal templates stop calling the package database "the distribution's hashes" and the integrity check "the cheapest way to clear thousands of files". The audit-log skill and tool, the systemd, timestamp-anomaly and cloud-host skills, the container tools and the package verifier are the pack's next pull request, and the goal's execution question now asks for audit records only where the host retained them.
