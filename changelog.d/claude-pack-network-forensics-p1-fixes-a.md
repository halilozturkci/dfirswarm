### Fixed: pcap_extract ties HTTP objects to frames on the current tshark, and the network pack's log, extract and beacon tools stop printing what they should withhold

A second review of the network pack found that the headline feature of `pcap_extract` did not run on the one real tshark available to test with. The frame-association pass asked tshark for the field `http.response_for.uri`, which tshark 4.6 does not list (`Some fields aren't valid`, exit 1), so on every capture with HTTP objects the pass failed, every HTTP row said `failed`, and the run exited 1. The test stand-in accepted any `-e` field and the test copied the same field list, so CI never saw it. On a real capture with five HTTP objects the old tool gave `ok: false` and five `failed`; it now gives four `matched_by_content` and one `unmapped`.

- **`pcap_extract`** asks the installed tshark which fields it has (`tshark -G fields`) and asks for those: the request URI from `http.request.full_uri` (or `http.response_for.uri` on a build that lists only that), and the host from `http.host` or, where that is empty on a response frame, from the request URI. A field the build lacks is named in `association_pass.fields_missing` and is never a failed run; without `http.file_data` the pass is `unavailable` by name and every object stays indexed. The test stand-in now refuses an unknown field as the real program does, and a test runs against the real tshark when it is installed and skips with a reason when it is not. The rows are ordered by name for the names that are printed, and the objects whose names are withheld follow them, numbered and ordered by size and SHA-256, never by their real names (the position of a withheld row bracketed the first letter of its name in 77 of 77 runs, a chance rate is 4%; it is now 1 of 77). The listing pass has a display filter of its own and the caller's `display_filter` is neither passed to it nor echoed in the answer or the receipt: a count of listed responses that followed the filter was a bit oracle on withheld request URIs. A host in the URL authority and the host column goes through the same rule as every other string of the pack. The unreadable listing rows are all named in a file, `ftp-data` is in the default export types where the build lists it, a pcapng's Decryption Secrets Blocks are counted and said (tshark applies them), and a stopped run prints partial JSON.
- **`network_log_summary`** printed columns in eleven slots as the line wrote them (`src`, `dst`, ports, NAT addresses, `elapsed_ms`, the whole time text of a web line, a firewall line's whole prefix, a quoted firewall value): a token planted in any of them was printed in 100% of runs, and the aggregate keys carried the raw `src` and `dst`. Every printed column now has a rule of its own, and a test holds the rule table to the column list: an address is an IP address or goes through the withholding block, a port, status and counter are digits or go through it, a host in a target or referer goes through it, and the aggregate keys are the printed text. In 4 listed shapes x 32 slots x 12 random plants none is printed (it was 11 of the 32 slots in the reviewer's run). An escaped quote in a referer or user agent (`\"`) no longer ends the field and silently drops the rest; text after the last field of a grammar is kept in the new `unparsed_tail` column and the row is `partial`.
- **`beacon_score`** held a series in two Python lists: 3,000,000 timestamps took 1.19 GB; the series is now packed (336 MB measured at the 3,000,000-event cap, which it refuses to pass; it was 5,000,000). It keeps its own clock (`max_seconds`, default 40) and answers partial for the values read. An integer too large for a float is `out_of_range` (it aborted the run), ISO 8601 times are read by the tool's own parser, the same on Python 3.11, 3.12 and 3.14 (the standard library's parser accepted `24:00` on 3.14 only and a bare fraction point on 3.11 and 3.12 only; 60,000 seeded inputs now give one result on all three), a rejected value is named by position, reason and length and never printed back (a bearer token in a timestamps file was printed three times), every rejected value is listed in a file, a label must be a few plain words, and an answer in which any value was not scored is `partial` (`all_values_scored` false, the counts in the `status_basis`), never `complete`.
- **All three** answer with `status` and `status_basis`, exit 0 when the engine ran (the answer says whether it was whole), keep the exit 1 for a refusal, and end with partial JSON on SIGTERM, SIGINT and SIGHUP. `pcap_extract` and `network_log_summary` declare `secret_output: "required"` in their manifest (the harness now enforces it) and refuse `write_values` as JSON, before anything is written, in a job whose process does not have `SECRET_OUTPUT=1`.
- **Manifest examples.** Five of the six examples were refused in a job (`work/pcap-summary` is not a place a job writes); they name `work/<your id>/...` and a test runs every example as a job.

New tests in `tests/pack-network-*.test.ts` (146 cases in the pack's suites, each new one fails on the code it replaces); the random shapes live in `tests/pack-network-canaries.ts`. Withholding is by shape, as before: the shared block is unchanged here, and what it does not recognise (a short secret, an unlisted token family) is still printed. The tool-process changes (zeek_run, suricata_run, pcap_summary, the capture recipe) follow in the next pull request.
