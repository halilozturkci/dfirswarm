### Security: the ransomware-response pack no longer prints a note's identifiers or tells an agent to hash a credential

`ransom_note_scan` returned, inline in an ordinary tool answer, every identifier it matched (its pattern captures "your personal key/token" values), the first lines of every note and global lists of every onion address, e-mail address, URL, wallet and Tox id. A victim identifier or a portal URL with an access token is access-bearing, and an appendix is not an access-control boundary. The answer is now a locator, the secret-safe output pattern of `recovery_key_scan`: per note an id, size, whole-file sha256, modification time, class, encoding and a count per kind; per occurrence a finding id, byte offset, length and validation; no identifier, wallet, address, URL or note text anywhere in the answer or in a file it names. `write_values: true` writes the values, and a preview of each note, to `$OUT/ransom-note-values.jsonl` (mode 0600, created before the scan, refused outside a job); every path it prints (notes, rejected name matches, directories it could not list, exclusions, the root) has any component withheld that holds an identifier-shaped token (eight or more letters and digits, both kinds) or a value the note held, so a name is never hidden on one line and printed on the next; and the whole-file sha256 of a note shorter than 128 bytes, or one that is a single token or indicator value, is withheld, since it would be a digest of the value. `encrypted_survey` withholds, and counts in `paths_withheld`, the identifier-shaped name of a file named like a note (ransom_note_scan's name pattern), which it printed in `note_name_candidates` and the census. The skills that name the tool say the job runs with `secret_output: true`.

`reporting/for-regulators` told the agent to cite where a recovered credential was "and record its hash". The worker prompt forbids a hash of a secret anywhere; the skill now says to record where it was, its type and length, what it grants and the rotation it needs, with a sealed reference. The goal template's definition of done follows: answer 2 states `Exfiltration conclusion: <outcome>`, the outcome one of established, partial, bounded negative or not determinable (it said "which of three positions"); no credential, key, wallet, victim identifier or hash of a secret is in the report, which cites where each is (note id and offset, sealed job output) instead of an appendix of values; and its acceptance check is bound to answer 2's section and to that phrase, so "the connection was established" elsewhere in the report no longer passes it.

### Fixed: the ransomware-response pack's tools stop publishing heuristics under verdict names

- **`encrypted_survey`** published `not_encrypted`, `proportion_encrypted` and `bytes_intact` for files it had only failed to match, read a compressed archive as encrypted without saying so, called a low-entropy end window `partially_encrypted`, called a trailer shared by the sampled files "a family marker", said the hourly modification times of every file "bracket the run to the minute", and described its sample as "read in full" when it reads three windows and a tail. It now names candidates, with reasons, and gives what it could not measure buckets of their own (`noncandidate`, `unmeasured` for 4096 bytes or less or a spent read budget, `read_failed`), each with a count and bytes; `candidate_file_fraction` names its denominator; the three windows carry their offsets and lengths and say when they overlap; shared tail bytes are an observation pending a reference match; modification times are counted by hour for all files and for candidates, labelled as filesystem mtime as collected and not an execution time, and a time a datetime cannot hold no longer stops the survey. Its name rule now catches an identifier between the known extension and the new one (`report.docx.id[AB12CD34].locked`), the list of known extensions and of normally compressed formats includes `gz`, `bz2`, `xz`, `7z`, `rar`, `webp`, `heic`, `mkv`, `jar` and the common media formats (so a real `.gz` candidate carries an alternative explanation, and a `.tar.gz` is no appended extension), and the overflow of each hour histogram past its cap is counted on its own (`histogram_tables`). A top-level `proc`, `sys` or `dev` is skipped by a stated parameter and listed (it was dropped at any depth, silently), links are not followed and only regular files are opened, the walk is in name order, `sample`, `tail_bytes` and the bytes read are bounded and a spent budget says `partial`, and a census of every entry, ending in a receipt row, is written whole under `tool-output` beside every table longer than `limit`. Rows are written as JSON escapes, so a file name that is not UTF-8 (lone surrogates in Python) no longer stops either tool.
- **`ransom_note_scan`** counted every file whose name matched as a ransom note, took any NUL in the first 200 bytes for UTF-16LE, followed links to files outside the tree, dropped read failures silently, and said the onion address "identifies the group" and the earliest note time "is close to when the run started". A name match is now a candidate, classed `content_resembles_note` or `filename_only` (a project readme is the latter); indicators are candidates (the value after a label such as "your personal ID" is an `identifier_candidate`), a bitcoin address's own checksum is checked and the rest are syntactic; the earliest note time is an observation of the filesystem's mtime; the manifest says that a long unlabelled token (a 64-digit hex string after the word "Token") is neither located nor counted. It reads a byte-order mark, UTF-16BE and the NUL pattern, counts decoding errors and does not read a binary file as text; reads only regular files; lists every name match it did not read with the reason and says `partial` when one could have held something; bounds `max_size` above; and bounds every repetition in its patterns (a 200 KB note of `a.a.a.` or of spaces after `victim id` took minutes).

New suites, `tests/pack-ransom-note-scan.test.ts` and `tests/pack-encrypted-survey.test.ts`, build their fixtures from the formats (addresses checked by their own checksums, offsets checked by slicing the file, node's random bytes, English text, an 8 GiB sparse file whose windows sit past 4 GiB) and assert that no value, fragment or note text is in anything the tools print or name. A third, `tests/pack-ransomware-goal.test.ts`, runs the goal template's acceptance check on small reports. Run against the original tools and goal template, 40 of the 41 cases do not pass (39 fail and the hostile note's ran into its timeout); the one that passes only checks the fixtures.

### Changed: the ransomware-response pack's skills say what each tool shows and does not show

The seven skills are rewritten in the defender's voice, each saying what an artefact shows, what it does not and what has to corroborate it. A staged archive's size is no lower bound on what left, and staging is not transfer; an MFT time is not a deletion time and a service installation is not execution; a missing snapshot or a compromised backup server is not proof of deliberate destruction; a family is not read from an onion address, and a shared tail is an observation; a service stop does not mark the encryption to the second; "these files cannot be recovered" rests on named routes, not on entropy. The first-hour skill no longer fixes the order of the questions or makes exfiltration the regulatory determinant: containment, preservation, impact and notification assessment run in parallel, with the volatile evidence and the management and backup planes in the preservation list. `reporting/for-regulators` keeps the notification clocks apart by their triggers (awareness of a personal-data breach under GDPR and similar laws, a materiality determination, a classification of a major incident) and states no deadline: the legal owner supplies the current text and the number. Skills that need a tool of another pack say "if that pack is loaded" and name it under `mentions:`; the front matter lists exactly the tools and programs each body names, so the pack leaves `tests/pack-links.pending`. The skills' caveat about names the survey cannot see now covers a name that loses its original extension as well as an unchanged one. The pack description, README, goal template and `docs/packs.md` row no longer say the pack fixes the order of a case or serves a negotiation, and "operator" means the authorised human, not the adversary. `requires/host.json` says that no rules ship with the `yara` entry and that the image's inventory records its version.
