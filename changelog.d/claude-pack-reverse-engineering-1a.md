### Security: the reverse-engineering pack's document tool no longer prints a credential a document holds, and the pack stops saying the kernel prevents execution

`doc_probe` printed every external relationship target whole. A target is often a credential (user-info in the URL, a signed query string, a token in the path), and the part names and the caller's own path it printed can be one too. It now withholds user-info, every query value, the fragment and token-shaped text from a target; a token-shaped part name from the part list; and, one path component at a time, the path the caller named, `extract_to` and the paths in its errors (an ordinary Office theme showed 201 of its 259 part names withheld when the whole name was tested at once; the real name behind a withheld one is now written, always, to a private 0600 file the answer names, and to the values file with `write_values`). An extracted part with a token-shaped name is written under a name that gives nothing of it: no head of the token, and an extension only if it is short, plain and not token-shaped. The length of a target is kept. The whole target goes to `doc-probe-values.jsonl` only when the caller asks (`write_values: true`), only in a job, in a file created exclusively with mode 0600 (a second run in the same job is refused by name and the earlier file is untouched; with nothing to write it stays an empty file and the answer says `written: 0`). The answer names the file and says `contains_secret_values`, and the manifest says to run the job with `secret_output: true`. `extract_to` writes in a job only under `$OUT`, creates each part exclusively with mode 0600 (nothing already there is replaced) and says extracted parts can contain secrets.

`pe_info` prints the strings a loader reads from a binary (`DT_NEEDED`, `DT_SONAME`, `DT_RPATH`, `DT_RUNPATH`, the interpreter, an install name, linked libraries, the export name); a run path is where a binary looks for code and can carry a repository address with user-info or a signed query. These fields are withheld when they carry user-info, a query value or a token-shaped string, with where the string lies in the file and `withheld_fields` naming them. Import and section names are not withheld: the token-shape rule hid 128 of 6,363 real imported function names (mangled C++ names) and none of 496 real library names, so withholding function names would hide evidence. `entropy_map` and `fuzzy_hash` print measurements and digests and echo the path the caller named; none prints document content, a string table or a resource.

The README said the harness enforces non-execution at the kernel. A no-exec mount reduces accidental direct execution of a binary; it does not stop an interpreter from running a script or an application from evaluating a macro (the worker prompt says so). The README now says that, the tools' own texts no longer make the claim, and `triage/quarantine` follows in the skills change.

### Fixed: the reverse-engineering pack's tools stop returning plausible wrong answers

- **static-binary** took "complete" from the exit codes of its two child tools and wrote "complete static structure" into the index whenever `binary.json` was not empty, although `pe_info` can exit 0 with a header problem, a failed import table or one Mach-O slice of several. Each child's output now goes straight to a file; the recipe reads the parser's own `status` (complete, partial, failed, unsupported) and writes `coverage.json` with the parser statuses, the warnings (the parsers' problems), the limits hit, the errors and the structures not read; the index says what each file is with its status beside it and names the complete entropy profile and every table a parser kept whole. The entropy profile went to the caller's `$OUT`, outside the recipe's directory and outside the index; it now goes to the recipe's own directory. Detection checks enough structure to tell an executable from a coincident magic (a whole ELF header with a class and a byte order; a plausible universal-binary table whose first slice begins with a Mach-O magic, so a Java class file is not a Mach-O). A second run into the same directory had replaced the first result with a smaller one (a 12,757-byte `binary.json` became 0 bytes): each pass's output is now created exclusively under a new name when the name is taken, the index names both results and says which is from an earlier run, and `coverage.json` names this run's files; an empty stderr is not left behind. `recipe.json` offers every magic that `detect` accepts (thin big-endian and 64-bit fat forms were never offered to the recipe in the derived catalogue).
- **pe_info** read optional-header fields against the file's length instead of the header's declared size, bounded the import table by the file and not by its section, rejected a 52-byte ELF32 header, took "stripped" from a section count of zero, found an ELF's dependencies only through sections named `.dynamic` and `.dynstr`, read only the first slice of a universal Mach-O (both fat magics as big-endian), listed `LC_ID_DYLIB` as a linked library and missed weak and re-exported ones, named a nonzero certificate-directory size `signed`, and ended with a note that said a large virtual size with high entropy "is packed". Every field is now read through checked ranges inside the structure that holds it; every answer carries a status (complete, partial, failed, unsupported), the problems found, the limits hit and the structures not read. `signed` is `certificate_table_declared` with the table's offset, size and first entry's header (presence only: nothing is verified). An ELF's dependencies come from `PT_DYNAMIC`, then an `SHT_DYNAMIC` section found by type, with the string table found through the `PT_LOAD` that maps `DT_STRTAB`; `stripped` is true only when section headers are present and none is an `SHT_SYMTAB`, and null when they are absent. A universal binary lists every slice in the byte order its header declares (FAT_MAGIC and FAT_CIGAM, 32- and 64-bit), with its own load commands, linked libraries, segments, entry offset and code-signature location; thin Mach-O files of both widths and byte orders are read. Entropy is measured in chunks against a work budget, a table longer than the answer holds is kept whole in a file, and `size_entropy_pattern` replaces `packed_shape`. A range that runs past the end of the file (an ELF segment or section, a PE certificate table, a Mach-O segment or code signature) is a problem that names the range and the bytes missing, the answer is `partial`, and an entropy measured over a clipped range says over how many of how many bytes (a truncated ELF32, a signed driver cut short and a cut arm64 slice had all been `complete` with no problems). The section behind an RVA is found by address in a sorted list (65,535 sections and 30,000 thunks had taken 170 seconds, past the manifest's 120), and the tool has its own clock (`max_seconds`, default 100): a read that reaches it stops, keeps what it read and says so. Mach-O load commands are a table kept whole in a file like sections (a file with more than 1,000 was `complete` and cut), a command size that is not a multiple of 4 or 8, a library name with no terminator inside its command and overlapping slices are problems, a Java class file whose version reads as 45 to 100 slices is `unsupported` and not a Mach-O with invented slices, and more than 65,535 program headers is a limit hit. `compile_timestamp` is `header_timestamp_raw` and `header_timestamp_utc` with a note (reproducible-build DLLs show 1982, 2043 and 2064); an overlay that is exactly the certificate table says so (`overlay_is_certificate_table`); `with_imports: false` says the import directory was not read; every answer, a refusal included, carries `problems`, `limits_hit` and `coverage`, and a directory, a pipe and a missing file are told apart.
- **doc_probe** read every relationship and code-related member with no budget; found relationships with a regular expression (single-quoted attributes and a prefixed element were missed); skipped an unreadable member without a word; counted `/Type /Page` as a page count and `/Encrypt` as "encrypted"; and told the agent a file "has been renamed" and that an external target "fetches when the document opens". A member is now read under a per-member budget, a total budget and an expansion-ratio limit, and a member that is over a budget, encrypted, corrupt or unsupported is counted and named, never skipped and never extracted cut. Relationship parts are parsed, one relationship at a time (nothing is collected, and those read before a malformed element are kept), by a namespace-aware XML parser that refuses a DOCTYPE. The ZIP end record (zip64 included) is read by the tool, so no Python version's validator decides what a ZIP is. PDF and RTF results are marker observations with offsets (a PDF name ends at white space or a delimiter: `/JS` is not `/JSON`); the OLE answer is byte markers by encoding. An extension that disagrees with the code-related parts is said as a disagreement ("renaming history, application acceptance and execution are not established"). A member is read only if it is stored or deflated (OOXML uses no other method): the standard library decompresses a bzip2 or LZMA chunk whole, before any budget can act (a 1,265-byte `.docx` with a forged size reached 2 GB and, under a 1 GiB cap, was killed with no answer), so any other method is counted unsupported and never opened. The archive is seen up to the end record the tool chose, so the listing and the counts come from the same directory (a directory hidden in another's comment had been listed as complete); more than one end record, a directory that holds more or fewer members than the end record declares, duplicate member names and members marked encrypted are problems; a directory is bounded by its size as well as its count. A PDF stream behind a filter is not searched, so the answer is `partial` and says how many; the PDF header may follow up to 1,023 bytes; marker offsets in the file are capped at 100,000 with the counts going on; the tool has its own clock (`max_seconds`, default 100) and says when it stops; an RTF header may follow leading bytes and class names are capped.
- **entropy_map** wrote `entropy-windows.tsv` into `$OUT` whatever it measured, so a job that measured two files lost the first profile; compared the threshold on the rounded value (a window of 6.99999 bits counted as 7); kept every window in memory and in the answer without an `$OUT`, and every high-entropy run in memory. The complete profile is now always a file, created exclusively under a name derived from the source or chosen by the caller (a taken name gets a new one and the earlier file is named); the answer holds a preview, the bytes processed, the final window's length, the schema version and whether the pass finished; the threshold is compared unrounded; runs are held up to 1,000 and the whole list is a file past that. A file it cannot open is `failed` and creates no profile; a pass that reaches its own clock (`max_seconds`, default 270, below the manifest's 300) stops, the profile holds the windows measured so far and the answer is `partial` with `bytes_processed`.
- **fuzzy_hash** ran ssdeep and tlsh with no time limit and unbounded captured output, took the first line of whatever they printed as a digest, and returned a null distance with a null reason when one file had no digest. Each engine now runs under a time limit with its whole output in a log file; a digest is accepted only with its own shape; every engine's result is a status; a comparison that cannot be made names the input that prevented it; each program's argv and what its version command printed are recorded. A TLSH digest is accepted only with one of the lengths its encodings give (70, 74, 134 or 138 hexadecimal digits after an optional `T1`); a row that names another file, and more than one row, are not read as this file's digest; ssdeep's digest of an input too small to hash is `insufficient_input`; a stop signal keeps the digests already computed in its last word.

- **Processes**: the harness ends a tool that runs too long, or is aborted, by killing the tool's process group, so a program the pack starts in a session of its own would go on running and writing after the tool is gone. `fuzzy_hash` starts ssdeep and tlsh, and the `static-binary` recipe starts `pe_info` and `entropy_map`; each is started in the tool's own group, asked to die with its parent on Linux (`PR_SET_PDEATHSIG`), ended with what it started (a walk of the process tree) at the tool's own deadline, and ended by SIGTERM, SIGINT and SIGHUP, after which `fuzzy_hash` answers that it was stopped (with the digests it had finished) and the recipe leaves a `coverage.json` that says so with the index of what had been written. The recipe writes `coverage.json` from its first moment (it says it has not finished) and replaces it after each pass, so a recipe ended without a last word still leaves one. The recipe's own budget (`--seconds`, default 570) is handed to each tool as that tool's clock, so a recipe killed alone (the evidence catalogue ends the recipe, not its group, at its limit) leaves no tool running past it where the kernel does not end the child with its parent (macOS). The block of code is the one the network pack carries (`# BEGIN SHARED PROCESS`), and `doc_probe` and `pe_info` carry the network pack's current withholding block. `tests/pack-re-process.test.ts` kills the tool's group the way the harness does and asserts the engine and its child die, pins both shared blocks to the network pack's text, and refuses `os.setpg*`, `os.spawn*`, `os.popen`, `pty` and `multiprocessing` in the pack as well as `start_new_session`.

A new suite (`tests/pack-re-*.test.ts`, 147 cases) builds its fixtures from the PE/COFF specification, the System V gABI, `<mach-o/loader.h>` and `<mach-o/fat.h>`, the PKWARE APPNOTE, the OPC relationship schema and the literal tokens of PDF and RTF; 141 of them fail or hang on the tools and recipe before this change. The other six hold behaviour that was right and must stay so: a missing program is reported in the words the harness reads, the builders lay structures at the specified offsets, and a file name that is not UTF-8 never raises (two cases, reported as skipped where the file system refuses such a name, as macOS does).

### Changed: the reverse-engineering pack's manifests, README and requires say what is and is not measured

`pe_info` and `doc_probe` carry a `use` (magic and extensions) so the library hint offers them for the files they read; every tool's description says what it reads, what it does not and what it does not show (no signature verified, no packing determined, no resolved PDF action). The README counts four tools and `file_type` from the base pack (it said five). `requires/host.json` declares `readelf` (binutils, as `strings` is; on macOS it is keg-only and not on PATH, and the entry says so), says that tlsh has no Homebrew formula (the CLI is built from the upstream release or run in the re image), says in capa's entry that a match is a hypothesis over features it extracts (it said capa reads code "not from its strings"), and gives `gcc` and `make` an `unreferenced_ok` reason in `pack.json`. FLOSS and oletools stay unpinned: no package metadata for either is available offline.
