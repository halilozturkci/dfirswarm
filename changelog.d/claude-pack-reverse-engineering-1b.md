### Changed: the reverse-engineering pack's skills say what each artefact shows and does not show, and stop contradicting the worker prompt

`triage/quarantine` said the harness holds the extraction directory no-exec "so a sample cannot run even if something tries". A no-exec mount does not stop an interpreter from running a script or an application from evaluating a macro (the worker prompt says so); the leaf now says that, never to run evidence or build source it supplied, to cite the isolation the run recorded, and that an upload discloses the sample (what follows depends on the service, the case authority and the rules that apply) where it said an upload "breaks the custody chain". The other six skills overclaimed in the same way and are rewritten in the examiner's voice, as observation, what it shows, what it does not show and what corroborates it, with bounded negatives, no version fact and a Sensitive output line where a tool or a program can reach a secret:

- an entropy value "is packed" (the entropy tool's own note said otherwise), a section layout or an import combination "means" injection or ransomware, the compile timestamp is checked against the Rich header as an independent clock, a valid signature "means a stolen certificate", whole-file strings are resource parsing, an `OriginalFilename` matches a Prefetch entry: now a triage feature, a declared directory, an editable claim, each with what corroborates it (and `pe_info.signed`, which the skill already said verified nothing, is `certificate_table_declared` in the tool);
- missing section headers and removed symbols are conflated, a static binary "runs on any distribution" and is "what a dropped tool usually looks like", UPX recognition and unpacking are routine, a build ID "identifies a binary across rebuilds and strippings": now the loader's view (program headers, `PT_DYNAMIC`), `stripped` null without section headers, packing as a hypothesis with a derived copy and a stopping rule, a build ID as a lead;
- FLOSS recovers "the strings the sample hides", a cross-reference is a connection, no reference means unused, decoding has no execution boundary: now derived strings, a reference as an inference bounded by function discovery, and decoding by non-evaluating steps in a job;
- capa reads "the code, not the strings", few matches on a high-entropy file "means packed", a mutex is "often unique to a family", the analysis says "what it was built to do": now rule-supported hypotheses (which kinds of feature a rule used is left to the rule and the version run), the rule set and version recorded, absence as "no matches under this tool, rule set and scope";
- a `.docx` holding a macro part "has been renamed", an auto-execution name decides whether a click is needed, an external relationship "fetches when opened", `/AA` and `/OpenAction` "run on open": now a disagreement, a procedure name, a target and a type, and markers that resolve nothing;
- YARA rules that "will still be right next month", anchors that "survive a rename and most repacking", system DLLs as the negative corpus, and nothing said that `yara -s` prints the matched bytes, which can be a credential: now what a rule claims, what was tested, and a job with `secret_output: true` where they can.

The seven skills are twelve leaves within the skill size budget (at most 800 tokens, estimated as bytes over 4.245, and 300 lines; the largest is 2,877 bytes): each decision-rule leaf opens with "Use when ... Not for ...", and five second-level leaves (`pe/signature-and-resources`, `elf/packing-and-identity`, `strings/decoding-and-similarity`, `documents/external-and-active-content`, `rules/authoring`) are opened only when the leaf above says "Only if". `needs` is at most two deep. `timestamp_decode`, `entropy_map`, `file_type`, `pe_info`, `readelf`, `r2`, `strings`, `floss`, `ssdeep`, `tlsh`, `upx` and `yara` are each named where the body uses them and listed in front matter, so the pack leaves `tests/pack-links.pending` (14 lines) and holds under `PACK_LINKS_STRICT=1`. The sample-triage goal no longer asks "what it was built to do" or "whether any of it is packed", and asks for capability hypotheses with a locator and the limits of the analysis; its checks are unchanged. A new suite, `tests/pack-re-skills.test.ts`, holds the size and shape rules, that every tool field a skill names is a field the tool writes, and that the old overclaims are gone.
