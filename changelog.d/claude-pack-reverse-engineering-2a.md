### Added: the reverse-engineering pack reads document and PE structure, and runs capa and FLOSS when they are installed

Phase 2 of the pack review, the tools. Nothing is executed and nothing is verified: each tool reads bytes through checked ranges, under budgets, and says what it read and what it did not.

- **doc_structure** reads what `doc_probe`'s byte search cannot (stdlib only). An OLE compound file: the header, FAT and mini FAT, the whole directory (every entry, the ones no storage reaches marked `reachable: false`, each stream's chain checked against the file), the VBA project (the `dir` stream is decompressed, each module's stream and the size of its compressed and decompressed source are listed; source is written out only with `extract: ["vba"]`, byte for byte, or not at all when it passes a budget), and the encryption structures the Office formats record, read from the structure and not from a byte search: EncryptionInfo (standard and agile; scheme, algorithm, key size, hash and spin count), the Word FIB flags and table-stream header, the Excel FILEPASS record and BOUNDSHEET sheet kinds (an Excel 4.0 macro sheet, a very hidden sheet; after FILEPASS a sheet's name, visibility and kind are ciphertext, so only the count and each sheet's stream position are given), the PowerPoint Current User token. A name the Office formats give a stream is read only from a stream, a directory name of an odd length or without its NUL is a broken entry and not a decoding failure, a VBA storage whose `dir` is missing or is not a stream is listed and said, two entries of one name in a storage (names compare in upper case, [MS-CFB] 2.6.4) are a problem and every copy of a VBA storage's `dir` and module streams is read (each `dir` a project of its own), a VBA stream no `dir` names is said, and an entry type [MS-CFB] does not define, an unallocated entry a tree reaches and a root entry size the mini stream does not match are each said. OOXML: the central directory (part names compare case-insensitively, so two spellings of one part are a duplicate, said, each copy of a part the tool reads is read, and when one spelling of a name is withheld every spelling is; a local header that disagrees with its central entry is said, and a name marked UTF-8 that is not is read as CP437 and said instead of losing the archive; a Unicode Path extra field (0x7075), which Python 3.12 and later honour and 3.11 ignores, is hidden from the reader so that every member is listed by its central directory name on every version, and the tool reads the field itself, shows its name beside the central one, and says a field that renames a member or is not UTF-8), `[Content_Types].xml`, the document, workbook and presentation protection elements, and the VBA project: every member the content types (an Override, or a Default extension for a part with no Override of its own) or a `vbaProject` relationship declare as one, every member named `vbaProject.bin` by either name, and every other member that begins with the compound file signature and holds a VBA storage, each read as a compound file and listed with `selected_by`; a declared part that is absent or not read is a problem and the answer is partial, and so is a member that begins with the compound file signature, that nothing declares, and that a bound (`max_stream_bytes`, the ratio, the total) keeps unread. PDF: the cross-reference chain (tables, streams with a PNG predictor, hybrid files, every `/Prev` revision, a rebuild by scanning when the chain is unusable), every object's dictionary and stream filters, object streams, the encryption dictionary named by the current trailer, the catalog's actions with the key that reaches each (and the action objects nothing reaches; a direct action inside an annotation or field that nothing reaches is not listed; an action object is known by its number and a direct action by the place it sits, never by a Python object's identity, so a file of 4,000 links has 4,000 actions on every run; each step of every walker counts against `max_objects` and reads the clock, a `/Next` chain visits each action once, a link back to an earlier action of the chain or an outline that returns to an object is a named cycle and two links that reach one action are said, and in an encrypted file a target string is marked `ciphertext: true` and given by length, and `pdf:<n>` is not decoded while `pdf-raw:<n>` is written marked ciphertext), embedded files, and the page tree as two named numbers (the root's declared `/Count`, the leaves traversed) instead of a page count. An object whose header is in the file and that the newest cross-reference section frees, or that no section lists, is counted in `objects_scan` (`headers_freed_in_newest_chain`, `headers_not_in_the_cross_reference_chain`), and an action dictionary in one is listed with `outside_chain` (counted in `actions.outside_chain`) and makes the answer partial. RTF (also a file that begins with `{\rt`, as Word reads it): groups, nesting, control words counted by a tokenizer that honours `\binN` (a word with a capital letter is no RTF control word: counted, never printed; every word is a row of `rtf_control_words`), object groups with their class, the hex length of their data, the signature it begins with (named, no byte printed) and the decoded OLE 1.0 object header (a payload that is a compound file is read as one), fields by the field type they begin with (when it is an ECMA-376 field type) and templates, by length, each a row of a table, a field inside another field's instruction or a template included; in a captured name, instruction or template a `\'xx` is the byte it names, a `\uN` is the character N and the `\ucN` fallback characters after it are dropped, and a carriage return or line feed is dropped, as RTF readers do, before the text is matched or withheld; an OLE 1.0 class name written as UTF-16 in its ANSI field is read as UTF-16. A password verifier, salt, hash or encrypted key that a structure holds is reported by length and is in no answer and no file the answer names, and no key is tried (not even an empty password). Every key and every value the tool prints or writes (the answer, each table file, each list file, a failure) goes through two steps of one shared block. The sanitiser withholds by shape only. It withholds user-info, to the last `@` before the host (a password may hold `@`, and in a `scheme://name:` URL also `/`, `?` and `#`, read to the last `@` of the same whitespace-delimited token unless the password begins with up to five digits and then one of them, which is a port; a `file:///` URL is not user-info; also a `name:password@` with no host after it, and in a URL target, whose path then goes through the same rules as any string), the value of a secret-named key after `=` (`Password=`, `Pwd='...'`, `AccountKey=`, `token=`, `pass=`, `pw=`, `auth=`, `credential=`; `pass_word`, `pass-wd` and `pass_phrase` are `password`, `passwd` and `passphrase`) or after `:` for the password and key names (`password: ...`, `"AccountKey": "..."`, `x-api-key: ...`; also `secret_key`, `private_key`, `psw`, `pswd`, `sig`, and a quoted JSON `"token"`, `"secret"`, `"credentials"`, `"auth"`), quoted (to the closing quote; a quote nothing closes is dropped and the rest is the value) or not (to `;`, a space or the end, so that a `,` `&` `<` `>` inside a password stays in it; a value made only of `%` conversions (a format), of `*` (a mask), or of `${NAME}` or `%NAME%` (a variable a file names) is a placeholder and kept, in an element only when its text ends there, so that `*<8r...` is a value and not a mask; the name, the quote and the gap may be written as a file writes them inside another format: with an escaped quote (`{\"password\": \"...\"}`, a backslash doubled again where a cell prints it), as an entity (`&quot;`, `&apos;`, `&#34;`, `&#39;`), with a tab or a tab as written (`\t`, `\x09`) around the `=`, as an attribute pair (`<add key="Password" value="..."/>`) or as an element (`<Password>...</Password>`, also `&lt;Password&gt;...&lt;/Password&gt;`, with attributes in the open tag, `<Password Type="x">`, and as a .NET setting, `<setting name="Password"><value>...</value>`: the text of an element is withheld to the next `<` or `&lt;`, to the end of the line or to the end of the text, whatever it holds and however long it is, so a `>` in it, a missing closing tag or a value of 700 characters does not leave it printed; text that begins with white space is a value only when a closing tag follows it, so that prose such as `the <secret> is shown` is kept, and text that begins with a `<` that is no tag is a value that begins with one); not read: a value that holds a raw `<` after its first characters (XML text cannot: it is withheld up to the `<`, as `;` ends the value of `Password=`), a value that begins with a complete tag (`<ab>...`, read as markup), a value in `<![CDATA[...]]>`, a name in another language or another spelling (`Kennwort`, `mot_de_passe`), a value on the line after its name, and a value nested in an escape deeper than a cell's), a PEM body after its header (also glued to it), the token families of the shared block, in the whole text and in each `/` component, a prefixed token with the rest of the run it ends inside and a JWT's payload and signature after a `.` (a token glued to another), a withheld token with the random-looking pieces joined to it by `/` (an empty piece, as `//` makes, inside a window), base64 joined by `/` (a window of whole `/`-pieces, 16 to 64 characters, whose character class changes at 0.45 of its characters or more, with no piece a plain word, and padded base64 across `/`), a token head (an AWS key id's in capitals wherever it stands; a GitHub, Slack or `sk-` head of four characters after no letter or digit, of twenty anywhere, so `Risk-Assessment` and `highs_lows` are words), and the whole of a text whose copy without NUL and other control characters, their `\xNN` escapes, spaces other than U+0020, the line and paragraph separators, the braille blank, the Hangul fillers (U+115F, U+1160, U+3164, U+FFA0), zero-width, soft-hyphen, bidi and combining characters, with full-width forms folded (NFKD), holds any of these; the same copy is also made after the UTF-8 that a tool read as Latin-1 or CP437 is put back, so a token split by the three bytes of a zero-width space shown as three visible characters is found. A backslash of the file (written doubled) is a character of its piece, not its end, so a password holding one is read whole. A string a file's address points into the middle of a token run (pe_directories) goes through the sanitiser whole, its head is withheld after. Its result is a fixed point. The backstop, behind it at every write (it tests with the sanitiser's own rules: it catches a field that did not pass through the sanitiser, not a shape the sanitiser misses; a result the sanitiser settled on is known clean and is not read again), withholds any key or value the sanitiser would still change, a number of 32 digits or more and any value JSON does not carry, counts it in `withheld_by_final_check`, names it in `problems` and makes the answer partial: with the sanitiser taken out of a real call and raw canaries injected into the answer and every table row, nothing of them reaches stdout or a table file. A name, key or target longer than 2,048 characters is given by length only (the whole goes to the values file with `write_values`, in a job, and to a private names file), no message quotes bytes of the file (a token is described by its length and offset), a table or file name holds no text of the document (nested compound files are rows of one `ole_nested_directories` table; the digest that names a paging file is taken over the path as it is printed), two keys withheld to one text are both kept (also where a file's names are counted: object types, filter chains, crypt filters, annotation subtypes), a `<` of a file's key is written `\x3c` so that no text of the file reads as a marker the tool writes, a file key spelled `<key>_not_shown` is kept beside the spill file's, a class id whose bytes read as text (a run of nine token characters, or ten in all) is withheld, a `mailto:` address with a password in it has the password withheld (to the last `@` within 512 characters, found in time linear in the text: a password of more than 512 characters in a `mailto:` address is not withheld by that rule; an Override's part name, a name-tree key and an embedded file's name are given by their length past 2,048 characters like any other name), and no list in the answer is longer than the larger of `limit` and 100 items (a longer one is written whole to a file named beside it; past the first 20 nested compound files their VBA projects and modules are rows of `nested_vba_projects` and `nested_vba_modules`). The shared withholding block finds a span in a time that grows with about the cube of the text (a 13 KB name took 44 s); it is not edited (its copies are held equal to the network pack's), and these tools bind a linear version of its span finder that a test holds equal to it on generated text. Every stream is read under budgets (a stream, all streams, an expansion ratio, entries, objects, nesting depth and the clock): each filter decodes in pieces, reads the encoded bytes where they are in the file, and holds its output to the budget before it is allocated; an object stream read again after it left the cache is counted against `max_total_bytes` once. What the PDF parser keeps of what it parsed is held to budgets of its estimated size (80 bytes a value plus the bytes of its strings and names as Python holds them: a name at one, two or four bytes a character by its widest one, a dictionary key twice): one parse reads at most 250,000 values and holds at most 64 MiB so estimated (past either, a named limit), and the object cache, the objects kept for the trace and the decoded object streams are each bounded, oldest out first, an object not kept being read again when it is needed; trailers keep only the entries the reader uses. The tests hold the memory shapes of the reviews (seven 999,000-value members in each of four object streams of a 118 KB file; 33 objects of 240,000 values) under 400 MB of peak memory; they are tests of those shapes, not a proof of a bound for every file (measured: a 50.9 MB file of astral-character names, 657 MB before the byte count, 364 MB, complete; a 258 MB one, 1,150 MB, 509 MB, partial with the parse bound named; the file's own pages count in that figure). The PDF parser reads the file in place (a window is a pair of offsets, not a copy) and charges every piece of input it walks (strings, hex strings, names, numbers, comments, white space, values) to one budget per object over every window it is retried in and to one budget for the call, reading the clock as it goes; a failure that a larger window cannot change is not read again, a dictionary padded to the window's edge is read again in a larger window before it is taken for one without a stream, and a budget or the clock reached is a named limit and the status is `partial`. In a file whose cross-reference chain cannot be used, the search for trailers has a share of the scan budget of its own and reads a trailer dictionary to 1 MiB at most, so a tail of junk `trailer` keywords ends that search, named, and the census, the catalog and the actions are still read. No digest of an extracted object is printed (a hash of a planted token confirms it); with `write_values`, in a job, it goes to the values file.
- **pe_directories** reads the PE data directories `pe_info` declares and does not read: every export (ordinal as base plus index, RVA, section, name through the ordinal table, forwarder), delay-load imports (the RVA form and the old virtual-address form), the TLS directory with each callback and the section that holds it, the resource tree (type, name, language, size, file offset; `extract: ["resource:<row>"]` writes a row exactly), the version information and the manifest's requested execution level, the CLR header and the metadata root's version string and streams (the metadata tables are not read, so there is no assembly name), the debug directory with the CodeView GUID (withheld when its bytes read as text), age and PDB path (with a REPRO entry no stamp is rendered as a time), and the Rich header's raw entries. Each delay-load name table is read once, so descriptors that share one do not multiply its rows; a section whose PointerToRawData is not a multiple of FileAlignment (PE/COFF requires one of an executable image) is listed and is a problem, and so is a FileAlignment outside 512..64K that is not equal to a SectionAlignment below the page size; the reading rule is stated beside them: with FileAlignment of 512 or more a value that is not a multiple of 512 is read rounded down to 512, any other as written (PE/COFF says nothing of rounding, so readers differ). The problem list's cap is tested before a message is withheld (a 1.4 MB PE: 21 s before, 4 s after, on the machine the fix was measured on). A tool-output directory reached through a symbolic link is refused in both tools; `doc_structure` refuses to run, as JSON, under a Python older than 3.11. Every bound that is reached is a limit. The clock is read at every export, delay-load name, resource entry, TLS callback, debug entry and version string (it was read once in 4,096 names, and a file of 5,000 exports of 2,000 characters of `a:b@` ran for two minutes at `max_seconds` 5); an export, forwarder or delay-load name of more than 512 characters is given by its length only (a longer one is in the values file with `write_values`). The answer and its files go through the same one withholding step as `doc_structure`'s (two version string tables whose keys withhold to one text are both kept), and no digest of an extracted resource is printed. An export, a callback, a strong-name flag or a PDB path is reported as a declaration or a claim.
- **capa-floss**, a recipe that is not run automatically: for a PE or ELF it runs `capa -j` and `floss -j` if they are installed, each in the recipe's own process group with its output going straight to a file, and keeps the whole JSON, stderr, argv, what `--version` printed and the exit code of each. An engine that is not installed, cannot be executed, exits non-zero, is stopped at its time limit or prints something unreadable (for FLOSS: no `strings` mapping of the kinds the recipe reads) is a named status of that engine, and the recipe is `partial` or `failed`, never `complete`. capa's rule set (`meta.analysis.rules`) and FLOSS's `enable_*` flags are recorded, and a string kind whose flag is false was not run: the FLOSS result is then partial, as an empty list of it is not "none found". The receipt, the index and `matches.tsv` pass the same sanitiser and backstop as the tools; the receipt's `withheld_by_final_check` counts that receipt's fields (it was counted again at each rewrite). An engine's JSON over 32 MiB (parsed JSON takes up to about twenty-five times its size) is kept whole and not read, and that engine is partial; `--version` runs within what is left of the recipe's time; the engines' own files (`capa.json`, `floss.json`, the stderr files) are mode 0600 and a directory the recipe makes is 0700; a `--target` that is not a JSON object with a list of paths is a JSON refusal; on Linux the recipe is the subreaper of its engines, so a process an engine started in a session of its own and left running when the engine exited is ended before the receipt is written (the engine is then `partial` with `orphans_ended`); macOS has no such call and an orphan of an engine that exited by itself is not found there (an engine that is still running at the deadline is killed with its whole tree on both); an `--out` that cannot be written is a JSON failure. A second run into the same directory writes its receipt under new names and leaves the earlier `coverage.json` and `index.tsv` as they were; each run's `index.tsv` names its own receipt as this run's and lists only the files an earlier run left as earlier. What an engine prints is withheld whole and then cut, and the keys of its JSON are withheld. `matches.tsv` lists capa's matched rules (name, namespace, ATT&CK ids, count); no string and no matched feature is copied into the receipt, the index or that table. capa and FLOSS are not installed where the tests run, so the suite uses stand-ins that print the JSON shape the recipe reads or fail in one named way; it says so, and holds only the recipe's own contract. The `--version` and `-j` arguments are the recipe's assumption about both programs: a program that rejects one fails visibly with its stderr kept.

`max_seconds` is the clock of the reading (default 70, at most 90 in both tools; it was 100 and 110). A row of a table is withheld (the sanitiser, then the backstop) when it is added, under that clock, and kept as it will be printed, so the answer does not pay for it again; what the answer still has to withhold after the reading has until 90 seconds after the call began, and at least 5 seconds after the reading ended (the hard limit is 105, the manifest's 120): a string of more than 200 characters that has not been checked by then is given by its length (`<N characters: not shown, the answer ran out of time>`), the answer says so in `limits_hit` and is partial; shorter strings and the answer's own keys are always checked. The settled result of a string the tool keeps for its answer is remembered whatever its size (it was not above 8,192 characters, so a 2,000-character `a:b@` name, whose result is 16 KB, was read again at every pass), and the ZIP part-name check reads the clock (with it out, the names not yet checked are all given by their length: more is withheld, never less). The lists of a ZIP (the part-name check, the member rows, the list of repeated part names) have 60% of `max_seconds` and each reads the clock inside its loop; the other 40% is kept for the content types, the relationships and the VBA project, which are looked for in an index of the whole package made before anything is listed (so a member the listing did not reach is still found, and a package of thousands of long names cannot use the clock up before its macros are read). Each distinct name goes through the sanitiser once. The repeated part names are counted whole, 100 are listed in `duplicate_part_names` (with the total in `duplicate_part_names_total`), 10 are named in the problems and one problem says how many there are in all, so that a package of a thousand repeated names does not fill the hundred problems the answer has room for. The loops over members and groups that call the sanitiser were each read for the clock: the part-name check, the member rows, the repeated names, the content-type rows (each row is a clocked table add), the relationship parts, the compound-file signature check, the VBA parts, the declared-but-missing names (capped at 10 and counted, where it was one sanitising of a name per name) and the protection parts and the extraction of ZIP members (new checks); the scan for members that are VBA projects was quadratic in their number and is not. A table reads the clock before it counts a row, so that `matched` (and a ZIP's `members.listed`) is the number of rows the table holds and never one more than its file when the clock stops it.  `limit` is at most 20,000 (a larger one is refused, as JSON). A call that has not answered within 105 seconds ends with a partial JSON answer of what it holds (the problems, the limits and the first 100 rows of each table, all of them already withheld) and the exit code 0, and if that is not finished within 5 seconds more, with one failed JSON answer, before the harness's kill at 120; a file the call was writing can be half-written then (a values, table or names file: a row is written in one call and the files are line-buffered, so a call stopped by the limit leaves whole rows, but a last line can still be cut by the stop itself, and the partial answer names each table file it started in `all_results` and says so), and a call that had read nothing yet answers failed. The partial answer is one document: when the reader of the pipe takes no byte for the whole grace (a partial of 3.3 MB, a reader 25 s late) the first 65,536 bytes of it are what the reader gets and nothing is appended (it was followed by the failed document, 65,807 bytes that no JSON parser takes); that is a document cut by the pipe and the call exits 1. A signal while the partial answer is being built is answered with one minimal failed document and the exit code 128 plus the signal (it was answered with nothing); a signal while a document is being written leaves that document cut, as before. Measured (macOS, Python 3.12; wall seconds, CPU seconds close behind, machine load 6-11; the previous head in brackets, measured at load 8-87): a PDF of 1,200 URI annotations, 1,200 Launch annotations and 1,200 file specifications of three 2,000-character `a:b@` fields (12 MB) 32 s at the default (84-101 s) and 43 s at 90 (failed at 105 s); a package of 2,300 members with names and content types of 1,900 characters (4.4 MB of central directory) 70 s at the default (89-101 s) and 90 s at 90 (failed at 105 s); a PDF of 30,000 name-tree keys that share one file specification 70 s (79 s) and 90 s (98 s); a PE of 60,000 export names that share one 500-character name and 2,000 debug entries 70 s at the default and 90 s at 90; a PE of 19,000 resources that share one 2,000-character type name 3 s and complete (77 s); a package of 1,150 pairs of members whose 1,900-character names differ only in case (2,301 members, a 9 MB file, a 20 MB answer) 21 s (CPU 21 s) at the default and at 90 with its content types read, where the lists ran to the 105 s alarm at the default (the repeated-name loop read no clock, and the content types, relationships and VBA project after it were never reached), 15 s on Linux (Docker, `--cpus=1`, Python 3.11; 105 s and a 60 MB answer before); on Linux (Docker, `--cpus=1`, Python 3.11) a PDF of the first kind with Win-launch and name-tree rows (22 MB) 45 s at 90 (failed at 105 s), the 2,300-member package 89 s and complete at 90. The worst answer phase seen before this round was 20-31 s; now every call of these files ends at its reading clock plus a second or less. Reading the clock was also added to the TLS callbacks, the VBA modules and the RTF templates; every other loop that is not bounded by a small constant of its own was read for the same omission, and the ones left without a check are bounded by what the file can hold (a version information block is 64 KB at most: 8,000 empty string tables took 3.7 s; OLE entries by `max_entries`, 20,000 hostile names took 1.4-3 s; Excel sheets by 1,000). The sanitiser takes time linear in the text: about 2 s per MB on its worst unit (a megabyte of `{\"password\": \"x` repeated; 1.2-2.3 s measured at load 8-87), 0.1 s per 64 KB, and a string in the tools is held to 2,048 characters before most paths. The answer is written after it is built, and a signal while it is being written ends it there (the first document is cut, no second one follows). SIGINT, SIGTERM and SIGHUP end `doc_structure` and `pe_directories` with one JSON answer and the exit code 128 plus the signal (they were a traceback and silence); a file the call was writing can be incomplete then. `doc_probe` and `pe_info` (earlier changes) keep their clock of 100 s (at most 110) and have no hard limit: their answers are small. The answer and the files it names have no byte bound, as nothing is cut: the 835 KB PE of 60,000 export names wrote 520 MB under `$OUT` in a job at the old clock, and a hostile file can still write a large answer (a `limit` of 20,000 on a PDF of 9,000 embedded files, 30 s: 66 MB; the 2,301-member package above: 20 MB on macOS, 60 MB on Linux before this round's cap on the repeated-name list), so a file of unknown origin is read with a small `limit`.

Fixtures are built from the format specifications and not from the tools' output ([MS-CFB], [MS-OVBA] with a compressor that writes literal tokens and a hand-made copy token, [MS-OFFCRYPTO], [MS-DOC], [MS-XLS], [MS-PPT], ISO 32000, the RTF specification, [MS-OLEDS], the PE/COFF specification). Hostile cases are named tests, among them one per finding of each review round, a canary harness (a canary of its own in every string slot of a PDF, an RTF, an OLE file, an OOXML package and a PE, each seed mutated so that error paths are reached, every output and file name searched for any nine characters of any canary), a slot harness (74 slots, a string whose address follows a token run among them, each file holding one of 17 shapes of secret, 1,198 files, each read twice, in a job and outside one, once with limit 1 and once with the default, the pairing alternating from file to file, so that each slot meets all four combinations across its shapes: no nine characters of a canary and no six of a password in stdout, stderr, any file or any file name, and nothing left for the backstop to catch), cases that hold the PDF lexer's strings, names, numbers, nesting, comments and white space to `max_seconds` plus two seconds and under 400 MB of memory, and its hex strings to under 400 MB, (an ASCII85 `z` object stream, a filter chain past its ratio, an unterminated object referenced six times, an object stream that fails after a predictor, five million empty cross-reference subsections, a canary in every printable place of each format, case-variant part names, actions past every old slice, a trailer inside a stream, a deleted object an older hybrid stream defines, 2,000 delay-load descriptors sharing one table; a looping FAT chain, a directory tree that returns to itself, a cut file, a decompression bomb in a VBA module, a PDF stream and an object stream, a `/Prev` loop, a four-billion-entry cross-reference subsection, 5,000 nested arrays, 30 million open braces against a one-second clock, 50,000 exports). The shared withholding block of `doc_structure`, `pe_directories` and the `capa-floss` recipe is held equal to the network pack's text, and the recipe's process block to the one `fuzzy_hash` and `static-binary` carry.

What the withholding does not catch, measured (random secrets, seeded; `tests/pack-re-one-way-out.test.ts` holds the first five under bounds about twice these rates, on 400 plants of each in six places). It is a rule of shapes, so some secrets of a covered shape and every secret of another shape are printed: of random AWS-format secret keys (40 characters of the base64 alphabet) that hold a `/`, 1.2% are printed whole and 1.7% have some nine characters printed; of the base64 of 16, 20, 24 and 32 random bytes holding a `/`, 1.4%, 0.7%, 2.9% and 0.1% whole (nine characters: 1.5%, 0.8%, 3.2%, 0.8%). A random alphanumeric of 20 characters is printed whole 44% of the time, of 28 characters 4%, of 36 characters 1%; an AWS-format key in all capitals or all small letters 12%; token families the rules do not name are printed when no other rule catches them (`glpat-` 27%, `sk_live_` 16%, `AIza` 2%, `npm_` 2% of random ones). A plain password with no secret-named key before it, a secret-named key the rules do not list, and a token split across two fields (two names, two table cells) are printed.
