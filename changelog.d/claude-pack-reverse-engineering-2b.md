### Added: the reverse-engineering pack teaches eight more examinations, each with its limits

Phase 2 of the pack review, the skills (stacked on the tools: `doc_structure`, `pe_directories` and the `capa-floss` recipe). Each is a leaf within the skill budget (at most 800 tokens; the longest, `documents/macros` and `documents/pdf-rtf`, are 797.9 and 798.1) that opens with "Use when ... Not for ...", needs `triage/quarantine` only (so no chain passes 1,900 tokens), and ends with what it shows, what it does not show and what to record, plus a "Sensitive output" line.

- `code/static-inspection`: native code read with `r2 -N` (no user settings or scripts loaded, stderr kept in a file) with the frame fixed first (format, architecture, entry point and its address type), the analysis pass named and kept as a setting, indirect calls and unresolved functions counted as gaps, a decompiler's output as a reconstruction, and no project, script or plugin from the evidence loaded.
- `managed/clr`: the CLR header read through `pe_directories` (IL-only against native code beside the IL, which a native entry point or a managed-native header shows and an `mscoree.dll` import does not, `runtime_version` as the header's format version and not a .NET release, the entry point as a token, strong naming as a declaration), a managed file's import table as the loader stub, and the plain statement that this pack has no metadata-table reader, so there is no assembly name or IL to cite.
- `runtimes/go-rust`: runtime artefacts recorded rather than guessed, build paths as claims, runtime and dependency code kept apart from the author's, sparse imports as ordinary, and why plain string extraction and FLOSS need care with strings that are a pointer and a length.
- `runtimes/python-packaged`: a bootloader kept apart from the bundled application, the overlay or resource preserved by byte range with hashes, and a stop when no vetted archive reader or non-evaluating bytecode parser is supplied (`marshal`, `pickle`, `import` and `exec` are never used on recovered content).
- `scripts/static-analysis`: PowerShell, JavaScript and VBScript read with language, host and encoding recorded, source spans kept, data decoded by transformations that do not evaluate, the first layer that needs evaluation named as unresolved, and a call as a conditional capability.
- `packing/static-recovery`: compression, packaging, encryption and "packed" kept apart; entropy, section shape and overlay as leads; a UPX container tested on a copy; an installer or self-extractor treated as an archive, with what `archive_extract` reads (a ZIP with a stub in front) and what it does not (MSI, CAB, NSIS, Inno Setup, RAR and 7-Zip self-extractors) said; a derived copy decompressed only with an output name and a receipt; and a stopping rule that ends static recovery where the next step would need the sample to run, with no steps beyond it.
- `documents/pdf-rtf`: how to read `doc_structure` on a PDF or RTF (the cross-reference chain against a scan, revisions and the counters for objects the newest chain frees or does not list, with the actions found in them; the encryption dictionary of the current trailer, its ciphertext targets and the `Identity` crypt filter that leaves strings or streams plain; actions as an action, the key that reaches it and whether anything does; targets shown redacted, a `Launch` action's `/Win` strings by length; embedded files and their extraction, ciphertext in an encrypted file; undecoded filters; RTF objects by signature, nested compound files, fields by field type or `=` for a formula, in their tables).
- `macho/structure`: a universal binary as several binaries read slice by slice, each preserved by byte range, the entry offset, linked libraries by load command, the code signature as presence only and encrypted segments as unread.

`documents/macros` is now the Office, OLE, OOXML and VBA leaf and points PDF and RTF to `documents/pdf-rtf`; it and `documents/pdf-rtf` ask for `secret_output: true` where a job writes source, targets or values (`olevba`; `extract_to`, `extract` and `write_values` of the tools that take them), not for every call; their sensitive-output lines and `pe/signature-and-resources`'s say the tools withhold by shape only (a secret of another shape is printed, and `pe/signature-and-resources` says when to run with `secret_output`), and `documents/macros` names the OOXML VBA project part by its content type; `triage/quarantine` routes to all eleven examinations; `capabilities/mapping` and `strings/obfuscated` name the `capa-floss` recipe; every `r2` example in the pack runs with `-N` and keeps stderr. The pack README lists the twenty skills and what the pack does not provide (a .NET metadata-table reader or decompiler, a Go build-information reader, a Python archive extractor or bytecode disassembler, a packer-signature detector, parse-only script tooling, a native decompiler, a trust-aware Authenticode verifier). The new leaves name only programs the pack declares: `tests/pack-re-skills.test.ts` fails if one names Ghidra, a .NET decompiler, a Python extractor, a packer detector, an Authenticode verifier or the like, holds the stopping rules and the unavailable-tool statements in place, and checks that every field a leaf names is one its tool writes, observed over fixtures (now with an encrypted PDF, an extracted script and an RTF field and template besides; the PE, Mach-O, PDF and RTF fixtures it runs now include a universal binary with a code signature, a PDF with a script, an RTF with a nested compound file and a section that is far larger in memory than on disk).
