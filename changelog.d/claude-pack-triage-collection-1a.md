### Fixed: the triage tools stop returning plausible wrong answers

- **`collection_id`** answered "disk image, physical image" and returned at once for any delivery with a top-level name ending `.e01`, `.ex01`, `.dd`, `.raw`, `.img`, `.vhd`, `.vhdx`, `.vmdk` or `.qcow2` (a raw memory capture beside copied files was a "physical image"), named the first of KAPE, UAC and Velociraptor whose marker it met as the collector of the whole tree, called a tree with no marker and a top-level `C`, `C$` or `Windows` directory "CyLR or a plain copy", attached the same fixed `cannot_contain` list (no carving, no slack, no inode, no shadow copies, no memory) to every other result, counted a UAC log line "0 errors found" as a failure and any line with `error`, `cannot` or `permission denied` too, never filled `failed_targets` for Velociraptor, kept the path of only the last KAPE log of each kind and read one `uac.log` and one `uploads.json` and no other, and dropped an unreadable directory without a word. It now classifies each object on its own (`delivery.kind` is `logical`, `disk_container`, `memory_capture`, `archive`, `unknown` or `mixed`; a name that says image or raw with no signature behind it is `unknown`, and each row says whether it rests on the first bytes or on the extension only; an 8 KiB `$Boot` and a small nested `*.img` that is a PNG are copied files; a note or a log beside an image is another file and not a second kind), names collectors by the paths of their records (several collectors, several runs; a drive-letter directory is a `layout_clues` entry that names none; a record inside `[root]` or `uploads` belongs to the source host and is not read), and reads each recognised log whole and streamed: KAPE copy, skip and console logs; UAC lines in both the 3.4.0 form (`DBG`, `INF`, `ERR`, `CMD`) and the 2.9.1 form, where an `ERR` is a failure with its line and a command's stderr is counted apart; and a Velociraptor container read from the source of the pinned 0.77.2, which writes no failed upload to `uploads.json` (the failure is in a `results/*.json` upload record's `Error` and in an ERROR line of `log.json`, and the count comes from those). A skip row is kept whole with its locator and the collector's own words.
- **The failure count is `null`, never 0, unless it was read.** `failed_target_count` was 0 for a Velociraptor collection whose upload had failed (status `complete`), for a header-only skip log beside a skip log nobody could read, after a time-limit stop, and beside UAC lines that carried failure words in no recognised form. It is now a number only when every failure-source log was read whole, the walk was complete and no archive went unopened; `failed_targets_seen` says how many rows were read all the same. The rows of a skip log with unrecognised columns, and a binary or UTF-16 log, are no failures (the rows are kept whole in `unrecognised_rows`). The fixed `cannot_contain` list is gone; `delivery.not_observed` lists the kinds of object not seen among the files walked and says what qualifies it (an unknown object, an unopened archive, a hibernation file, an incomplete walk).
- **`collection_index`** published a convention as `original_path` (`root/.bash_history` became `/.bash_history`, a real `/root` directory was removed; `uploads/auto/C%3A/...` lost one wrapper and kept the rest), refused any root with a top-level image name, said of thirty files on one date "an intermediate copy probably dropped the original timestamps, and every timestamp conclusion drawn from this tree would be about the copy rather than the machine", followed symbolic links (a link to a file outside the tree was hashed as an object of the tree), dropped unreadable directories silently, opened `out_file` with `w` before the walk (an earlier file at that name was truncated, and one inside the root listed itself), and promised in its manifest to undo a named stream's colon and a reserved-name escape, which it only noted. It now offers `source_path_hypothesis` (path, method, confidence `low`, `medium` or `none`, the components it could not explain, the other readings; a Linux tree is rooted the same way with or without `root/`, `[root]` may sit below a wrapper, a wrapper that needs the collector's own index is not decoded) and `source_path_observed` only from a KAPE copy log found in the tree, matched on the path relative to that log's own directory (so a file outside it never claims the row; rows that name one source are one observation with every row cited, rows that name different sources, or a sibling that shares the name letters of case apart, are `ambiguous` with every candidate listed), with the log's `ModifiedOnUtc` and `FileSize` raw beside the delivered values. A root that holds an image is indexed and the image says what it looks like. Links are rows that are never followed, special files and empty directories are rows, every object that could not be listed, examined or read is a row and an error and makes the status `partial` (so do a copy log whose rows cannot be used for the mapping, a hash the time limit cut and a file that changed size while it was read), directories are visited in sorted order, and a distribution that puts more than 90% of more than 20 files on one UTC date is `mtime_distribution_anomaly` with counts and no cause. `out_file` inside the collection is refused (decided by identity, so a case-variant spelling on a case-insensitive volume does not get round it, nor `INPUTS/`) and a file already at the name is never replaced (the new one is `name.2.jsonl`, named); the complete census is written to a file in a job, with `out_file`, with `contains` and whenever the inline page cannot hold it, and the typo `sumarryinformation` is fixed.
- **`modified_epoch_ns` is a decimal string.** It was a JSON number past 2^53: JavaScript's `JSON.parse` and the VM's jq 1.6 rounded it by up to 128 ns (it failed on Node 24 on Linux and passed elsewhere only because the old test's microsecond value was a multiple of 64). ### Security: the triage tools follow the secret-safe output pattern

Both tools print paths and the text of collectors' logs, and a path or a UAC command line can carry a credential. They now withhold, in every channel (a path, a log line, a dictionary key, an error, the files the answer names), a string shaped like a BitLocker recovery password (with or without a separator), an access key id, a GitHub, Slack or OpenAI-style token, a web token (JWT or JWE), a private-key block (header, body and END line, or to the end of the field when there is none), a webhook URL, the user-info of a URL up to the last `@` (a password that holds an `@`, a `/`, a `?` or a `#`; with or without a scheme), the value after an `Authorization` header, an `aws_secret_access_key`, a `password=`, a `sig=` or a mysql or sshpass password option, by one block of code carried in both (`tests/pack-triage-shared.test.ts` holds the two copies equal and holds the shapes to a table of strings written from the formats, GUIDs, hashes, cache names and `icon@2x.png` among the names it leaves alone). Each withheld text carries a finding id that is the `finding_id` of its row in the sealed values file. The shapes are few and exact, so a secret of no recognisable shape can still appear in a log: the manifests say to run the tools as jobs with `secret_output: true`; the tools cannot see whether a job was run so (the job service passes them `JOB_ID` and `OUT` and nothing about secret output). `write_values: true` (refused outside a job, created exclusively, mode 0600, before anything is read; a second run in the same job is refused by name and leaves the first file) writes the real strings to `$OUT/collection-id-values.jsonl` or `$OUT/collection-index-values.jsonl`. `collection_index` filters on what it prints: `contains` was matched on the real name, so a withheld key could be recovered one prefix at a time from `entries`, `matches_filter` and the hash counts. It marks a file whose name says it is a credential store or holds credentials (`may_hold_secrets`: shadow and `master.passwd`, iOS `keychain-2.db`, `ntds.dit`, SAM and SECURITY hives and their transaction logs, keys and key stores by name or suffix, SSH, GnuPG, AWS, Docker and Kubernetes files, DPAPI and credential directories, browser stores) and does not hash it unless `hash_credential_stores: true` is given with `write_values: true` in a job, and then the digest goes only to the sealed values file, never to the answer or the index file. A `contains` pattern that repeats a group that itself repeats, or uses a back-reference, is refused before anything is read (the time limit does not interrupt a backtracking search).

### Changed: the triage tool manifests say what each tool reads and does not measure

Each manifest has a `use` (the collectors' marker file names), says what is and is not measured, names exactly the parameters its script reads (`tests/pack-triage-shared.test.ts` holds both to the script) and carries its raised version and the sha256 of its script. In a job the run directory is read-only and only `$OUT` is written: both tools write there, never elsewhere, and a place that cannot be written is a JSON error. The manifest example no longer names an `out_file` outside `$OUT`. Both take `time_limit_seconds` and stop with an answer before the manifest's timeout (raised to 3600). New suites (`tests/pack-triage-*.test.ts`, 82 cases; 2 skip where the file system refuses a name that is not UTF-8 or a case variant) build their fixtures from the formats' own definitions (the EWF, VHDX and LiME signatures, a GPT header at offset 512, the column names of a real KAPE copy log, the UAC 3.4.0 and 2.9.1 line forms and the Velociraptor 0.77.2 container files as their sources write them) or by hand, never from a tool's output. The suites assert that a secret is absent (no 6-character window of the secret part in the answer, the files it names or stderr), not only that a marker is present. The README follows; the skills, the goal template and `requires` are the pack's next pull request. Collector manifests are read only as far as the KAPE copy, skip and console logs, UAC's log lines and a Velociraptor container's `uploads.json`, `results/*.json` and `log.json`; the KAPE skip log's two columns are a stand-in the adapter recognises (no real sample exists here), and `collection_manifest_parse`, `collection_manifest_verify`, `collection_path_map`, `collection_coverage` and the `collection_intake` recipe are Phase 2.
