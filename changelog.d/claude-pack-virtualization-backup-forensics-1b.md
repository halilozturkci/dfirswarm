### Added: the virtualization-backup-forensics pack, second part: the router, seven more skills and the goal template

The skills and the goal template of the pack whose tools came in the previous change. The pack now carries eleven skills (a router, a method leaf and nine decision-rule leaves, the largest 800 tokens or fewer, none over the budget, no `needs` chain over 1,900) and one goal template.

- **`router/start`** says which note answers which question. **`evidence/boundaries`** names the planes of virtualization evidence (guest, VM files, hypervisor host, management server, backup server, repository), says that each has its own clock and administrators, and sets the handling rules: work from hashed copies, read natively, never power on, register, import, consolidate, commit, rebase or restore from an evidence VM or backup, and treat a credential in a configuration as an indicator and not a login.
- **`control-plane/chronology`** (one clock per source; a task has several times; a guest clock is the guest's; an offset measured once does not hold across a restore) and **`hypervisor/activity`** (the five things to ask of a management record; which planes could have recorded an operation; a bounded negative) name what to do with `backup_audit_normalise`'s time fields and with a declared mapping for products it has no reader for; an operation made through a management server may be recorded at both ends, and each export is checked for what it keeps.
- **`snapshots/markers`** reads the candidates `snapshot_chain_check` lists for consolidation and close (an unclean-close flag, a dirty bit, a log GUID, a leftover delta, a running disk that is a delta with no snapshot listed, a lock artefact, a sparse extent no descriptor names) and the corroboration each needs; none is a verdict. **`snapshots/header-markers`**, a second-level leaf it points to, names every other marker the tool raises (a VHD saved-state flag or footer copy that differs, a newline-detection mismatch, a VHD footer or dynamic header, both VHDX headers or both VHDX region tables whose checksums fail, which the tool reads as written and answers `partial` for, a damaged region-table copy or VHDX header read from the other and a VHD whose end footer is missing (the last two `partial`), a descriptor problem, a duplicate CID, a missing or ambiguous parent, parent names that disagree, the three identity mismatches, a missing or short extent, a missing external data file, a cycle, a qemu-img disagreement), each with its observation and the reading to test.
- **`backup/deletion-vs-loss`** keeps four states apart for every object (requested, reported, observed, verified loss) and says which evidence shows each; **`recovery/survivability`** gives the five tests a copy must pass before it is called restorable (it exists, its chain is whole, its bytes are readable and intact, the key or credential to use it is held apart from what was damaged, a restore was tested) and the five positions an object can end in.
- **`snapshots/chain-integrity`** names every `id_check` value the tool prints (`match`, VHDX also `match_via_parent_linkage2`, `mismatch`, `not_available`); **`backup/catalogues-and-retention`** says what the tool does with a declared field it cannot find (counted and `partial` for JSON Lines and XML; a CSV header without the column fails the file).
- **Sensitive output.** Every leaf that names a tool now says plainly what the tools show and withhold: a name, path or id is shown only if it is plain (GUIDs, VMFS and `naa.` ids stay readable), else `<withheld: N bytes, field F>` with the original in the `write_text` file of a job run with `secret_output: true`; hosts and free text have tokens, user-info and the value after `password=`-style names withheld; a short plain password is not recognised. `evidence/boundaries` lists the field types in full: plain means letters, digits, space and `. _ - ( ) + [ ] ' # , & ~ % $` (a path adds `/` and `\`), at most 160 characters for a name, the same grammar as the three tools' manifests and changelog. Its credentials rule also says that a value in angle brackets after a secret's name is withheld unless it is a placeholder word, and that a base64 key with a `/` can still leave a few characters of itself (at most 2 in 1,000 in the tests).
- **The goal template `what-recovery-survives`** asks eight questions, ends with `Recovery position: <state> - <object>` lines in answer 7, and its acceptance check is one `awk` pass that binds that phrase and one of the five states to answer 7's own section (a pattern for the bare words anywhere in the report would not), asks for no minimum number of events, and holds on a 300 KB report under `set -euo pipefail`.
- **Tests.** `tests/pack-virtualization-skills.test.ts` (size and shape rules, the router, the two second-level pointers, the names and fields a skill teaches against the tools' source, every marker kind the tool raises named by its own name in one of the two marker tables, no version fact, no verdict from a marker, `secret_output: true` where a tool can reach a secret) and `tests/pack-virtualization-goal.test.ts` (the check run on small reports and on a 300 KB one under `set -euo pipefail`, with no event minimum). The goal-checks suite's phrase list carries the recovery-position line, so that suite reads this goal's check on a 300 KB report too. `README.md` and the pack standard's table carry the new counts (11 skills, 3 tools, 1 goal).
