### Security: the Windows pack's tools stop printing credentials, tokens and matched bytes

`yara_scan` ran `yara -s`, whose output is the bytes a string matched, and returned them: a rule that found `password=` or a key header put the secret in stdout and in the job log. `browser_history` returned any cell of Login Data, Cookies or Firefox's key database that a query selected, in any encoding (`hex(password_value)`, `substr(value, 1, 8)`). `regkv` returned any registry value, including a SAM user's `V` (password verifiers) and the LSA secrets of a SECURITY hive. All three now follow the secret-safe pattern the encrypted-containers pack set (`docs/packs.md`, "Secrets and sensitive output"). `yara_scan` answers rule, file, string identifier, offset and length, with a finding id; the matched bytes are written only on `write_matches: true`, only when the tool runs as a job (it is told to run with `secret_output: true`), to a 0600 file under `$OUT`, and the request is refused anywhere else; yara's text is read as a stream and dropped, never written otherwise. `browser_history` replaces, in its disposable copy and before any query runs, every text or BLOB cell of a credential column (`logins.password_value`, `cookies.value` and `encrypted_value`, `moz_cookies.value`, Firefox's `metadata` and `nssPrivate`, and any column whose name says password, secret, token, encrypted or card number) by a marker holding only its length, and lists what it withheld; there is no flag to bring a value back and nothing is decrypted. `regkv` withholds the same way a value named for a password, secret, token or credential, a SAM user's `V` and the LSA secrets and cached logons of a SECURITY hive. Each test plants the secret in every encoding the tool could print and asserts it is in neither the answer nor any file the tool wrote.

### Fixed: the Windows pack's parsers stop returning plausible wrong answers, and say what they did not read

- **`lnk_parse`** unpacked LinkInfo in the wrong order (the flags taken for the VolumeID offset), so the local path came out as one stray byte; decoded the ANSI path as UTF-16; and never read the volume serial, the network link or the Unicode offsets. It follows MS-SHLLINK field by field, returns the drive type, serial and label, the share, device name and provider, both path forms, raw FILETIMEs beside seven-digit dates, and says when a read ended inside the structure.
- **`jumplist`** read every DestList version with one 118-byte entry layout. It dispatches on the version (a 114-byte fixed part in 1; 130 bytes and a 4-byte trailer in 3 and 4), refuses another version with a problem and no entries, keeps the pin state and last access exact, returns the access counters raw (their position is not established, so no access count is claimed), pages entries and files like links, calls a customDestinations split a carve, and counts files it could not read. The two DestList tests whose fixtures shared the wrong layout are rewritten from the documented layouts.
- **`amcache_apps`** labelled the file description a version, converted the Unix-epoch PE linker time as a FILETIME (1700000000 became 1601), read the older tree only when the newer was absent, and said it listed "program execution". It reads both layouts and labels each row, converts each timestamp by its own epoch, keeps hashes as stored beside the stripped form, reports a dirty hive and its transaction logs (not replayed), and calls itself an inventory.
- **`browser_history`** named URL summaries `chrome_history` and `firefox_history`, called a copied `-wal` replayed, and guarded writes with a prefix test. It adds `chrome_visits` and `firefox_visits` (every visit with its raw time and microseconds, transition and referring visit), keeps the old names as notes-bearing aliases of the summaries, reports the frames SQLite found and checkpointed instead of "replayed", opens its copy under an authorizer that denies everything but reading, and puts its scratch under the job's `$OUT`.
- **`esedb_query`** accepted an export directory whatever the exporter's exit status, exported the whole database on every call and took the first of several matching table files. It judges the exit status and time limit (a partial export is said to be one and is never listed as the database's tables), exports once per database digest with the exporter's whole output and a manifest, refuses an ambiguous table name with the candidates, numbers rows and keeps repeated column names and any cell whole.
- **`sigma_hunt`** accepted any result file in `out_dir` (an earlier run's, after a failed engine), ranked every level word it did not know as the lowest (Hayabusa's `crit` and `med` were dropped), and skipped unreadable result lines. Each run has a directory of its own, a non-zero status or a timeout marks it partial, the engines' level words are ranked and an unknown level is kept and counted, unreadable lines are counted and kept whole, the result is streamed and sorted with a bounded-memory merge, and the ruleset is recorded by digest.
- **`vss_stores`** printed "No shadow-copy stores were observed" after a failed or unrecognised `vshadowinfo`. It judges the exit status and the claimed against the readable store count, keeps the whole stderr, says "no stores" only when `vshadowinfo` exited 0 and reported zero, and gives the mount command as a quoted argv.
- **`indx_carve`** emitted every entry carved from a block whose update-sequence check failed as if sound, and said slack times are the set a timestomper does not reach. Every entry carries `block_offset`, `fixup_ok`, `node_ok` and `salvaged`; entries from a salvaged block are left out and counted unless `include_unreliable`; the note calls slack stale index material.
- **`prefetch_mam` and `mam_scan`** inflated a MAM payload with a decoder that has no output bound, read the last-run times and run count at fixed offsets for every version, found strings by a pattern that only sees ASCII-range UTF-16, rounded the last-run fraction, and lost a candidate that failed to decompress as soon as a name filter was set. The decoder runs behind an output cap, MAM framing is checked first, fields are read by the layout of the version (another version is unsupported, with no version-dependent field), filename strings come from the section the header locates, and `mam_scan` accounts for every candidate. The two tools carry the same reader, held identical by a test.
- **`recyclebin_i`** returned an empty or short path for a truncated record without an error and read a fixed 4096 bytes; **`utf16_urls`** read the whole file, cut every ASCII URL at 300 characters and dropped repeated occurrences with their offsets. They report truncation and keep every occurrence whole, as a streaming string-candidate scanner.
- **`regkv`, `amcache_apps` and `shellbags`** read values through regipy's default, which cuts a binary value to 128 bytes and a string to 256 characters; they read them whole. `regkv` also keeps each value's type and length, names every unreadable key and every branch it did not enter, bounds a recursive walk and keeps the whole listing in a file, and reports a dirty hive.
- **`evtx_query`** counted broken records as matches, gave good rows no locator and had no time filter. **`evtx_carve`** overwrote a repeated EventData name, listed every problem inline, and counted built chunks rather than signatures against its budget. **`usn_journal`** dropped the parent sequence, source info, security id and raw attributes, and a name filter silently left out V4 records. **`shellbags`** used one long-name offset for every extension version from 7 and stopped at the first root. **`mft_records`** checked nested ranges against the whole record, left a record whose update sequence check failed as a flag on that record alone, and skipped a slot with no signature without a count (both are counted now, in `records_fixup_failed` and `slots_without_signature`). **`extract_stream`** printed the stream as base64; it writes a named file with its size and sha256. Each fix has a regression test, listed in the pull request.

### Changed: the Windows pack's manifests and requirements say what is and is not measured

Every manifest now declares `requires` (the programs it runs; `sigma_hunt` needs one of two engines and says so) and `use` where its input has a signature, describes `limit` as an inline page size, and states what its tool does not do. `requires/python.txt` pins the four libraries the tools import to the releases they were tested against (python-evtx 0.8.1, regipy 6.3.0, dissect.util 3.24, olefile 0.46) with licence labels read from the installed packages' metadata where they were installed, and separates the three capability-only entries (`libfwsi-python`, `impacket`, `dpapick3`) from what a tool imports; the last two are untouched, pending a decision. `requires/host.json` drops the eight macOS routes that installed a Python binding in place of the command-line tool (`fsntfsinfo`, `sccainfo`, `olecfexport`, `lnkinfo`, `regfexport`, `evtxexport`, `msiecfexport`, `pffexport`) and says "no macOS install route is declared", and drops an unsupported comparison from Zircolite's reason. Timestamps from the changed tools are ISO 8601 UTC with seven fractional digits by integer arithmetic, with the raw FILETIME beside them. The library's `usn_journal`, which a test holds byte-identical to the pack's, is updated with it. A new suite, `tests/pack-windows-forensics.test.ts`, builds its fixtures from the formats' layouts (a regf writer, MS-SHLLINK, DestList, INDX, $MFT, USN, Prefetch and Xpress Huffman writers) and runs against the tools as they were before the fixes when `WINDOWS_PACK_TOOLS` points at a copy of them.

### Fixed: the Windows pack's tools survive hostile input, keep every secret out of their answers, and read real files

A review of the first version of this change ran the tools against real files and hostile inputs and found what the fixtures could not. Prefetch: the run count was read at 0xD0 for every version 30 file, and 8 of 302 real files keep it at 0xC8 (the file information is 216 bytes there, 224 elsewhere): both tools now derive the size from the file-metrics offset (`file_information_size`) and say `run_count` null with a problem for any other, and a stream whose last symbols sit in the decoder's lookahead is no longer refused as short. Registry: `regkv` judged a value by its type before its name and place, so an odd type under a secret's name printed whole, listed 2,000 of 2,500 subkeys as complete, and failed with a traceback without regipy; `shellbags` read a long name at offsets that 15 of 19 real Windows 10 items do not have (the layout has a 2-byte size before the name: 0x14, 0x26, 0x2A, 0x2E for versions 3, 7, 8, 9). `browser_history` failed every query on a read-only evidence file, let a trigger on a copy hand a password back, echoed 16 bytes of an unreadable file as hex, and called another database's log "0 frames"; it, `utf16_urls` and `esedb_query` printed URL tokens and user-info, and `esedb_query` printed the credential attributes of a directory database; `lnk_parse` printed a link's arguments (`--password ...`) and its string scan inline and read 32 MiB into 1.2 GiB. `evtx_carve` counted forged signatures as chunks, `evtx_query` called a truncated log complete and dropped records at a `Z` time bound, and `mft_records` read a file whose first record is not at offset 0 as zero records. Tools that open evidence paths hung on a FIFO or followed a link (`recyclebin_i`, `jumplist`, `amcache_apps`, `usn_journal`, `yara_scan`); several replaced what an earlier run had kept (`extract_stream`, `vss_stores`, `yara_scan`, `evtx_query`); many raised a traceback instead of a JSON error, and the shared paging block did so when the work directory was read-only. Each is fixed against the format or the library's contract and has a regression test that fails on the earlier code.

The tool library carried the old, secret-printing copies of thirteen of these tools (`yara_scan` with the matched bytes in its answer, `extract_stream` as a base64 shell script, the registry and browser readers): they are replaced by the pack's tools, and a test holds each shared tool, manifest included, byte-identical to its library copy. The cases that need a real `regipy` or `dissect.util` now also run against stand-ins that follow what the tools call, so CI exercises the secret assertions and the decompression bounds without the libraries.

The five tools that run a program (`esedb_query`, `extract_stream`, `sigma_hunt`, `vss_stores`, `yara_scan`) started it in a session of its own, so the harness ending a tool by killing its process group did not reach the program, which went on writing after the tool was gone. The program now stays in the tool's group, the kernel is asked to kill it with the tool (Linux), the tool's own deadline kills it and what it started by walking the process tree, and SIGTERM, SIGINT and SIGHUP do the same and leave a last word (`status: interrupted`); one process block, held equal in the five tools by a test, and the tools' own timeouts are capped below their manifests' (`export_timeout_seconds` and `timeout_seconds` at most 270, 270, 1,000 and 110 against 300, 300, 1,200 and 120). `esedb_query` also makes again an export a signal stopped, instead of handing `esedbexport` a directory that exists. The tests start each tool the way the harness does and kill its group, and assert that the program and its child are gone.
