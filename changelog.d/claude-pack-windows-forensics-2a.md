### Added: the Windows pack replays a hive's transaction logs on a copy, reads shell links and Jump Lists as rows with their offsets, and reads an extracted collection family by family

`registry_recover` takes a registry hive and the `.LOG1` and `.LOG2` that were copied with it (named by the caller: nothing is looked for beside the hive) and replays them onto a copy under its own output directory, never on the original. The replay follows the two log layouts and does not use regipy's `apply_transaction_logs`, which writes every entry whatever its sequence number: a new-format entry is applied only when its signature and both Marvin32 hashes hold and its sequence number is the one the hive needs next, and an older entry, an entry that does not follow, the rest of a log after a bad hash and an old-format log whose own numbers disagree are each named under `unrecovered` with the hive ranges they would have written. A clean hive is not replayed. The receipt gives the sequence numbers before and after, the log entries applied in order, the three base-block fields that differ from the original and the digests of the original and of the copy. The key and value records of the resulting state are read with regipy (`keys.jsonl`, and `changes.jsonl` against the original) and counted again by `regfexport` as an independent reader; a disagreement of the counts makes the status partial. The values of a SAM user's `V` and `SupplementalCredentials`, of the LSA secrets and cached-logon keys and of any value named for a password, secret or token (a DWORD or QWORD excepted) are written as a record with their place, name, type and length; `write_values` writes them to a 0600 file and is refused anywhere but a job run with `secret_output: true`. Withholding is by place and name: a secret inside a value that does not look like one (a command line with a password in it) is printed with the rest.

`lnk_jumplist` reads a shell link, an `automaticDestinations-ms`, a `customDestinations-ms` or a directory of them as JSON Lines rows: the file, the compound-file container (header, FAT, directory, mini stream, chains that loop or leave the file, a stream shared by two chains), every stream with its extents in the file, every DestList entry with the stream it names, and every link with its extents, its FILETIMEs raw and in UTC, its VolumeID or network target and an `integrity` that compares lnk_parse's reading with `lnkinfo` field by field. It decodes nothing itself: links are decoded by `lnk_parse` and DestLists by `jumplist`'s layouts. A link's arguments and string scan are withheld as `lnk_parse` withholds them, and `write_strings` is refused outside a job run with `secret_output: true`. A customDestinations-ms is carved at the 20-byte header, each link marked carved; its categories, pins and tasks are not parsed. A file named like a link that was not opened (a pipe, a symbolic link) or whose first bytes are none of the three kinds makes the status partial.

The recipe `windows-artefacts` is run on request over an extracted collection or files named one by one. It classifies files by name and then first bytes (a pipe is never read, a link is not followed), reads each family with the tool of the pack that reads it, keeps the whole answer of every call, and writes `coverage.json` and `index.tsv` with `parsed`, `partial`, `empty`, `unsupported`, `failed` or `not_attempted` for each family, written before the first tool runs, after every family and again if the recipe is terminated. A hive whose logs were replayed is read by `shellbags` and `amcache_apps` from the recovered copy, and the row says so. When the target is one directory and `target-query` is installed, a fixed list of its functions that no tool of the pack covers (`userassist`, `bam`, `shimcache`, `srum`, `services`, `runkeys`, `tasks`) is run, one call each, with the whole stdout and stderr kept; a function the installed version lacks is `unsupported`. `complete` for the run means every family that had an input ended parsed or empty; it is not coverage of the host. Plaso is not run.

Not done here: JLECmd is not used as a backend of `lnk_jumplist` (no pin of it is declared), Dissect's functions were run only against a stand-in for `target-query` (it is not installed where this was built), and the registry tests that read records need regipy and are skipped, with the reason, where it is not installed; the replay itself needs only the standard library and is tested everywhere. The skills `registry/overview`, `artifacts/links` and `artifacts/jumplists` name the new tools; the rest of the pack's skills are unchanged.
