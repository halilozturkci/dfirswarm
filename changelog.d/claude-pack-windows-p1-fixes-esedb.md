### Fixed: esedb_query reads the exporter's table as text, bounds what it prints inline, and never replaces a result (windows-forensics)

`esedb_query` (and its tool-library twin) read the table `esedbexport` writes with a CSV reader and printed every cell of every row inline. A table file whose cell began with a quote lost its quotes, and an unbalanced quote swallowed the tabs and lines after it (five exported rows came back as two, with `status: complete`); a carriage return in a cell ended a row. A table of 200 rows of 1 MiB cells (a 200 MB file) came back as 210 MB on stdout at 850 MB of memory.

- **The table is read as the exporter wrote it:** tab-separated text, a row to a line, no quoting rule (a quote and a carriage return are characters of their cell). A file whose lines end with CR LF is read as that and says so (`export_file_line_ending`). `_row` is the 1-based line of the row after the header. A column named like a key the answer adds (`_row`) is numbered (`_row_2`) instead of replacing the ordinal.
- **What an answer prints inline is bounded:** the rows that fit `limit` and 256 KiB, a cell over 4,096 characters shown cut with `_cells_shortened` naming its length. The file `all_results` names holds every row with every cell whole, is written whenever the inline rows are not the whole of the table (more rows than fit, or a cell cut), and is never replaced: the same result is named again, any other takes the next free `-n` name. The same holds for the file of URL-secret locators. A row over 8 MiB is read that far and said to be cut (`rows_read_cut`); the export keeps it whole. The columns shown inline are at most 1,000 (`column_count`).
- **Its own time limit (285 seconds, under the manifest's 300):** the rows read so far, `status: partial`, `rows_complete: false` and the line the reading stopped at. SIGTERM, SIGINT and SIGHUP while a table is read answer JSON (`status: interrupted`) and leave no temporary file. Every answer, refusals included, carries `status` and `status_basis`.
- The manifest and the `execution/esedb` skill no longer say that the secrets of every URL are withheld: they are withheld by parameter name and user-info shape, and a secret in a URL path, a title or free text is printed (the masking block itself is unchanged here).
- Not changed here: the cell-withholding of identifier slots (table and column names), which belongs to the shared withholding work, and `write_url_secrets` as a declared secret-output argument, which waits for the harness change that adds the declaration.

windows-forensics is re-sealed and raised by a patch version; the other two pull requests of this review (registry and event-log readers) also raise it, so the second to merge needs the merge-prep step.
