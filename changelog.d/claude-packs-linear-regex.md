### Fixed: five more expressions and loops that cost the square (or the cube) of a text a file chose are read in linear time: lnk_parse, vss_stores, auth_log, the triage tools and plist_read

The expressions of the windows, macos, mobile, triage, cloud, linux and virtualization packs that are applied to text from evidence were timed against 80 repeated units (`eyJ`, `AKIA`, `ghp_`, `Bearer `, `a.`, `=`, `\`, `%41`, spaces, line breaks and so on) at 64 KiB and 2 MiB, at one CPU, and the tools themselves against files of such text. Five places took longer than a second, and one of them past its manifest's timeout.

- **windows-forensics, `lnk_parse`.** The expression that decides whether a string of a link has the shape of a secret read a URL with a password as `[a-z][a-z0-9+.-]*://user:password@`, tried at every letter of a run and run to the end of the run each time, and a web token the same way. A link's name is up to 65,535 characters: one such string took 36 s (the manifest allows 30) and the five strings a link can hold took 165 to 185 s. The scheme and the web token are now read once per run of characters, in a function (`secret_shaped`) that answers what the expression answered on 100,000 generated texts, and a string over 262,144 characters (a LinkInfo path can be longer than a string of the string data) is not read at all: it is withheld whole by its length, and its row in `sensitive_fields_withheld` says `not_scanned`. A link of five 65,535-character strings is answered in 0.08 s. The tool-library copy follows.
- **windows-forensics, `vss_stores`.** The expression that reads a `key : value` line of vshadowinfo's output backtracks over the leading whitespace and the key together: a line of 1,024 spaces took 0.3 s, 2,048 took 2.3 s and 4,096 took 19 to 37 s, the cube of the length. `parse_field` finds the same key and value (every line of up to eight characters drawn from five was compared with the expression) in one pass: 65,536 spaces take 0.01 s.
- **linux-forensics, `auth_log`.** The expression that takes the `rhost=` that ends a PAM failure's text was tried at every offset of the text after `ruser=` and ran to the end of a run of spaces each time: a line of 65,000 bytes (the longest the tool parses) took 40 s, one of 16,000 bytes took 2.5 s. `pam_rhost_last` reads the last word from the end and gives the same position and value on 200,000 generated texts: the line takes 0.03 s.
- **triage-collection, the six tools that carry the shared withholding block.** The expression for a web token (`eyJ`, 8 name characters, two to four dot-joined parts) was tried at every `eyJ` of a run and ran to the end of the run: a text of repeated `eyJ` took 0.3 s in each 8,192-character window the block judges and 1.9 s at 64 KiB, so a megabyte of it took 49 s and two megabytes 119 s, until the run's clock ended it. `_web_token_spans` takes the first `eyJ` of a run that has 8 characters after it, reads up to four parts, and goes on from the end of the run; it finds the spans the expression found on 200,000 generated texts. A megabyte of `eyJ` is judged in 0.5 s. What the block withholds is the same.
- **macos-forensics, `plist_read`.** The pattern that decides whether a key's name names a secret costs 0.4 microseconds a character, so a key name of 24 MiB (a property list may be 32 MiB) held the tool for 4.3 s. A key name over 65,536 characters is not read for a secret's name any more: its value is withheld, with the reason in the answer and in the values file (`key name over 65536 characters: not read for a secret's name, so withheld`). A name of exactly 65,536 characters is read as before.

The other expressions of these packs were found linear in the text they are applied to, or bounded by a gate that holds them under a second: the windows and macos withholding blocks (0.25 s for the 256 KiB they read of a string), the mobile tools' scrubs (0.3 s at 2 MiB), the cloud tools' scan (0.95 s for the 1 MiB it reads of a string, and it stops at its own deadline) and the virtualization tools (0.3 s on a 2 MiB file, with the shared withholding block's linear JWT match). The triage block's judgement of random-looking text costs up to 1 s per 64 KiB of a text of short pieces joined by `-`; it is linear, is read in windows and ends at the run's clock, and is left as it is.
