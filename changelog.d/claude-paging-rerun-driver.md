### Added: one driver reruns the paging tools in one job-shaped $OUT

`tests/tool-paging-rerun.test.ts` runs a paging tool twice with `JOB_ID` and `OUT` set, the first time with a page smaller than the result (so the whole result is written to `$OUT`) and the second time with a smaller page, and asserts that every file the first run left is still there with the same bytes and that the second answer names a paging file that exists. It covers ten tools today (lnk_parse, auth_log, shell_history, cron_dump, ransom_note_scan, encrypted_survey, recovery_key_scan, cloudtrail_parse, utf16_urls, recyclebin_i) and takes about two seconds; none fails at this head. The other 45 tools that write or name a paging file have no input builder yet: `tests/tool-paging-rerun-allowed.json` lists each under `uncovered` with the package that is to add its builder, and the test fails on a paging tool that is neither covered nor listed, so a new paging tool must get a builder or an entry. Both lists may only shrink. A case inside the test runs the driver against a stub that replaces its larger file with a smaller one and against one that keeps it, so the driver is shown to fail. The per-pack rerun tests stay.
