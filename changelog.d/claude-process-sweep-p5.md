### Fixed: the encrypted-containers tools that run a program no longer answer complete over a file it wrote when it left a process behind, and a 7z that leaves a writer on the pipe no longer holds the archive tools to their deadline

The shared PROCESS block already ends what a program leaves behind (`settle()`) before a tool reads, counts or hashes what the program wrote; the tools of this pack now say so in the answer. Every answer of `password_recover`, `crypto_metadata`, `crypto_selftest`, `materialise_decrypted`, `tcrypt_header`, `archive_metadata` and `archive_probe` that is not a refusal or an error carries `program_group` (`subreaper`, `left_behind`, `unproven`, `notes`); a refusal, an error, `unsupported` and `unavailable` carry none. `crypto_id` and `recovery_key_scan` start no program and are unchanged.

- **Tools that report a file a program wrote answer `partial`** when `settle()` ended a leftover (the file is stable, but it may be short or changed by the leftover) and, on a host that is not Linux or where the kernel refuses `PR_SET_CHILD_SUBREAPER`, when the absence of a leftover cannot be proven. `password_recover` (the helper's hash file, john's pot, log and show output; the pot stays sealed and the recovered value is withheld as before), `crypto_metadata` (the reader's output file), `crypto_selftest` (each reader's output file and the version probes) and `materialise_decrypted` (the decrypted image) answer so. `materialise_decrypted` keeps the image as an unverified `.partial` file in both cases and, after a process was ended, takes its size from the file and claims no digest of it (the reader's own digest may not be the file's; the provenance file says so); a clean run on Linux is unchanged and complete.
- **Tools that report only what a program printed on a pipe are not held to the non-Linux rule.** `tcrypt_header` (cryptsetup's header fields), `archive_metadata` and `archive_probe` (7z's listing) keep their status on a host that cannot adopt orphans (`program_group` says so). A process `settle()` ended makes them `partial`: it may have held the pipe, and a line it wrote cannot be told from the program's.
- **A process that holds 7z's pipe no longer holds the archive tools to their deadline.** The pipe reader of `archive_metadata` and `archive_probe` gave a program that had ended one second to reach end of file, but a holder that kept writing (a byte every 20 ms) restarted that second for ever, so the tool answered only when 7z's own clock ended the read (60 s, or `max_seconds` when that is less, against the manifest's 120). The second now runs from the moment 7z is seen to have ended and no byte restarts it; a holder is ended, the lister is `listed_with_warnings` with `pipe_held`, and the answer is `partial`, about one second after 7z ended. A silent holder was already let go after one second; what changes for it is the status (it was `complete`).
- **Probed, unchanged.** The readers that wait for a pipe through `communicate_bounded` (`tcrypt_header`'s cryptsetup, `crypto_selftest`'s version probe, `materialise_decrypted`'s reader child) were run with a stand-in that exits leaving a sleeper on the pipe, a writer that never stops, a holder of standard input and a holder of every descriptor: each answered within seconds with the leftover ended. The tools that read the program's output from a file (`password_recover`, `crypto_metadata`, `crypto_selftest`'s readers) have no pipe to wait for.
- **Not changed, stated.** A writer that is no descendant of the program (one started through a service manager) is found by none of this. A leftover of a version probe (`--version`, `-V`) counts in `program_group.left_behind` and makes the answer `partial` although no file of the run is affected. The reader child of `materialise_decrypted` is this repository's own Python; a process it started through a native module is treated like any other leftover.
- Packs raised: `encrypted-containers` 1.14.4 over the batch (password_recover 9, crypto_metadata 4, crypto_selftest 4, materialise_decrypted 4, tcrypt_header 8, archive_metadata 4, archive_probe 16).
