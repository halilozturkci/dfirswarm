### Added: pack tools and recipes declare the programs they run, and a test holds it

`tests/pack-program-declarations.test.ts` takes the program names from every pack's `requires/host.json` (99 names) and reads the source of every tool and recipe (100 or more): a program named as a call (a quoted argv item or `which()` argument in Python, a command at the start of a line or after a pipe in a shell script) must be in the tool's `manifest.json` `requires`, or in the recipe's `recipe.json` `requires` (it cannot run without it) or `requires_optional` (it uses it when it is there). A name that is only a word in the source (a file type, a dictionary key, a collector's name) is allow-listed in the test with its reason, and an entry that no longer matches fails. Before this, only the tool library was checked, against a fixed list of ten programs.

`recipe.json` gains the two keys, validated by the seal (a list of program names, none in both). The audit found 18 real undeclared calls (programs, counted by tool and recipe); 14 are declared: tools password_recover (john) and vss_stores (vshadowmount); recipes disk-timeline (requires log2timeline, psort; optional pinfo), android-aleapp (aleapp), ios-ileapp (ileapp), network-capture (tshark, capinfos), and, because they run without it when it is missing, archive-members (optional 7z), capa-floss (optional capa, floss), linux-target and windows-artefacts (optional target-query). A tool manifest's `requires` cannot say optional (the key names the programs a tool calls, and picks a smaller image only for the tool library), so the tools' entries are calls, not promises that the tool cannot run without them; the descriptions of what each does without the program are unchanged. The words (`strings`, `log`, `7z`, `pwsh` and three collector names, , the macOS system `log` command that unified_log looks for only on macOS, qemu-img in snapshot_chain_check and the two engines of sigma_hunt: three tests pin that those tools declare none of them, so each is allow-listed with that reason) are listed in the test with the tools that carry them. `docs/packs.md` "Requires and images" states the rule. Tool and recipe versions, the packs' versions and the seals are raised and refreshed; no code of a tool changes.
