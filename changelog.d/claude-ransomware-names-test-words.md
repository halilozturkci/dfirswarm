### Fixed: the ransomware-response names test no longer fails once in about 400 runs

The test that draws random identifiers in every shape the name rule withholds drew 24 random mixed-case letters (and 22 base58 characters, which hold no digit in 2.5% of draws) and sometimes got a string that reads as several capitalised words (`QvxlcUfWpvapSivtbtthbsvs` is Qvxlc, Uf, Wpvap and Sivtbtthbsvs). The manifests already say that class is printed: one word, a capitalised word, several capitalised words and all capitals are not identifier-shaped, and 24 mixed-case letters read as capitalised words in about 0.5% of draws before the shared withholding rules and 0.07% after. So `encrypted_survey` printed it, as documented, and the test failed (about 0.24% of runs: three draws of each of the two shapes). The test now draws again when a letters-only draw is in that documented class; the rates test below it still holds the class's rate. Nothing in a tool, a manifest or a skill changes. A draw outside the class that is printed still fails the test: 1,200,000 such draws of the two shapes were all withheld.
