### Fixed: doc_probe reads a signature away from offset 0 as a note, and a read the clock stopped is not_attempted

A text file that mentioned `%PDF-` was read as a PDF (partial, "no %PDF- header line"), and one that mentioned `{\rtf` was read as an RTF and came back complete: the bytes alone, anywhere in the first 1,024, made a container. Away from offset 0 only the form of a real header is now a claim (`%PDF-` and a version such as `1.4`, `{\rtf` and a version digit); the same bytes without one, a ZIP local file header signature that is not at offset 0 (a JPEG or PNG that holds `PK\x03\x04` in its metadata), and ZIP end-record signatures in the last 64 KiB that form no directory inside the file are a note under `notes` with their offsets, and the file is `unsupported` as any file that is no container. A PDF with a few bytes in front of its header is read as a PDF, complete, with a note on the offset. A real structure there is still reported as before: a PDF header with a version inside an RTF, a PDF with a ZIP appended, and the polyglot problem and `also_read_as` that come with them; an archive behind a prefix is not read as a ZIP (the file does not begin as one) but is named in a note, with the offset of the end record that names a directory inside the file.

A relationship part the clock stopped was counted under `relationship_parts.failed`, which read as a part that could not be parsed, with `read: 0`; it is now counted under the new `relationship_parts.not_attempted`, and the relationships before the stop are still listed. The tool is version 5. Pack `reverse-engineering`.
