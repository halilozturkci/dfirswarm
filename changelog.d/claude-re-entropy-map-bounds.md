### Fixed: entropy_map never writes an unbounded profile, creates its files mode 0600, and looks at the clock inside a window

The profile file had no bound: a 64-byte window over a 1 GiB file would have written 16.7 million rows (and a 4 TiB image, billions). A window that would give a file more than 4,000,000 rows is now refused before anything is read, naming the cap and the smallest window that fits (`smallest_window_that_fits`, `rows_needed`, `max_profile_rows`), so the profile is never cut. The profile and the runs file were created mode 0644; they are now created exclusively with mode 0600. `max_windows`, the windows shown in the answer, was allowed up to 1,000,000; it is at most 10,000, and the rest of the profile is in the file as before.

The clock was looked at only between windows, so a 64 MiB window read and counted whole could run seconds past `max_seconds`. The window is now read a MiB at a time with the clock looked at between the pieces; a window the clock stops is not measured, the profile ends at the last whole window, and the problem names the offset and how far into the window the pass got. Every answer and every refusal now carries a one-sentence `status_basis` beside `status` (complete, partial or failed). The signal path comes with the stop-handler change of this pack. The tool is version 3. Pack `reverse-engineering`.
