### Fixed: reverse-engineering doc_probe, doc_structure and pe_directories declare secret_output for write_values and check SECRET_OUTPUT

The three tools write the values they withheld from an answer whole to a file under `$OUT` when `write_values` is set, but their manifests declared no `secret_output`, so a job that set the flag was not run as secret output, and the tool only checked that it was inside a job. Each manifest now declares `secret_output: { "when_args": ["write_values"] }` (the harness seals such a job's outputs as sensitive and sets `SECRET_OUTPUT=1`), each description says SENSITIVE and names the flag, and the tool refuses `write_values` as JSON, before it creates anything, in a job that is not run as secret output as well as outside a job.

`extract_to` is not named by the declaration: it is a path, not a boolean flag (`when_args` takes only boolean parameters), and it writes byte-for-byte parts of the document the examiner supplied into a directory the examiner names, mode 0600, created exclusively, not a value the tool found. The description says so. The three tools already answered `status` failed and a `status_basis` on `{}`, on a missing path and on a wrong type; a test now holds that. The RE entries of `tests/tool-contract-allowed.json` are removed.
