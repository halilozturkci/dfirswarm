### Fixed: a redacted package withholds the files a recipe marks secret_bearing

A recipe cannot declare `secret_output` (the seal refuses the key in `recipe.json`), so network-capture says which of its output files hold what the evidence holds by writing `secret_bearing: { "<file>": "<why>" }` in its coverage, and `package --redact` ignored it: a marked table such as `http.tsv` reached a redacted package whole. `scripts/package-tools.ts` now reads that mark by its shape, never by the name of a recipe or a tool (a JSON file with a `secret_bearing` object whose keys are plain relative paths beside it and whose values are strings), and withholds each file it names whole, the way it withholds a sensitive job's output: the placeholder names the mark and the reason, `REDACTIONS.json` keeps the file's sha256, and the private sidecar keeps the digest and path. A `secret_bearing` that is not a map of names to reasons marks nothing; plist_read's (counts of what it withheld) and doc_structure's `secret_bearing_attributes` are answer fields, and `docs/packs.md` section 8 now states the mark's contract and says so. A name that escapes the directory, an absolute one, a non-string reason, a file over 8 MiB and a list over 10,000 names are not read as marks. `tests/redaction.test.ts` plants a run whose recipe output marks `http.tsv`: the marked file and a file in a subdirectory are withheld, an unmarked sibling and a file the mark gives a number for are kept, and a count under the same key withholds nothing. The reader route was taken; no pack changes.
