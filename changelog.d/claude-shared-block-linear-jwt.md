### Fixed: a text of repeated `eyJ` no longer keeps the shared withholding block busy for minutes, in every tool that carries it

The expression that finds prefixed secrets in the shared withholding block tried its JWT alternative (`eyJ` + 8 name characters + `.` + 8 + `.` + the rest) at every `eyJ`, and at each one ran to the end of the run of name characters before failing, so a text made of `eyJ` cost the square of its length: 63,000 characters took 1.5 s, and a `.docx` of 2,324 bytes whose external target was 1.8 million characters of it kept doc_probe busy past the manifest's 120 s with no answer (an RTF object class of 300 KB took 37 s). The 2 MiB length gate did not bound it, and the comment that called the examination linear was wrong. The JWT is now read from the runs of name characters, cut once: the first `eyJ` of a run that has 8 or more characters after it decides, because every later `eyJ` of the run reads the same rest, and a run that holds no JWT is not read again for each `eyJ` in it. 1.8 million characters of `eyJ` take 0.2 s with the length gate lifted, and the spans are the same as the expression's on every generated text it was compared with (JWTs glued to other tokens, in the middle of a run, with `=` padding, non-ASCII text and line breaks).

The length gate is now 64 KiB (65,536 characters): a longer text is withheld whole, by its length (`<over-long text withheld N characters>`), and not examined, so that no call of `scrub` or `token_spans` runs for long on a text a file chose whatever its shape; every rule reads a text of that length in a small fraction of a second. A name, a path or a URL is not tens of thousands of characters, so the answers on real input are the same. The block is the same text in the network, computer-forensics-base, virtualization-backup-forensics, reverse-engineering, encrypted-containers, memory-forensics and ransomware-response packs and the tool library (24 tools).

Three places outside the block shared the expression's pattern and the same shape, and use the block's `_prefixed_spans` now: the reverse-engineering tools doc_structure and pe_directories and the capa-floss recipe (the prefixed secret with the rest of the run it ends inside), the memory tools mem_fs and mem_profile, and the three virtualization tools, whose private copy of the expression, with a lookbehind that made a JWT head start where a run starts, is gone: a JWT inside a run is now withheld there as it is everywhere else.
