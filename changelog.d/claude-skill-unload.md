### Added: a skill body a seat has finished with leaves its context when it hands off, and the compaction's summary is written from ids and sizes

Stacked on the skill-delivery change (index in the prompt, `skill_done`, the ledger). Over 67 recorded runs, 71 % of the 82 skill bodies seats fetched were never named or used again, and 114 of the 120 fetches a compaction followed were summarised away with none loaded again; Pi has no unload, and its compaction cut each tool result to 2,000 characters before writing the summary. What changed:

- **The unloader.** A body the seat marked done with `skill_done` is replaced in the seat's context by a one-line stub, `<id> released (N tokens). Re-load with skill('<id>').` It is a `context_edit` draft the swarm extension returns from Pi's `turn_end` (Pi 0.87.1 appends a boundary's drafts to the session before it builds the next request from the session's projection), so the next model call is sent the stub. The session keeps the raw tool result and the edit beside it as an append-only line: custody hashes what it always hashed, and the replay and cost readers read the same entries. `skill(id)` after a release delivers the body again and the `skill` row says `reload_after_release` (with the turn of the release, counted on the branch, also after a restart); `skill_done` on a released note says so. The `skill_unload` trace row carries the note, its sha256 and tokens, the tool call whose result was replaced, the reason (`done` or `compaction`), the turn, how many bodies left in the boundary, and `suffix_tokens` / `batch_suffix_tokens`, an estimate of what a provider's cache writes again (the batch's largest suffix: it writes once). A release Pi did not commit is found at the next boundary (or at the compaction), put back, said on the trace by an `ok:false` row that names the release it takes back, and not counted.
- **`--skill-release compaction|auto|off`** (`SWARM_SKILL_RELEASE` in the seats; recorded as `skill_release`; said at kickoff; refused if it is none of the three; an unknown value in a seat's environment runs as `compaction`). **`compaction` is the default:** a finished body leaves in the turn the seat's `self_compact` came back, just before the compaction rewrites the prefix anyway, on every model. A mid-run release does not pay back its cache write before a context is cut (break-even about 11.5 x S/N requests at a 0.1 cached-read price, 24 at 0.05, 49 at 0.025), so `auto`, which adds the next turn boundary, is the experiment arm until a run has measured what it buys in attention. `off` releases nothing and leaves the summary input as Pi serialises it. A `skill_release_policy` row says what a seat's policy came to, and again whenever its model or thinking level changes.
- **Which models `auto` may edit.** The class is read from Pi's catalogue entry for the seat's model (`api`, `reasoning`), not from its name or the thinking level, and boundary release is an allow-list: `openai-responses`, `openai-codex-responses`, `azure-openai-responses`, or an entry that is not `reasoning`. Every other reasoning model releases at a compaction only: Claude on `anthropic-messages` or Bedrock (Anthropic says a client-side edit of an earlier turn can invalidate the thinking blocks after it, and Pi tells its managed-effort models to drop a block whose prefix no longer matches), OpenRouter's and the radius gateway's Claude entries (which replay Anthropic's signatures through `openai-completions` and `pi-messages`), Gemini, a local reasoning model. A signed thinking block after the body keeps it whatever model or thinking level the seat has now, so switching the model with `/model` or turning thinking off and on does not leave a block behind an edit. Verified offline through Pi's real request builders (Anthropic with an API key and OAuth, Bedrock, OpenRouter, OpenAI Responses, Codex): an edit changes the edited result alone and every signature and reasoning item goes out unchanged. What the service does with it was not asked.
- **The rules.** Only a body the agent marked done is released; the notes it is working from are never touched, however many it holds. A body no assistant turn has read waits one boundary. All the finished bodies of a boundary go in one return. A body released once between two compactions is not released again at a turn boundary: no toggling. A hand-off that was refused or that failed and was given up is not a compaction: such a seat released bodies mid-run and toggled them before this was fixed.
- **An edit does not lock a seat.** After an edit Pi estimates the whole context at characters over four until the next reply; on 10,853 recorded replies that is up to 17 % above the provider's count (7 to 12 % at p95), enough to push a seat 10 % under its compact line over it, force a hand-off and refuse its tools. The levels and the lock now keep the last count the provider gave until the next reply. The `context` rows were never the estimate.
- **The compaction is told ids and sizes.** The summary call is given every skill body as one line naming the note and its size (a released one is already a stub) and a `<skills-read>` block: what was read, what the seat marked done (the ledger's marks count for a note read in the summarised part and marked done in the kept tail), what it did not (probably still needed). `prompts/compaction-summary.md` asks for those under Critical Context. The hand-off header names each note once, with its size and whether it is done, and lists the ones probably still needed (it replaces S1's separate sentence). The ledger rebuild at a compaction and at start knows a result that a `context_edit` replaced is not held.
- **Measured.** The context audit and the Packs tab count, per seat, the bodies released, the tokens that took out of the context, the share released at a compaction, the loads that came after a release (the wasted-release rate), and, from `skill_release_effect` rows, how many thinking blocks Anthropic said it dropped in the first reply after a release and after a compaction: one Claude run on `auto` answers the open question the Claude rule rests on. The worker prompt's Skills section says a released body is a one-line stub and `skill(id)` brings it back.

Not done here: releasing at Pi's own threshold or overflow compaction (no boundary comes before it), a staleness release of bodies the agent never marked done, a suffix-size guard on cache-priced providers, the `--skill-release` field in the console's kickoff form. Not verified: whether Anthropic accepts (or silently drops the thinking blocks after) a history in which one earlier tool result changed, and what the Codex OAuth endpoint does with a re-sent suffix.
