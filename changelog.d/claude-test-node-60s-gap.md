### Fixed: the node tests no longer wait a fixed minute after the last test

Every CI run of `npm test` showed a gap of exactly 60 seconds between the last test finishing and the summary line, on the fast runs and the slow ones alike. The cause was a pending timer in `tests/worker-fence.test.ts`: the case that checks the process making a worker is stopped bounded its wait with a `Promise.race` against a 60-second `setTimeout`, and never cleared that timer when the process exited first. The timer kept the file's node process alive for its full 60 seconds after the last test, and `node --test` held the summary back until that file's process ended. The timer is now cleared as soon as the race is decided; the bound itself is unchanged, so a maker that is not stopped still fails that case by name after 60 seconds. The file now takes about 12 seconds instead of about 73, and every node-tests job (the Linux job, both Node jobs, the macOS job) saves about a minute. No other test holds a timer open: the other long timers in `tests/` are all cleared when they are no longer needed. Nothing is masked by `--test-force-exit`, which is not used.
