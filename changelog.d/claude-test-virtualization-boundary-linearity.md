### Fixed: the linearity tests of the virtualization and windows boundary blocks no longer fail on a loaded runner

The test that every layer of the virtualization pack's boundary takes time proportional to the length of a string compared one measurement at 5 KB (about 0.01 s) with one at 100 KB and allowed it about 0.43 s; a loaded CI runner took 0.39 to 0.48 s for linear code and failed it on `main` and on many pull requests. It now measures CPU time at 6.25, 25 and 100 KB (each step four times the one before), takes the least of up to three rounds, and allows each step eight times the shorter time, which is never taken as less than 0.05 s, the rule the reverse-engineering pack's linearity tests already used (`tests/pack-re-timing.ts`, now with a ladder of sizes). A rule that is quadratic still fails, in seconds: the longer texts are not run once a step is not linear. The same rule holds the test of every identifier kind of that pack (2,048, 8,192 and 32,768 characters, each combination on its own instead of the worst of all), and the windows boundary block's test of hostile repeated shapes now measures CPU time and repeats a slow-looking case before it counts it.

The store-sweep tests read `ledger/ledger.md` right after the sweeps had finished; a render of the file that began before the sweep's line was written could end after the sweep's own and leave "store sweep pending" in it (seen once on a Linux runner). They now render the file from what is on disk before they read it. No tool or harness behaviour is changed.
