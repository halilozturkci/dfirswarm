### Added: the profile comparator's three definition corpora are pinned data in the images (`triage-collection`)

- `requires/host.json` declares UAC 3.4.0's release tarball, the Velociraptor v0.77.2 source archive (for `artifacts/definitions`) and the KapeFiles repository at one commit as `install.data`, each with its URL, sha256, size and the licence its own LICENSE file states (Apache-2.0, AGPL-3.0, MIT), `redistributable: false`, installed under `/opt/dfir/data/triage-definitions/<name>-<version>/`. A new `KAPE` entry (`not_in_image`, licence "declared, unverified") carries the KapeFiles data, and the eight leaves that name KAPE list it in `mentions:`. The programs stay `not_in_image`; no image is rebuilt here.
- `collection_profile_compare` carries the three archives' sha256 in its list (the Velociraptor and KapeFiles lists were empty) and, when `definitions` is not given, reads `/opt/dfir/data/triage-definitions` if it exists, one directory per corpus; a link is never entered. A GitHub archive of a tag or commit is generated on request, so if GitHub ever serves other bytes the image build stops at the sha256 check.
- Images: `install.data` accepts an absolute `into` under `/opt/dfir/data/` with no `package` (anywhere else is refused), and `recipe.py` installs the data of a `not_in_image` program. `tests/recipe.test.sh` and `tests/pack-triage-profile-compare.test.ts` each have a case that fails without the change.
