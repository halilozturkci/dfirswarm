### Fixed: triage-collection's six collection_* tools give their failure answers a status_basis

The shared block's failure function and its stop-signal answer printed `status: "failed"` and an `error` but no `status_basis`, so the six tools (collection_coverage, collection_id, collection_index, collection_manifest_parse, collection_manifest_verify, collection_path_map) answered the first refusal (`{}`, a root that is not there) without the second half of the pair. Both answers now carry a one-sentence `status_basis` ("the tool stopped with an error: ..." with the scrubbed message; "stopped by signal N before the answer was complete"), once in the block and copied byte for byte into the six tools. Their versions are raised and the manifests' `sha256` is current. The triage entries of `tests/tool-contract-allowed.json` are removed; `tests/pack-triage-refusals.test.ts` holds the refusals of all six, and the contract run test now also gives a missing path to the tools whose path parameter is called `root`.
