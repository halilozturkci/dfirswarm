### Fixed: virtualization-backup-forensics declares secret_output for write_text in the three manifests

`backup_audit_normalise`, `snapshot_chain_check` and `virtualization_inventory` refuse `write_text` unless they run with `SECRET_OUTPUT=1`, and their skills say to run them as jobs with `secret_output: true`, but no manifest declared it. Each manifest now carries `"secret_output": {"when_args": ["write_text"]}`, so the job service makes a job with `write_text` true secret output by itself (recorded as `secret_output_by: tool_manifest`), whether or not the agent set the flag; a job without `write_text` is an ordinary job. The `write_text` parameter's description says so. The tools' own code is unchanged; their manifest versions rise (backup_audit_normalise 3, snapshot_chain_check 5, virtualization_inventory 3). `tests/pack-virtualization-secret-output.test.ts` asks the job service, tool by tool, with synthetic inputs.

### Fixed: virtualization-backup-forensics tools answer a stop signal from the end of their opening block, not from the start of main()

`virtualization_inventory`, `backup_audit_normalise` and `snapshot_chain_check` installed their SIGTERM, SIGINT and SIGHUP handlers at the start of `main()`, after the whole module had run, so a signal in that gap ended the tool with no JSON (exit -15 or -1, or a `KeyboardInterrupt` traceback for SIGINT). Each now calls its installer at module level, right after the block that defines it (the shared COMMON block in the first two, the shared PROCESS block in `snapshot_chain_check`, which also ends the programs it runs first); `main()` no longer repeats the call. The blocks' text is unchanged. From there on a stop gives one JSON answer (status partial, `stopped_by_signal`) and exit 128 plus the signal number; in the first two tools a signal before the output block has loaded gets a shorter answer that says so. Each manifest states the window that remains: the start of the interpreter, the compiling of the file and the shared opening blocks. Measured, 120 SIGTERMs per tool at random moments after the start, on a busy host (load average about 18, where compiling the file alone took 0.2 to 0.3 s, so the window before the handlers is large): from 0 to 250 ms after the start nearly all signals land while the interpreter is still compiling, before and after alike (no JSON in 119, 115 and 120 of 120 before; 117, 119 and 120 after, for inventory, audit and chain); from 250 to 900 ms the signals that had no JSON fell from 27, 35 and 31 of 120 to 19, 1 and 0. `tests/pack-virtualization-startup-stop.test.ts` runs each tool's source up to the installer's call and signals there, and the whole tool while it waits for its arguments; the first part fails on the previous code.

### Changed: virtualization-backup-forensics `control-plane/chronology` no longer calls whoever acted an operator

The leaf's "does not show" clause read "Which operator acted". In this repository the operator is the authorised human who runs the case; on the management plane the word meant whoever stands behind an account, an administrator or an intruder. It now reads "Which person or account acted". The leaf stays within its budget. `tests/pack-virtualization-skills.test.ts` holds that no leaf of the pack uses "operator".
