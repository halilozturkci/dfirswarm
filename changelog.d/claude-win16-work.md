### Added: powershell_blocks reassembles PowerShell script block logging records (event 4104) into blocks

`powershell_blocks` in the windows-forensics pack takes an `.evtx` file (read with the chunk code `evtx_query` and `evtx_carve` carry) or a JSON Lines file of `evtx_query` rows, and groups the 4104 records of `Microsoft-Windows-PowerShell/Operational` and `PowerShellCore/Operational` (kept apart) by source, Computer and ScriptBlockId, in the order of MessageNumber. Per block it gives the expected against the observed fragments, the missing numbers as ranges, duplicates (and whether the copies match), MessageTotal values that disagree, numbers out of range, the Path and Level fields and the length of the text, and per fragment the EventRecordID and the record's byte offset in a file. The answer and its files carry metadata only: the text is never evaluated, decoded or shown, and no hash of a block is written. `write_text` writes the reassembled text to a 0600 file under `$OUT` and is accepted only in a `secret_output` job. What it keeps is bounded (200,000 fragments in 100,000 blocks, a JSON Lines row of 16 MiB, its own clock) and a bound that cut something makes the answer partial and names the number. Not verified here: a real PowerShell log; the reader is exercised on events built to the documented layout, and python-evtx is not installed where the tests run. The `logs/powershell` skill now names the tool where it said the pack had no assembler. The pack goes to a new patch version, the tool counts in the READMEs and the block census follow, and the shared blocks of the tool are copies of the ones `evtx_query` and `evtx_carve` carry.
