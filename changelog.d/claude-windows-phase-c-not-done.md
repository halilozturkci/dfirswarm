### Changed: the offline hive-secrets and DPAPI tools of windows-forensics are not in this batch; the owner has them written by another model

Two packages of the windows-forensics Phase C are not built in this repository and nothing about them was changed: the offline hive secrets tool (an `impacket secretsdump`-style reader of SAM, SECURITY and SYSTEM hives, with its credential-stores skill and pins) and the DPAPI tool (`dpapick3`: master keys, CREDHIST, Credential Manager, Vault and generic blobs, decrypted offline). The implementer assigned to them was stopped by the model's safety classifier before it wrote any code; the stop was not worked around and the scope was not narrowed. The owner decided to have both tools written by another model and to bring them in as their own change.

- **What stays undone here.** The two tools, their tests and fixtures, and the credential-stores leaf. `windows-forensics` therefore has no tool for either, and no skill names one.
- **What waits for them.** The windows router, index and skills reconciliation (eight new skills, the router limit of 500 tokens, the windows index allowed past 1,000 tokens) and the review loop of the windows Phase C tools come after the two tools and are not done either.
- **What the change that brings them in must keep.** The rules of `docs/packs.md` for a tool that starts a program (the shared process block, `process_apply`, an entry in `tests/process-sweep-coverage.json`) and the sensitive-output rules of the windows skills: a secret value is for the agent to use and is recorded, not printed where the manifest says it is withheld.
