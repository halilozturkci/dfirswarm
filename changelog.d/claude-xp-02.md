### Fixed: a FIFO, a link or a directory at the name a result is placed at no longer holds a tool, and the comparing of results has a clock

- **A FIFO at a result's own name no longer blocks the tool for ever.** `same_bytes` (called by `place_without_replacing` in the shared PLACE block of the windows lineage and the shared PAGE block of the memory lineage, and by the `publish` of the cloud, base and triage tools) compared sizes by path and then opened both files. A FIFO planted at the final name (`mkfifo work/s1/hits.jsonl`, then `mem_carve` on a clean image with `results_to` naming it) is 0 bytes, as is the empty temporary file of a run with no hit, so the size check passed and `open()` of the FIFO blocked until `SIGKILL` (it swallowed `SIGTERM`). Both files are now opened with `O_NONBLOCK|O_NOFOLLOW`, looked at with `fstat`, and read only when both are regular files of one size; a FIFO, a link, a device or a directory at a name is another result's, so the next name (`hits-2.jsonl`) is taken, and an identical rerun still gets its old name. A link at the final name is no longer followed by the comparison either (the base and cloud `publish` copies named the link as the result when it pointed at a file of the same bytes).
- **The comparing of one placing has a clock.** `place_without_replacing` compared every earlier list of the same size in turn (up to 999 names) with no clock. It now has `PLACE_COMPARE_SECONDS` (5 s) in all for one call; past it an earlier result that has not been compared is taken as different, and the result takes the next free name. Nothing is replaced; what stays open is that an identical rerun may then be named anew.
- Carriers: the PLACE block (33 carriers), the memory PAGE block (3), and the unmarked `same_bytes` and `_same_bytes` copies of the cloud, base and triage tools and their tool-library twins (20 more). `unified_log` keeps its own `same_bytes`: it compares members of one staged tree after every special file has been refused, and places no result.
- Packs raised: `windows-forensics`, `memory-forensics`, `encrypted-containers`, `ransomware-response`, `cloud-forensics`, `computer-forensics-base`, `triage-collection`; the tool-library twins and their README rows follow.
- Test: `tests/pack-shared-residuals.test.ts` runs the block's own text from a carrier of each lineage, the unmarked copies, and `mem_carve` end to end with a FIFO planted at its `results_to`; each fails on the code it replaced and passes on this change.
