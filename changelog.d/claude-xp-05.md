### Changed: the three virtualization tools carry the one BOUNDARY text, byte for byte

`backup_audit_normalise`, `snapshot_chain_check` and `virtualization_inventory` no longer carry their own 1,300-line block. They carry the text of the other 13 carriers, and `tests/pack-boundary-shared.test.ts` now declares one variant with 16 carriers (the census, `tests/shared-blocks.json`, says 16). Each tool keeps its table of field kinds outside the block and passes it in with `bind_fields`; a few lines of adapter after the block map the old call names (`seal_text`, `answer_text`, `row_text`, `Shower`) onto it. The common block, the files block and the process block are untouched, and the contracts the delta review checks are kept and still tested: `write_text` is refused without `SECRET_OUTPUT=1`, nothing is written outside `$OUT` or `work/<agent>/`, SIGTERM, SIGINT and SIGHUP give one JSON answer, `paging_files_left` names files whose rows all parse, the 400,000,000-character cap and the deadline stop with `partial` and `boundary.stopped_by`, and the 512 KiB inline cut keeps `status`. The two R2 repros (200,000 descriptors with `limit` 100000, and 2,000,000 JSON Lines records with `limit` 100000) pass. The tool manifests (versions 5, 7 and 5) and the pack (1.2.0) are resealed; the README, the manifests and ten skills say what the one text withholds, in its words.

What the tools print differently:

- A withheld text is `<withheld N characters: reason>` (and `<withheld N bytes: backstop: reason>` for the backstop), not `<withheld: N bytes, field F>`, `<token-shaped text withheld N characters>`, `<userinfo withheld N characters>` or `<withheld: an integer of N bits>`. An integer of 19 digits or more is withheld as a long number.
- The `boundary` object counts `strings_replaced_by_the_backstop` and lists `replaced_by_check` and `replaced_at` by the backstop's own check names. `stopped_by` and `strings_withheld_by_the_stop` are present when judging stopped and absent otherwise (they were `null` and `0`); the stop is named "the judging time" or "the cap of N characters judged in one run", not "max_seconds".
- A name that holds a lone surrogate (what a non-UTF-8 byte becomes) is withheld whole as invisible characters; it was shown with the bytes escaped. A version field takes an `=`. The part of a path before a withheld value stays readable (`...web01.qcow2?rootPassword=<withheld>`); the old block withheld the whole path.
- Withheld now that was shown: a machine name with several one-letter pieces (`ProxyK8sMgmtNode10`), a run of 40 characters of one letter in a name, and a Windows default name `WIN-xxxxxxxxxxx` with its part of a path in about one plant in eight (measured 11.8%; the limit was 1% before; DESKTOP- and LAPTOP- names stay under 1%).
- Shown now that was withheld: random letters of one case as the authority part of an `iqn.` name (`iqn.2004-12.<20 letters>.com:t1`) in up to 15.5% of plants (measured; limit 20%); two groups of six letters of one case after a secret's name in 6.3% (limit 8%); a padded base64 key with a `/` in a path leaves a head of 12 or more characters in at most 1% of plants (measured 0.2 to 0.7%), and shows a key whole in at most 0.5%. A short password used alone as a name, and a value of 6 characters or fewer after a secret's name, are still not recognised.
- The backstop alone (seal and layers removed on purpose) does not reach four shapes in the inventory's paging files: a value behind `key=`, `accessToken:`, `cipassword:` and an AWS secret with two slashes in a VM's own configuration (16 rows over 108 runs). Seal and backstop together find none of them; `tests/pack-virtualization-canary-lib.ts` names the four.

The one text gained what these suites asked of it, in all 16 carriers (the windows, macos and tool-library tools print the same differences where they carry these cases): the groups of a value written in parts are found whatever their case (`yIgK-paUn`, `KHIL-MS4S`), a short word next to a group is part of the value, and the end of a file name is not; a value in angle brackets after a secret's name (`password=<hJaXeuQz>`) is withheld, a placeholder word is not; the second check also names `psk`, `otp`, `bearer`, `authorization`, `ssh_key`, `connection_string`, `webhook_url`, `dsn`, a digit after a name (`password1=`), a camel-case flag with the value glued on (`--sshKeyb1185bce74632a`) and an `iqn.` authority of random letters, and only when a value built like a secret follows (a log line `authorization: failed` is left alone); a VMFS volume id (`95f26c46-d7e3b46c-b2e1-6fbd012c0188`) is a typed id for the second check; a window of a path (`/vmfs/volumes/ds1/`) is no residue of a key. The macos tools call the block's helper `_b_withheld`. The windows evtx test that needs a key only the backstop replaces now accepts any backstop label (the layers withhold more keys; 10 of 2,400 reach the backstop, as a named secret). The windows pack (1.7.19), the macos pack (1.5.15) and the four tool-library twins are resealed with their tool versions raised.

Canary bounds, re-measured on the new text (12-character windows of a planted secret, 54 shapes in every slot, in and out of a job, with a page of one row or two hundred): 0 leaks in `backup_audit_normalise` (2,592 runs), `snapshot_chain_check` (216 runs) and `virtualization_inventory` (216 runs), as on the old block. The backstop replaced a string in 44 of the audit tool's runs, 12 of the chain tool's and 68 of the inventory's, and every such answer is `partial` (the old block replaced none; the layers of the one text leave a piece of a secret between two cuts more often, and the backstop catches it). The backstop alone: 0 leaks in the audit tool (7,348 strings replaced, 7,186 before) and, in the chain tool and the inventory, 0 outside the 16 documented rows (8,937 replaced, 8,677 before).

Changed expectations of the suites (each marked `CHANGED` in its file): the marks and counters above (`audit`, `canary`, `chain`, `review2`, `harness`); the non-UTF-8 name (`audit`); the stop wording, a long name of words (161 characters shown, 301 withheld) and a version with `=` (`boundary`); the readable path before a withheld value (`boundary`); the rates above (`followups`, `followups-2`, `review4`, `review5`); the source check of the `t10.` pattern, which is now the one text's bounded class (`review5`); the placeholder `<secret withheld 15 characters>`, which the one text no longer writes and the tests now write as `<withheld 15 characters: secret value>` (`review4`, `review5`); the backstop-alone tolerance (`canary-lib`); the shared test, which no longer holds the BOUNDARY pair of the three tools (`shared`); `tests/pack-windows-forensics-boundary-evtx.test.ts` (any backstop label). New: three cases in `tests/pack-boundary-shared.test.ts` (the rules the virtualization suites asked of the text, no carrier defines a name the text defines, one variant of 16); the census case and the rules case fail on the code before this change.
