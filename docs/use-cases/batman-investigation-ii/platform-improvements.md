## Deney yorumu

- Başlangıç sınırları fail-closed çalıştı; aktif 10 VM'nin 19/19 harness ve ek 10/10 izolasyon probları geçti. Solution içerikleri operatör tarafından da okunmadı.
- Üç model de gerçek oturumlarda çalışıyor. Görevler ve önceki operatör girdileri farklı; çağrı/token/lead sayısından model başarı sıralaması çıkarılmıyor.
- Ajanlar kendileri rol değiştirdi, rapor yazarı/critic istedi, duplicate rotaları kapattı ve kanıt yetmediğinde iddialarını düzeltti. Bu davranışlar platformun gözlem kaydında korunuyor; yeni operatör yönlendirmesi yok.
- Mevcut job API üst stderr'i başarılı process için de gösteriyor. Eksik üyeleri fark etmemenin nedeni üst stderr görünürlüğünün kapalı olması değil; redirect edilen alt işlem sonuçlarının yapılandırılmamış olması.
- Typed job args için `{OUT}` zaten destekleniyor (`scripts/job-service.ts:1337`); agent-VM tool fallback'i kendi output path'lerini `ownPathsToOut` ile çeviriyor (`extensions/protocol-core.ts:7006`). j168, fallback değil doğrudan tool job çağrısında eski `work/...` mount path'i kullandığı için EROFS oldu; s07 bunu kendisi j170'te `$OUT` ile düzeltti. Eksik bir genel output substitution özelliği var diye raporlanmıyor.
- Git'teki `*.log` ignore kuralı ilk başarısız paket kaydından 35 dosyayı dışarıda bıraktı; `b8b3dbd` ile düzeltildi. Bu operasyon hatası platform/runtime analitik hatası diye sayılmıyor. Finalde gerçek dosya/Git manifest karşılaştırması gerekli.
- Tam kaynak/binary delil ve VM diskleri Git dışında, hashli envanterle kalacak. Tam trace, araç cevapları, job log/metadata ve Pi oturum metinleri kesilmeyecek.
